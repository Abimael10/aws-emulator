# iot: 4 net-new causes — constraint-violation messages drop the value for @pattern and add it for @range, SetDefaultPolicyVersion's not-found wording is emulator-authored, and DeleteThingGroup is still a 501 scaffold stub

> _Note: this issue was identified against the code base at commit `bdb39aafaf84b6475e0753269d38e8e33ea6d488`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
CreateThing

## Description
Four net-new root causes in service iot, all found by the behavioral suite under the `iot` service heading. Each cause below is independent and must be closed before submitting.

Cause 1 of 4: CreateThing's @pattern refusal message DROPS the rejected value AWS quotes.
AWS: Smithy CreateThing.thingName is @required, @length(1..128), @pattern ^[a-zA-Z0-9:_-]+$, and CreateThing models InvalidRequestException (httpError 400). Recorded behavior: a thingName containing an illegal character (e.g. a space) is refused 400 InvalidRequestException whose message is "1 validation error detected: Value '<thingName>' at 'thingName' failed to satisfy constraint: Member must satisfy regular expression pattern: [a-zA-Z0-9:_-]+". Fixed text: "1 validation error detected: Value '", "' at 'thingName' failed to satisfy constraint: Member must satisfy regular expression pattern: [a-zA-Z0-9:_-]+"; the ONLY variable part is the rejected thingName copied from the request. The same message is served for a subsequent DescribeThing addressed with that same illegal name.
Emulator: right status and right error code, but the message is "1 validation error detected: Value at 'thingName' failed to satisfy constraint: Member must satisfy regular expression pattern: [a-zA-Z0-9:_-]+" — the "'<value>' " segment is missing entirely, so the sentence reads "Value at 'thingName'".
Why: a client (or test, or log scraper) that matches AWS's refusal text never matches, and the operator loses the single piece of information the message exists to carry — WHICH value was rejected. Request-echo of the offending value is part of AWS's message contract for @pattern violations.
Fix: the shared constraint-violation message builder for this service (the formatter that renders @pattern violations) and CreateThing's input validation path that feeds it (services/service-com-amazonaws-iot-awsiotservice/src/ops/create_thing.rs plus the service's constraint-report serializer). Note the open issue 20261106T201842Z-iot-registry-plane-9-net-new-causes-creatething.md does NOT cover this: its Cause 2 was about the ERROR CLASS (ValidationException instead of InvalidRequestException), which now answers correctly; the check fails one assertion later, on the message.
Traces: iot.op-create-thing-invalid-name-rejected.

Cause 2 of 4: CreateRoleAlias's @range refusal message ADDS a quoted value AWS omits — the mirror image of Cause 1.
AWS: Smithy CreateRoleAlias.credentialDurationSeconds is an integer with @range(min 900, max 43200), and CreateRoleAlias models InvalidRequestException (httpError 400). Recorded behavior: a value above the maximum is refused 400 InvalidRequestException with the message "1 validation error detected: Value at 'credentialDurationSeconds' failed to satisfy constraint: Member must have value less than or equal to 43200", and a value below the minimum with "1 validation error detected: Value at 'credentialDurationSeconds' failed to satisfy constraint: Member must have value greater than or equal to 900". Both are entirely FIXED text — for this numeric member AWS does NOT interpolate the rejected number; the only values appearing in them are the modelled bounds 900/43200. In both cases the role alias is never created (DescribeRoleAlias then refuses ResourceNotFoundException "Role alias <roleAlias> not found").
Emulator: right status and error code, but the message inserts the request's value: "1 validation error detected: Value '<credentialDurationSeconds from the request>' at 'credentialDurationSeconds' failed to satisfy constraint: Member must have value less than or equal to 43200".
Why: the message differs from AWS's for every out-of-range request, so exact-match handling fails; together with Cause 1 the value-interpolation rule is applied exactly backwards (omitted where AWS quotes it, quoted where AWS omits it), which suggests one shared formatter deciding this per constraint kind.
Fix: the same constraint-violation message builder, in its @range branch, plus CreateRoleAlias's validation path (services/service-com-amazonaws-iot-awsiotservice/src/ops/create_role_alias.rs).
Traces: iot.role-alias-credential-duration-out-of-range-rejected.

Cause 3 of 4: SetDefaultPolicyVersion's unknown-version refusal uses emulator-authored wording.
AWS: Smithy SetDefaultPolicyVersion (PATCH /policies/{policyName}/version/{policyVersionId}) models ResourceNotFoundException (httpError 404); policyVersionId is @required with @pattern ^[0-9]+$. Recorded behavior: a policyVersionId that never existed for that policy is refused 404 ResourceNotFoundException whose message is "Policy version does not exist (name=<policyName>, versionId=<policyVersionId>)". Fixed text: "Policy version does not exist (name=", ", versionId=", ")"; the variable parts are the policyName and policyVersionId taken from the request URI labels. The refused call leaves the policy's defaultVersionId untouched.
Emulator: right status and error code, but the message is "Version <policyVersionId> of policy <policyName> does not exist" — different fixed text, different clause order, no parenthesised name=/versionId= form.
Why: AWS's message for this family is a keyed form clients parse (name=, versionId=); the emulator's prose is a sentence AWS never emits, so assertions and log-based tooling keyed to AWS's wording break.
Fix: SetDefaultPolicyVersion's version-lookup refusal wording (services/service-com-amazonaws-iot-awsiotservice/src/ops/set_default_policy_version.rs). The resolved issue 20261107T022027Z-iot-not-found-refusals-10-causes-emulator-authored.md reworked ten other IoT not-found sentences but names no policy-version cause.
Traces: iot.set-default-policy-version-invalid-fails.

Cause 4 of 4: DeleteThingGroup is an unimplemented scaffold stub, so thing groups cannot be deleted and the child-attachment guard is unobservable.
AWS: Smithy DeleteThingGroup is DELETE /thing-groups/{thingGroupName} returning 200 with an empty body, and models InvalidRequestException (400), VersionConflictException (409), ThrottlingException (400) and InternalFailureException (500). Recorded behavior: deleting a parent group that still has a live child group is refused 400 InvalidRequestException whose message is "Cannot delete thing group : <thingGroupName> when there are still child groups attached to it" — fixed text "Cannot delete thing group : " (note the space before the colon) and " when there are still child groups attached to it", with the parent group's name from the request as the only variable part — and the parent still exists afterwards (DescribeThingGroup returns it). Once the child is deleted, deleting the parent succeeds with 200 and DescribeThingGroup then refuses ResourceNotFoundException "ThingGroup <accountId>:<thingGroupName> not found."
Emulator: every DeleteThingGroup call answers HTTP 501 with error code `NotImplemented` — the handler is still the generated scaffold (services/service-com-amazonaws-iot-awsiotservice/src/ops/delete_thing_group.rs carries the "SCAFFOLDED, NOT IMPLEMENTED" marker and returns Scaffolded::not_implemented("DeleteThingGroup")).
Why: no thing group can ever be removed, so every group a client or a check creates leaks for the lifetime of the emulator, teardown of any group-based test is impossible, and the hierarchy rule AWS enforces on delete (parent with live children) can never be observed — a client relying on that refusal, or on a group actually disappearing, diverges completely.
Fix: implement DeleteThingGroup — delete the group from thing-group state, refuse InvalidRequestException with the message above when the group still has child groups, honour expectedVersion with VersionConflictException, and delete the SCAFFOLDED marker (delete_thing_group.rs plus thing-group state). The open issue 20261106T201842Z-iot-registry-plane-9-net-new-causes-creatething.md lists check iot.thing-group-hierarchy, but its replay key for that check is the ListThingGroups(parentGroup=…) 60 s timeout (its Cause 9); the check now gets past that read and fails later, at DeleteThingGroup, and no cause in that issue (or any other open issue) names DeleteThingGroup.
Traces: iot.thing-group-hierarchy.
