# dax: CreateCluster refuses every ClusterName longer than 20 characters, making the whole cluster control plane unreachable

> _Note: this issue was identified against the code base at commit `f40222b80bff0bb01bc5725930758a9790cd3d69`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
CreateCluster

## Description
One net-new behavioral root cause in the DAX control plane, grounded in the behavioral replay of this emulator. It blocks 12 of the 21 dax checks in simparity-behavioral-aws-v1.

Note on neighbouring issues: the open issue 20261029T193620Z-dax-createsubnetgroup-refuses-every-client-created-subnet-id.md lists dax.subnet-group-in-use-rejected, dax.delete-cluster-while-creating-rejected and dax.reboot-node-state-transition among its trace ids for a DIFFERENT cause (CreateSubnetGroup refusing client-created subnet ids). That cause no longer fires — CreateSubnetGroup now succeeds and the checks reach CreateCluster — and the replay report does not mark those three as owned, so they are grounded here. The resolved issue 20261029T172212Z-dax-create-path-refuses-valid-requests-and-raises.md touched this same code path but only to change PRECEDENCE (resolve ParameterGroupName before the ClusterName format rule); it never claimed the length rule itself was wrong, so this is not a reopen of it.

Cause 1 of 1: CreateCluster applies a hard 1..=20 character maximum to ClusterName and refuses any longer name with InvalidParameterValueException, where real DAX accepts it.
AWS: Smithy (services/service-com-amazonaws-dax-amazondaxv3/smithy-model/com-amazonaws-dax-amazondaxv3.json): CreateCluster input ClusterName targets `String` with NO @length constraint; the only length statement anywhere in the model is PROSE in the member's documentation ("A name must contain from 1 to 20 alphanumeric characters or hyphens. The first character must be a letter. A name cannot end with a hyphen or contain two consecutive hyphens."). Recorded behavior contradicts that prose: every cluster-creating check in this suite calls CreateCluster with a ClusterName of the form "sim2real-dax-cl-<12 hex>" / "sim2real-dax-race-<12 hex>" — 28 to 30 characters — and the recordings show AWS answering 200 with the Cluster (Status "creating", then converging to "available"), never a refusal. The modeled refusals the recordings do exercise on this operation are ClusterAlreadyExistsFault (400) for a duplicate name and ParameterGroupNotFoundFault for an unknown ParameterGroupName; no length refusal is recorded. Hypothesis: the documented 1-20 limit is stale doc text that the live DAX control plane does not enforce.
Emulator: answers HTTP 400 with error code InvalidParameterValueException and message "ClusterName must contain from 1 to 20 alphanumeric characters or hyphens". In that message the fixed text is "ClusterName must contain from 1 to " + the limit + " alphanumeric characters or hyphens" and the limit is the emulator's own constant, not a value from the request — no part of it is taken from the caller's input, so the client is never told which name or which length was at fault. Because every ClusterName the suite (and any client using a prefixed unique name) sends exceeds 20 characters, NO CreateCluster call ever succeeds.
Why: a client cannot create a DAX cluster with any name longer than 20 characters, so the entire cluster surface is unreachable: the create/available/delete lifecycle, UpdateCluster, IncreaseReplicationFactor/DecreaseReplicationFactor, RebootNode, TagResource/ListTags/UntagResource on a cluster ARN, the SubnetGroupInUseFault refusal, and the ClusterAlreadyExistsFault duplicate-name refusal. The refusal is also indistinguishable, by code or message, from a genuinely malformed name, and it points the client at its own valid input. Worse, it is the WRONG class of answer for the negative checks: a client probing for ClusterAlreadyExistsFault (dax.cluster-already-exists-rejected, dax.concurrent-create-cluster-same-name-single-winner) gets InvalidParameterValueException from every racer and sees zero winners instead of exactly one, i.e. a duplicate-create guard that can never be observed. Clients that retry InvalidParameterValueException as a transient IAM-role-propagation condition (the documented DAX behavior, and what several of these checks do) spin until their deadline, which is why 9 of the 12 failures surface as a timeout rather than an error.
Fix: CreateCluster's ClusterName validation — the `cluster_name_violation` check in the handler and the rule it calls in the service's state module (see Traces for the file/line citations). The max-length refusal must not reject a name the live service accepts; the recordings pin acceptance at least up to 30 characters, and the only name-shape refusals the recordings support are the character-set/first-character/hyphen rules. A duplicate name must still reach the ClusterAlreadyExistsFault branch, and the ParameterGroupName/SubnetGroupName resolution order established by the earlier fix must be preserved.
Traces: dax.concurrent-create-cluster-same-name-single-winner, dax.decrease-replication-factor-invalid-node-rejected and dax.untag-missing-tag-key-error surface the refusal directly; dax.cluster-already-exists-rejected, dax.cluster-create-available-delete-lifecycle, dax.delete-cluster-while-creating-rejected, dax.parameter-group-update-reflects-on-cluster, dax.reboot-node-state-transition, dax.replication-factor-scaling-round-trip, dax.subnet-group-in-use-rejected, dax.tag-resource-list-tags-round-trip and dax.update-cluster-description-transition exhaust their bounded retry-on-InvalidParameterValueException loop and time out. Code: services/service-com-amazonaws-dax-amazondaxv3/src/ops/create_cluster.rs lines 277-285 (the `cluster_name_violation` gate, applied before the duplicate-name and quota checks) and services/service-com-amazonaws-dax-amazondaxv3/src/state.rs lines 103-105 (`MAX_CLUSTER_NAME_LEN: usize = 20`) and 937-942 (`cluster_name_violation`, the empty-or-too-long branch that formats this message).
