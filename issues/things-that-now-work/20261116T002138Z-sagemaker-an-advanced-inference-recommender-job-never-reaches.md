# sagemaker: an Advanced Inference Recommender job never reaches COMPLETED and never carries an InferenceRecommendations entry, so GetScalingConfigurationRecommendation can never return a DynamicScalingConfiguration

> _Note: this issue was identified against the code base at commit `fdf278f439fa90531875ebdb8ce664f2d910d035`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
CreateInferenceRecommendationsJob

## Description
Cause 1 of 1: the emulator accepts CreateInferenceRecommendationsJob but never benchmarks anything, so DescribeInferenceRecommendationsJob never reports COMPLETED with recommendations and GetScalingConfigurationRecommendation has nothing to report on. Failing check: sagemaker.scaling-configuration-recommendation-for-existing-endpoint.

AWS: CreateInferenceRecommendationsJob with JobType='Advanced' (a custom load test, the only JobType that accepts InputConfig.ResourceLimit/TrafficPattern) returns 200 with JobArn while the job is queued, then the job actually runs the load test on its own ephemeral endpoint and settles in a terminal status. Smithy: DescribeInferenceRecommendationsJob output requires Status (RecommendationJobStatus, one of COMPLETED | DELETED | DELETING | FAILED | IN_PROGRESS | PENDING | STOPPED | STOPPING) and declares InferenceRecommendations (list, @length min 1 max 10) plus EndpointPerformances (@length 0..1); a job that completed its benchmark reports Status COMPLETED and at least one InferenceRecommendations entry, each carrying a RecommendationId. Smithy: GetScalingConfigurationRecommendation takes InferenceRecommendationsJobName (required) and exactly one of RecommendationId or EndpointName, and returns InferenceRecommendationsJobName, RecommendationId, Metric and DynamicScalingConfiguration (MinCapacity/MaxCapacity, 1 <= MinCapacity <= MaxCapacity); its only modelled error is ResourceNotFound (HTTP 400). In the recorded scenario the Advanced job is polled to COMPLETED, recommendations[0].RecommendationId is read off it, and GetScalingConfigurationRecommendation returns a non-empty DynamicScalingConfiguration for that id.

Emulator: no benchmark is ever run, and the handlers say so themselves. services/service-com-amazonaws-sagemaker-sagemaker/src/ops/create_inference_recommendations_job.rs stores the job with `recommendations: Vec::new()` and its header states 'No benchmark is RUN: ... the run ends in the modelled FAILED status with crate::state::NO_INFERENCE_BENCHMARK_REASON'. services/service-com-amazonaws-sagemaker-sagemaker/src/ops/describe_inference_recommendations_job.rs then always answers with `inference_recommendations: None, endpoint_performances: None`, materialising only the clock-owed move out of PENDING. Consequently (a) a polling client can never observe Status COMPLETED with a recommendation, and (b) services/service-com-amazonaws-sagemaker-sagemaker/src/ops/get_scaling_configuration_recommendation.rs, which resolves the id against `job.recommendations`, can only ever answer the modelled ResourceNotFound (HTTP 400, message: fixed text `Inference recommendations job ` + <the job name from the request> + ` has no recommendation for the requested endpoint or recommendation id.`) — a DynamicScalingConfiguration is unreachable for any job this emulator created. The replay surfaces this as 'Check timed out after 60.0s': the scenario never reaches its last call. Contributing to the timeout, the scenario's first SageMaker write is CreateModelPackage on an AWS Deep Learning Containers image `<dlc-registry-account>.dkr.ecr.<region>.amazonaws.com/huggingface-pytorch-inference:<tag>`, which this emulator refuses with HTTP 400 ValidationException 'Access denied for registry ID: <registry-id>, repository name: <repository>. Please check if your ECR image exists and has proper pull permissions for SageMaker.' (services/service-com-amazonaws-sagemaker-sagemaker/src/state/image_pull.rs); open issue 20261115T220927Z-sagemaker-createmodelpackage-refuses-an-aws-owned-built-in.md describes that refusal for the built-in/framework registries and does not carry this check's replay key, and because the check retries a ValidationException as IAM propagation (15 s per attempt, 6 attempts) that refusal alone exhausts the 60 s budget. Open issue 20261113T002132Z-sagemaker-3-net-new-causes-invokeendpoint-scores-a.md describes, as its Cause 3, the related per-transition settle-span cost for a DIFFERENT check (sagemaker.get-scaling-configuration-recommendation-references-endpoint) and likewise does not cover this one. Neither covers the defect named here: that an Inference Recommender job produces no recommendation at all.

Why: a client that uses Inference Recommender the way AWS documents it — register a package, start an Advanced load test, wait for COMPLETED, then ask GetScalingConfigurationRecommendation for the scaling configuration of one of the returned recommendation ids — can never get past the wait, and if it skips the wait it gets ResourceNotFound for every RecommendationId and EndpointName it could pass. Autoscaling-sizing code, and any test asserting 'the job completed and recommended something', is unrunnable against the emulator even though each individual call returns a plausible 200, so the failure looks like a hang rather than a missing feature.

Fix: the Inference Recommender slice of the sagemaker state (crate::state::InferenceRecommendationsJob and its settle_status, with crate::state::RECOMMENDATION_JOB_SETTLES_AFTER / NO_INFERENCE_BENCHMARK_REASON) must settle an accepted job into COMPLETED carrying at least one InferenceRecommendations entry derived from the request's EndpointConfigurations/SupportedInstanceTypes (each with a RecommendationId, EndpointConfiguration and metrics), so DescribeInferenceRecommendationsJob reports them and GetScalingConfigurationRecommendation (whose capacity computation already exists) resolves that id instead of refusing; the settle instant must also be reachable by a polling client inside one poll interval. The CreateModelPackage image-pull admission in front of it is the separately filed issue named above.

Traces: sagemaker.scaling-configuration-recommendation-for-existing-endpoint ('Check timed out after 60.0s').

## Evidence
Failing check: sagemaker.scaling-configuration-recommendation-for-existing-endpoint — verdict mismatch, detail: 'Error: Check timed out after 60.0s'.

Expected (AWS), as the check asserts: after CreateModelPackage(ModelPackageGroupName=<group>, ModelApprovalStatus='Approved', InferenceSpecification.Containers=[{Image: <AWS DLC huggingface-pytorch-inference image>}]) returns a ModelPackageArn, CreateInferenceRecommendationsJob(JobName=<job>, JobType='Advanced', InputConfig={ModelPackageVersionArn, ContainerConfig, EndpointConfigurations=[{InstanceType:'ml.m5.xlarge'}], TrafficPattern PHASES, ResourceLimit{MaxNumberOfTests:1,MaxParallelOfTests:1}, JobDurationInSeconds:1800}) is accepted, and DescribeInferenceRecommendationsJob(JobName=<job>) eventually reports Status == 'COMPLETED' with len(InferenceRecommendations) >= 1. GetScalingConfigurationRecommendation(InferenceRecommendationsJobName=<job>, RecommendationId=InferenceRecommendations[0].RecommendationId) then returns 200 echoing both identifiers with DynamicScalingConfiguration where MaxCapacity >= MinCapacity >= 1.

Actual (emulator): the check is cut off at the 60 s replay budget before GetScalingConfigurationRecommendation is ever called. The emulator's own handlers show the assertions could not have been met in any budget:
  - services/service-com-amazonaws-sagemaker-sagemaker/src/ops/create_inference_recommendations_job.rs lines 12-16 and 278-282: 'No benchmark is RUN ... the run ends in the modelled FAILED status with crate::state::NO_INFERENCE_BENCHMARK_REASON', and the job is stored with `recommendations: Vec::new()`.
  - services/service-com-amazonaws-sagemaker-sagemaker/src/ops/describe_inference_recommendations_job.rs lines 11-14 and 209-214: InferenceRecommendations and EndpointPerformances are hard-coded `None` on every describe.
  - services/service-com-amazonaws-sagemaker-sagemaker/src/ops/get_scaling_configuration_recommendation.rs lines 225-242: the lookup over `job.recommendations` is always empty, so the only possible answer is ResourceNotFound (HTTP 400) with message 'Inference recommendations job <job-name> has no recommendation for the requested endpoint or recommendation id.' — fixed text apart from the job name taken from the request.
  - the scenario's CreateModelPackage on the AWS DLC image is refused with HTTP 400 ValidationException 'Access denied for registry ID: <registry-id>, repository name: <repository>. Please check if your ECR image exists and has proper pull permissions for SageMaker.' (services/service-com-amazonaws-sagemaker-sagemaker/src/state/image_pull.rs, `unpullable_image`), and the check retries a ValidationException as IAM propagation (6 attempts, 15 s apart), which by itself consumes the whole 60 s budget — hence a timeout verdict rather than a recorded refusal.

## Steps to Reproduce
1. Create an S3 bucket whose name contains 'sagemaker' and an IAM role trusting sagemaker.amazonaws.com with AmazonSageMakerFullAccess; upload a .tar.gz sample payload (sample_payload.json) and note its s3:// URI.
2. CreateModelPackageGroup(ModelPackageGroupName=<group>).
3. CreateModelPackage(ModelPackageGroupName=<group>, ModelApprovalStatus='Approved', InferenceSpecification={Containers:[{Image:'<dlc-registry-account>.dkr.ecr.<region>.amazonaws.com/huggingface-pytorch-inference:<tag>', Environment:{HF_MODEL_ID, HF_TASK}}], SupportedContentTypes:['application/json'], SupportedResponseMIMETypes:['application/json'], SupportedRealtimeInferenceInstanceTypes:['ml.m5.xlarge']}). Observed: HTTP 400 ValidationException 'Access denied for registry ID: ..., repository name: ...' (that refusal is open issue 20261115T220927Z-sagemaker-createmodelpackage-refuses-an-aws-owned-built-in.md). To exercise the cause filed here, use any image the emulator admits (one in its own ECR registry in the request's Region) so the create returns a ModelPackageArn.
4. CreateInferenceRecommendationsJob(JobName=<job>, JobType='Advanced', RoleArn=<role>, InputConfig={ModelPackageVersionArn:<arn>, ContainerConfig{Domain,Task,Framework,NearestModelName,PayloadConfig{SamplePayloadUrl,SupportedContentTypes},SupportedInstanceTypes:['ml.m5.xlarge']}, EndpointConfigurations:[{InstanceType:'ml.m5.xlarge'}], TrafficPattern{TrafficType:'PHASES',Phases:[{InitialNumberOfUsers:1,SpawnRate:1,DurationInSeconds:120}]}, ResourceLimit{MaxNumberOfTests:1,MaxParallelOfTests:1}, JobDurationInSeconds:1800}, StoppingConditions={MaxInvocations:30, ModelLatencyThresholds:[{Percentile:'P99',ValueInMilliseconds:50000}]}) — returns 200 with JobArn.
5. Poll DescribeInferenceRecommendationsJob(JobName=<job>) until Status is terminal. Expected: COMPLETED with InferenceRecommendations of length >= 1. Observed: the job leaves PENDING into a terminal status with no InferenceRecommendations member at all (and no EndpointPerformances).
6. Call GetScalingConfigurationRecommendation(InferenceRecommendationsJobName=<job>, RecommendationId=<any id>), and again with EndpointName=<the benchmarked endpoint>. Expected: 200 echoing the identifiers with DynamicScalingConfiguration (MaxCapacity >= MinCapacity >= 1). Observed: HTTP 400 ResourceNotFound 'Inference recommendations job <job> has no recommendation for the requested endpoint or recommendation id.'
7. Replay: sagemaker.scaling-configuration-recommendation-for-existing-endpoint.
