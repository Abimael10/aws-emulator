# codedeploy: the Server-platform host-readiness gate still never completes for the fileExistsBehavior check — an SSM Run Command sent to the running managed node never returns the agent-status output, so CreateDeployment with fileExistsBehavior DISALLOW/OVERWRITE is never graded (1 cause)

## Operation

## Description
One net-new root cause in the codedeploy behavioral group: the failing check below carries a replay key no open issue holds.

Relation to what is already filed: open issue 20261114T164802Z-codedeploy-the-server-platform-ec2-agent-readiness-gate.md describes the same symptom family (a Run Command invocation on a Server-platform host never completing) and open issue 20261114T130417Z-codedeploy-the-server-platform-ec2-agent-surface-is.md covers an adjacent variant. Neither of them carries this check's replay key — the suite did not mark codedeploy.file-exists-behavior-disallow-blocks-foreign-file-and-overwrite-replaces-it as owned or already filed, so it is filed here so a fixer has a re-replayable key for the fileExistsBehavior path specifically (that path, and the three-revision manifest-adoption semantics it asserts, are exercised by no other check).

=== Cause 1 of 1: the SSM Run Command used to prove the CodeDeploy agent is active on a Server-platform host never yields a terminal invocation with stdout, so the readiness gate burns the whole run budget and the fileExistsBehavior semantics of CreateDeployment are never exercised ===
Failing check ids for this cause: codedeploy.file-exists-behavior-disallow-blocks-foreign-file-and-overwrite-replaces-it.

AWS: the check first proves the launched EC2 host is usable by running a shell command through Systems Manager Run Command — ssm:SendCommand(InstanceIds=[<id>], DocumentName='AWS-RunShellScript', Parameters={commands:['systemctl is-active codedeploy-agent']}) then ssm:GetCommandInvocation(CommandId, InstanceId). Smithy (ssm, com.amazonaws.ssm#CommandInvocationStatus) models the status enum as Pending|InProgress|Delayed|Success|Cancelled|TimedOut|Failed|Cancelling; on AWS a reachable managed node leaves the transient subset (Pending/InProgress/Delayed) within seconds and settles on Success with StandardOutputContent carrying the command's stdout ('active' for a running codedeploy-agent unit) and ResponseCode set. Only after that does the check call codedeploy:CreateDeployment. Smithy (codedeploy, com.amazonaws.codedeploy#CodeDeploy_20141006) models CreateDeployment.fileExistsBehavior as the FileExistsBehavior enum (DISALLOW|OVERWRITE|RETAIN) and declares InvalidFileExistsBehaviorException (HTTP 400) for a bad value; the documented behavior under test is that DISALLOW fails the Install lifecycle event when a path appearing for the first time in a revision's manifest already exists on the host (deploymentInfo.status 'Failed', errorInformation present, the foreign bytes left in place), that removing the file lets the same revision succeed, and that OVERWRITE replaces the bytes. deploymentInfo.status values come from DeploymentStatus (Created|Queued|InProgress|Baking|Succeeded|Failed|Stopped|Ready) and per-event status from LifecycleEventStatus (Pending|InProgress|Succeeded|Failed|Skipped|Unknown).
Emulator: the instance launches and reaches PingStatus 'Online' (phase one of the gate passes), SendCommand is accepted, but the invocation poll never produces StandardOutputContent equal to 'active' for 'systemctl is-active codedeploy-agent'. The helper loops until the run budget is exhausted and the check ends with 'TimeoutError: the CodeDeploy agent active on [<instance-id>]: the run budget ended first; not graded' raised from _wait_fleet_ready (the agent-active phase, which calls _invoke_command -> ssm:SendCommand + ssm:GetCommandInvocation). No codedeploy:CreateDeployment is issued, so no fileExistsBehavior outcome is produced at all. Hypothesis: the emulated Run Command execution plane records a sent invocation against a running instance but has no step that completes it, so the status never leaves the transient set and no stdout is ever attached.
Why: a client cannot use this emulator for any EC2/on-premises (computePlatform 'Server') CodeDeploy workflow that depends on what lands on the host. The fileExistsBehavior contract is invisible: a client cannot see a DISALLOW deployment fail on a conflicting path, cannot see the foreign bytes survive that failure, and cannot see OVERWRITE replace them. Worse, the blocking symptom is a status that never advances rather than a modeled error, so the client's own wait loops hang instead of failing fast.
Fix: two components, in order. First the SSM Run Command execution plane for an emulated managed node — the state behind SendCommand/GetCommandInvocation/ListCommandInvocations must advance an invocation sent to a running instance to a terminal CommandInvocationStatus and populate StandardOutputContent/StandardErrorContent/ResponseCode for AWS-RunShellScript. Then the CodeDeploy Server-platform deployment driver — the instance-target install path behind CreateDeployment that applies a revision's manifest to the host and enforces fileExistsBehavior, including the previous-successful-deployment manifest membership that decides whether an existing path is 'foreign'.
Traces: codedeploy.file-exists-behavior-disallow-blocks-foreign-file-and-overwrite-replaces-it — cut off in the host-readiness setup before any CreateDeployment.

## Evidence
Expected (AWS): ssm:SendCommand(DocumentName='AWS-RunShellScript', Parameters={commands:['systemctl is-active codedeploy-agent']}) on a host already reporting PingStatus 'Online', followed by ssm:GetCommandInvocation(CommandId, InstanceId), settles within seconds on a terminal CommandInvocationStatus ('Success' for a reachable node, otherwise 'Failed'/'TimedOut') with StandardOutputContent == 'active'. The check then runs three beats against codedeploy:CreateDeployment on a Server-platform deployment group: (1) a revision with no conflicting path succeeds (deploymentInfo.status 'Succeeded'); (2) a revision whose newly-added path already holds out-of-band bytes, deployed with fileExistsBehavior='DISALLOW', ends 'Failed' with errorInformation set and the foreign bytes still on disk; (3) the same revision with fileExistsBehavior='OVERWRITE' succeeds and the path reads the revision's bytes.

Actual (emulator): the agent-active phase of the readiness gate never completes. Verbatim failure for the check:
  codedeploy.file-exists-behavior-disallow-blocks-foreign-file-and-overwrite-replaces-it — "TimeoutError: the CodeDeploy agent active on ['i-00000000000000001']: the run budget ended first; not graded", raised from _wait_fleet_ready (the loop that calls _invoke_command -> ssm:SendCommand + ssm:GetCommandInvocation for 'systemctl is-active codedeploy-agent').
SendCommand is accepted and returns a CommandId; the invocation's stdout is never 'active'. No codedeploy:CreateDeployment (computePlatform 'Server') is reached, so no deploymentInfo.status, errorInformation, lifecycle event status or on-host file content is produced to compare.

Per-run values that are NOT part of the requirement: the instance id ('i-00000000000000001'), the generated application / deployment-group / bucket names and object keys, the content markers, the command id, the deployment id, and the run budget duration itself. The requirement is only that a Run Command sent to a running managed node reaches a terminal CommandInvocationStatus with its stdout, and that a Server-platform CreateDeployment then honours fileExistsBehavior DISALLOW/OVERWRITE on the host.

## Steps to Reproduce
1. Create an S3 bucket and upload three zip revisions whose manifests are {app.txt}, {app.txt, extra_disallow.txt} and {app.txt, extra_disallow.txt, extra_overwrite.txt}.
2. Create a VPC with a public subnet and an instance profile granting AmazonSSMManagedInstanceCore plus S3 read on that bucket.
3. ec2:RunInstances one t3.micro with that profile, tagged with the key the deployment group will filter on, with user data installing the SSM Agent and the CodeDeploy agent; wait for instance state 'running'.
4. Poll ssm:DescribeInstanceInformation(Filters=[{Key:'InstanceIds',Values:[<id>]}]) until PingStatus == 'Online' (this step passes today).
5. ssm:SendCommand(InstanceIds=[<id>], DocumentName='AWS-RunShellScript', Parameters={commands:['systemctl is-active codedeploy-agent']}), then poll ssm:GetCommandInvocation(CommandId=<returned id>, InstanceId=<id>). Observe that the invocation never reaches a terminal CommandInvocationStatus with StandardOutputContent == 'active', so the readiness gate loops until the run budget is spent and the check aborts with the TimeoutError above.
6. Because of step 5 the graded part is never reached: codedeploy:CreateApplication(computePlatform='Server') + CreateDeploymentGroup(ec2TagFilters=[{Key,Value,Type:'KEY_AND_VALUE'}], deploymentConfigName='CodeDeployDefault.AllAtOnce') + CreateDeployment with revision A (no conflict), then writing foreign bytes to /opt/sim2real/extra_disallow.txt out of band and deploying revision B with fileExistsBehavior='DISALLOW' (expect deploymentInfo.status 'Failed' with errorInformation and the foreign bytes retained), then revision C with fileExistsBehavior='OVERWRITE' (expect 'Succeeded' and the revision's bytes on disk) — none of which is observable.
