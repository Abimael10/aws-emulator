# AWS-managed security requirement packs ship an abridged, incomplete requirement catalog

> _Note: this issue was identified against the code base at commit `63b765d6e44c9c410b25a47ff497d3999b0c3a5c`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
ListSecurityRequirements

## Description
Four net-new causes, one per AWS-managed pack the catalog advertises. All four share ONE fault: the seeded AWS-managed requirement catalog is an ABRIDGED sample of each pack's shipped content — only a handful of entries per pack, and (for three of the four packs) each entry's `description` is a one-sentence paraphrase instead of the pack's published requirement text. ListSecurityRequirements answers HTTP 200 in every case; the status and the response SHAPE are right and only the catalog content is short, so this is a seed-content defect, not a handler defect.

NOTE ON OVERLAP: open issue 20261108T133019Z-securityagent-aws-managed-security-requirement-packs-return-no-requirements reported these same four steps as returning an EMPTY list. The seed now exists, so that symptom is gone and a different one is on the wire: partial, paraphrased content. The replay reports `owned_by: []` for all four of these clusters, so none of them is covered by that issue's replay key and all four must be closed here.

Cause 1 of 4 — packId srp-am-base (fixture securityagent-catalog-list-security-requirements, step task#1).
AWS: Smithy: ListSecurityRequirements (POST /ListSecurityRequirements, 200, @readonly, @paginated items=securityRequirementSummaries) takes packId (SecurityRequirementPackId, @required) and returns securityRequirementSummaries (@required); SecurityRequirementSummary.packId/name/description/createdAt/updatedAt are ALL @required, createdAt/updatedAt @timestampFormat date-time. Recorded behavior only for the CONTENTS: the model enumerates neither which packs AWS ships nor what they hold. The recording shows the base pack answering with its WHOLE shipped requirement set — every requirement name the pack defines, each with packId equal to the requested pack id, its own description, and the pack content's fixed publication instant as both createdAt and updatedAt (one value shared by every entry of the pack, not a per-run clock reading).
Emulator: the listing returns only the subset the seed table holds; the recording's remaining base-pack requirements are absent — the replay reports each as `missing (expected {...}, got None)` for names including authentication-best-practices, authorization-best-practices, information-protection-best-practices, log-protection-best-practices, privileged-access-best-practices, secret-protection-best-practices, secure-by-default-best-practices, tenant-isolation-best-practices and trusted-cryptography-best-practices (18 names in total for this step). The entries that ARE seeded match, so the projection path is right and only the table is short.
Why: a client that reads the AWS-managed catalog to discover or evaluate against what AWS ships sees a pack that is missing most of its rules, and concludes those rules do not exist rather than that the catalog is unseeded. Any flow that selects a requirement name out of a managed pack (BatchGetSecurityRequirements against managed content, asserting managed content is immutable) fails for the absent names with a per-item error instead of returning the rule. Pagination over a managed pack also terminates far too early, since nextToken is minted only while entries remain.
Fix: the service's seeded state — the AWS-managed requirement content table for the base pack, which must hold the pack's complete shipped requirement set rather than a sample, keyed by (packId, name) in the same requirement store BatchCreateSecurityRequirements writes and ListSecurityRequirements/BatchGetSecurityRequirements read, with the pack content's fixed publication instant rather than the boot clock. The ListSecurityRequirements handler needs no change.
Traces: securityagent-catalog-list-security-requirements#task#1.
