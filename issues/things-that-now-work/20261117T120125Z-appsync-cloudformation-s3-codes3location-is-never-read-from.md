# appsync__cloudformation__s3: CodeS3Location is never read from S3, so AWS::AppSync::FunctionConfiguration / AWS::AppSync::Resolver cannot be deployed from an S3 object and the missing-object failure reason is emulator-authored

> _Note: this issue was identified against the code base at commit `316bc8d4d27618b04e0a3739e3ce26f595ac855b`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
CreateFunction

## Description
One net-new root cause, grounded in two failing behavioral checks that are neither ALREADY FILED nor OWNED by an open issue.

Cause 1 of 1: the CloudFormation handlers for AWS::AppSync::FunctionConfiguration and AWS::AppSync::Resolver do not fetch the APPSYNC_JS document named by CodeS3Location, so every such resource fails to create and the stack rolls back; and when the S3 object really is absent, the recorded CREATE_FAILED reason is the emulator's own sentence instead of AWS's.
Failing check ids: appsync__cloudformation__s3.deploy-function-and-resolver-cfn-code-s3-location-matches-uploaded-code, appsync__cloudformation__s3.deploy-function-cfn-code-s3-location-missing-object-rejected
AWS: Smithy: CreateFunction.code and CreateResolver/UpdateResolver.code target Code (@length 1..32768) with runtime AppSyncRuntime{APPSYNC_JS, 1.0.0}; the CFN resources accept EITHER Code or CodeS3Location, and for CodeS3Location the resource handler reads the named s3://<bucket>/<key> object and submits its bytes as `code`. On a successful deploy the stack reaches CREATE_COMPLETE, GetFunction().functionConfiguration.code and GetResolver().resolver.code are byte-for-byte the uploaded objects, GetAtt FunctionId/FunctionArn/ResolverArn match the created resources, and a query through the pipeline returns the function's result. When the object does not exist, the S3 read fails and the resource handler reports CREATE_FAILED with the fixed reason form `Resource handler returned message: "<message>" (RequestToken: <token>, HandlerErrorCode: <code>)` where <code> is GeneralServiceException and <message> is AWS's nested S3-read diagnosis — "Error occurred during operation 'Error reading Code from S3.Error occurred during operation 'Error reading CodeS3Location from S3. Error message: The specified key does not exist. (Service: S3, Status Code: 404, Request ID: <id>, Extended Request ID: <id>) (SDK Attempt Count: <n>)'.'." — whose fixed text is that sentence nest including "The specified key does not exist." and "Status Code: 404", with the request ids and attempt count as the only run-specific parts.
Emulator: CodeS3Location is not implemented at all. The happy-path stack ends ROLLBACK_COMPLETE even though both objects were uploaded before CreateStack, so no function or resolver is ever created from S3, and the missing-object stack records the emulator-authored reason ("this emulator does not read the document a AWS::AppSync::FunctionConfiguration holds in Amazon S3, so the resource was not created from its CodeS3Location property") with HandlerErrorCode InvalidRequest instead of AWS's S3-read message with GeneralServiceException.
Why: CodeS3Location is the standard way real templates ship resolver/function JS (CDK and `aws cloudformation package` emit it), so every such stack fails to deploy on the emulator — a user cannot deploy an AppSync pipeline at all, and the one failure they do see names the emulator rather than diagnosing their template or their missing object. A fixer must also keep the two classifications apart: a readable object must deploy, and an unreadable one must fail as a service/S3 error (GeneralServiceException), not as a client InvalidRequest.
Fix: the AWS::AppSync::FunctionConfiguration and AWS::AppSync::Resolver CFN resource handlers — resolve the CodeS3Location URI, read the object through S3, submit its bytes as `code` to CreateFunction/CreateResolver, and map an S3 read failure onto the GeneralServiceException resource-handler reason.
Traces: appsync__cloudformation__s3.deploy-function-and-resolver-cfn-code-s3-location-matches-uploaded-code (mismatch: stack ended 'ROLLBACK_COMPLETE'), appsync__cloudformation__s3.deploy-function-cfn-code-s3-location-missing-object-rejected (mismatch: wrong handler reason and HandlerErrorCode).

## Evidence

Actual (emulator): AssertionError: stack arn:aws:cloudformation:us-west-2:000000000000:stack/sim2real-appsync-s3code-<id>/<id> ended 'ROLLBACK_COMPLETE' — nothing is created from S3.

Error message: The specified key does not exist. (Service: S3, Status Code: 404, Request ID: <id>, Extended Request ID: <id>) (SDK Attempt Count: <n>)'.'.", 'GeneralServiceException').
Actual (emulator): ('this emulator does not read the document a AWS::AppSync::FunctionConfiguration holds in Amazon S3, so the resource was not created from its CodeS3Location property', 'InvalidRequest').

## Steps to Reproduce
1. s3.CreateBucket(<bucket>) and PutObject func.js / resolver.js with the APPSYNC_JS modules above.
2. cloudformation.CreateStack with Parameters {ApiName, CodeBucket} and Resources {GraphQLApi: AWS::AppSync::GraphQLApi(API_KEY), ApiKey: AWS::AppSync::ApiKey, GraphQLSchema: AWS::AppSync::GraphQLSchema('type Query { s3CodeTest: String } schema { query: Query }'), NoneDataSource: AWS::AppSync::DataSource(Type NONE, Name NoneDS), Func1: AWS::AppSync::FunctionConfiguration(Runtime {APPSYNC_JS,1.0.0}, DataSourceName NoneDS, CodeS3Location !Sub 's3://${CodeBucket}/func.js'), PipelineResolver: AWS::AppSync::Resolver(Kind PIPELINE, PipelineConfig.Functions [!GetAtt Func1.FunctionId], Runtime {APPSYNC_JS,1.0.0}, CodeS3Location !Sub 's3://${CodeBucket}/resolver.js')}.
3. Poll DescribeStacks — AWS: CREATE_COMPLETE; emulator: ROLLBACK_COMPLETE.
4. (unreachable on the emulator) GetFunction/GetResolver must echo the uploaded JS byte-for-byte and `query { s3CodeTest }` must return 's3-function-result'.
5. Repeat with a CodeS3Location naming a key that was never uploaded and read the FunctionConfiguration's CREATE_FAILED ResourceStatusReason — AWS reports the nested S3 "The specified key does not exist." message with HandlerErrorCode GeneralServiceException; the emulator reports its own sentence with InvalidRequest.
