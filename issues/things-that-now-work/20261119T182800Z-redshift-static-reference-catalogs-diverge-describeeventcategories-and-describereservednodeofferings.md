# Redshift static reference catalogs diverge: DescribeEventCategories and DescribeReservedNodeOfferings serve non-AWS content (2 causes)

> _Note: this issue was identified against the code base at commit `16f3de6a7977b3149b880d4eb34f151da138eb5e`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
DescribeEventCategories

## Description
Two net-new causes, both the same underlying fault: Redshift's read-only, account-independent REFERENCE CATALOGS are not seeded from AWS's published content. Both operations answer HTTP 200 with a well-formed envelope, so a client sees a successful response whose body is simply not AWS's catalog. This issue is NOT covered by the open catalog issue 20261103T040731Z-redshift-parameter-group-validation-and-the-parameter-catalog.md, which concerns the cluster-parameter catalog and parameter-group validation, not the event-category or reserved-node-offering catalogs.

Cause 1 of 2: DescribeEventCategories returns none of AWS's event-category maps.
AWS: Smithy: DescribeEventCategories input {SourceType: String (optional)}, output EventCategoriesMessage.EventCategoriesMapList: list<EventCategoriesMap>; EventCategoriesMap = {SourceType: String, Events: list<EventInfoMap>}; EventInfoMap = {EventId, EventCategories: list<String>, EventDescription, Severity ('Values: ERROR, INFO')}. The operation models NO errors — it is a pure catalog read. AWS returns one EventCategoriesMap per event SOURCE TYPE (cluster, cluster-parameter-group, cluster-security-group, cluster-snapshot, scheduled-action, ...), each carrying the full set of REDSHIFT-EVENT-nnnn EventInfoMap entries for that source type, with the documented EventId, the templated EventDescription (AWS's fixed text with placeholder parts such as '<cluster name>' and '<time in UTC>' — e.g. 'Cluster <cluster name> created at <time in UTC>.' for REDSHIFT-EVENT-2000 and 'Cluster <cluster name> deleted at <time in UTC>.' for REDSHIFT-EVENT-2001), the EventCategories member ('management', 'monitoring', 'pending', 'security', ...) and Severity ('INFO' or 'ERROR'). This is a fixed published catalog: it does not depend on the account, the region or any created resource, so it is reproducible verbatim.
Emulator: the replayed response is HTTP 200 but every expected EventCategoriesMap is absent — the diff reports $.DescribeEventCategoriesResponse.DescribeEventCategoriesResult.EventCategoriesMapList.EventCategoriesMap[0] through [5] as 'missing', i.e. the emulator's EventCategoriesMapList does not contain the six AWS source-type maps, so no REDSHIFT-EVENT-nnnn EventId, EventDescription, EventCategory or Severity value is served at all.
Why: a client that drives event-subscription setup or event-severity filtering off this catalog (choosing a SourceType, picking EventCategories to subscribe to, or mapping a received EventId back to its description/severity) gets an empty or unrecognizable catalog. It cannot enumerate valid source types or categories, so subscription-building code and any UI/validation fed by this call silently sees zero options against the emulator while it works against AWS.
Fix: the DescribeEventCategories handler and the static reference data it reads — the catalog must be seeded with AWS's published per-source-type event maps (EventId, templated EventDescription, EventCategories, Severity) and filtered by the optional SourceType input.
Traces: redshift-catalog-describe-event-categories#task#1.

Cause 2 of 2: DescribeReservedNodeOfferings serves a fabricated offering catalog instead of AWS's.
AWS: Smithy: DescribeReservedNodeOfferings input {ReservedNodeOfferingId, MaxRecords: IntegerOptional, Marker}, output ReservedNodeOfferingsMessage {Marker, ReservedNodeOfferings: list<ReservedNodeOffering>}, paginated (inputToken Marker / outputToken Marker / items ReservedNodeOfferings / pageSize MaxRecords); errors DependentServiceUnavailableFault (400), ReservedNodeOfferingNotFoundFault (404, awsQueryError ReservedNodeOfferingNotFound), UnsupportedOperationFault (400). ReservedNodeOffering = {ReservedNodeOfferingId, NodeType, Duration: Integer (seconds), FixedPrice: Double, UsagePrice: Double, CurrencyCode, OfferingType, RecurringCharges: list<RecurringCharge>, ReservedNodeOfferingType: enum}. The unfiltered call returns AWS's whole published offering catalog: the recording shows it spans the current node families (e.g. rg.large, rg.xlarge) across BOTH term lengths — Duration 31536000 (1 year) and 94608000 (3 years) — and all three OfferingTypes ('All Upfront', 'No Upfront', 'Partial Upfront'), with ReservedNodeOfferingType 'Regular', CurrencyCode 'USD', and the Double members serialized in decimal form ('0.0', '3743.6', '0.33075'). Like the event-category list this is account-independent published pricing data.
Emulator: HTTP 200, but every one of the recorded 60 offerings ($...ReservedNodeOfferings.ReservedNodeOffering[0] .. [59]) is reported missing — the emulator substitutes a different, generated catalog: only the legacy dc2.large NodeType, only Duration '31536000' (no 3-year term), and Double members rendered as bare integers ('FixedPrice': '0', 'UsagePrice': '0') rather than AWS's decimal form, with per-call random ReservedNodeOfferingId values. No AWS offering row is reproduced. (The individual ReservedNodeOfferingId strings are AWS-side catalog ids and are not themselves a requirement; the requirement is that the catalog cover the node types, term Durations, OfferingTypes and Double formatting AWS publishes.)
Why: a client that lists offerings to pick one for PurchaseReservedNodeOffering finds no 3-year term and no current-generation node type, so the purchase flow it exercises on AWS cannot be reproduced; cost/term-comparison logic also sees zero candidates for anything but dc2.large, and a Double parsed from '0' versus '0.0' changes nothing numerically but breaks exact-shape assertions on the serialized price fields.
Fix: the DescribeReservedNodeOfferings handler and its static offering reference data (plus the Double serializer used for FixedPrice/UsagePrice) — seed AWS's published offering rows across node types, both term Durations and all OfferingTypes, honour the ReservedNodeOfferingId filter with ReservedNodeOfferingNotFoundFault (404 / ReservedNodeOfferingNotFound) for an unknown id, and serialize Double members in decimal form.
Traces: redshift-catalog-describe-reserved-node-offerings#task#1.
