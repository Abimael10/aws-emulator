## Description
5 net-new causes, one per ServiceCode. For each of the ServiceCodes apigateway, appconfig, application-autoscaling, athena and backup the emulator DOES answer ListAWSDefaultServiceQuotas with HTTP 200 and a non-empty Quotas list, but the rows it serves are not the AWS rows: a row's identity (QuotaCode) and its payload (QuotaName / Value / Unit / Adjustable / Description / Period / UsageMetric) come from different catalog entries, Description is omitted on rows that are served, some Descriptions are re-worded, and single rows are absent entirely. Each cause below is a distinct ServiceCode's catalog and must be closed separately.

Related open issues cover this SAME defect class for OTHER service codes and carry no replay key for the five below, so these are filed here rather than added to them: 20261113T222805Z-service-quotas-access-analyzer-acm-acm-pca-and-6-more.md, 20261118T222104Z-service-quotas-listawsdefaultservicequotas-rows-for-batch-cassandra-cloud9-cloudhsm-cloudtrail.md, 20261119T100022Z-service-quotas-dynamodb-ebs-ecr-and-6-more-listawsdefaultservicequotas-catalogs.md and 20261121T171035Z-service-quotas-listawsdefaultservicequotas-default-quota-catalog-omits-rows.md.

AWS (common to all 5 causes): Smithy ListAWSDefaultServiceQuotas — input ServiceCode (required, @length 1..63, @pattern ^[a-zA-Z][a-zA-Z0-9-]{1,63}$), NextToken, MaxResults (@range 1..100); output 200 with Quotas: list<ServiceQuota>, NextToken; modeled errors AccessDeniedException 403, IllegalArgumentException 400, InvalidPaginationTokenException 400, NoSuchResourceException 404, ServiceException 500, TooManyRequestsException 429. Smithy ServiceQuota members: ServiceCode, ServiceName, QuotaArn, QuotaCode (@length 1..128, @pattern ^[a-zA-Z][a-zA-Z0-9-]{1,128}$), QuotaName, Value (double @range 0..10000000000), Unit, Adjustable (boolean, default false, "Indicates whether the quota value can be increased"), GlobalQuota (default false), UsageMetric (MetricInfo: MetricNamespace, MetricName, MetricDimensions map @length 0..10, MetricStatisticRecommendation @pattern ^(Sum|Maximum)$), Period (QuotaPeriod: PeriodValue, PeriodUnit) and Description (@length 0..350, "The quota description"). AWS returns one row per published default quota for the requested ServiceCode, and every member of a row — name, value, unit, adjustability, description and, for rate quotas, Period and UsageMetric — belongs to the SAME QuotaCode. Which codes exist for a service code and what their published text and values are is not stated by the model: recorded behavior only, and the recordings are the reference. The requirement asserted here is structural — the QuotaCode-to-row binding, the presence of every published row, and verbatim publication of the AWS Description/QuotaName text — not any one recorded number from a single run.

Emulator (common, from the replay output): HTTP 200 == expected 200, so this is a body-only divergence in all five clusters. Three sub-defects recur: (a) the row served under a QuotaCode carries another quota's QuotaName, Value and/or Unit and sometimes an inverted Adjustable, i.e. the catalog rows are shifted/misbound relative to their codes; (b) Description is absent on served rows ("Description: missing ... got None"); (c) Description/QuotaName are present but re-worded relative to the AWS text, and one whole row is absent.

Why: ListAWSDefaultServiceQuotas is how a client discovers a service's published limits by QuotaCode. With rows misbound, a client that looks up a code reads a different quota's name and ceiling under it and then enforces, reports or requests an increase against the wrong limit while believing it read the right one — an inverted Adjustable additionally decides whether RequestServiceQuotaIncrease is attempted at all. A missing or re-worded Description breaks consoles and reports that display the published quota text, and an absent row makes a quota that exists in AWS look nonexistent.

Fix: the service-quotas crate's static default-quota catalog plus the ListAWSDefaultServiceQuotas response projection. Rows must be keyed by QuotaCode with QuotaName/Value/Unit/Adjustable/GlobalQuota/Description (and Period/UsageMetric where AWS publishes them) all taken from the SAME catalog entry, Description must be serialized rather than dropped, and the AWS text must be stored verbatim rather than paraphrased.
