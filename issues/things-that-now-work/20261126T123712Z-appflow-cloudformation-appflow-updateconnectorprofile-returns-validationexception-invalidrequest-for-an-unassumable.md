# AppFlow UpdateConnectorProfile returns ValidationException/InvalidRequest for an unassumable Redshift DataApiRoleArn instead of the connector-test ConnectorServerException/GeneralServiceException

> _Note: this issue was identified against the code base at commit `1f229c2134bf0bc4981979e50b09562ad02080b6`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
UpdateConnectorProfile

## Description
One net-new root cause.

NOTE: the open issue 20261126T101441Z-appflow-cloudformation-appflow-updateconnectorprofile-misclassifies-an-unassumable-redshift-dataapirolearn-as.md describes this same divergence, but the replay report does NOT mark the failing check as OWNED by it (it carries no replay key for this check), so the check is still ungated and is re-filed here with its check id in trace_ids. Treat the two as the same work item.

Cause 1 of 1: UpdateConnectorProfile refuses a Redshift connector profile whose dataApiRoleArn names a role AppFlow cannot assume with the wrong error class and the wrong message, so the CloudFormation AWS::AppFlow::ConnectorProfile UPDATE_FAILED event carries HandlerErrorCode `InvalidRequest` where AWS carries `GeneralServiceException`. Failing check: appflow__cloudformation.deploy-appflow-connector-profile-redshift-bad-data-api-role-update-rejected-and-rolled-back.

AWS: Smithy (com.amazonaws.appflow#SandstoneConfigurationServiceLambda) models UpdateConnectorProfile as POST /update-connector-profile, success 200, errors ConflictException(409), ConnectorAuthenticationException(401), InternalServerException(500), ResourceNotFoundException(404), ValidationException(400, doc "The request has invalid or missing parameters."); the service also models com.amazonaws.appflow#ConnectorServerException (@httpError 400, doc "An error occurred when retrieving data from the connector endpoint.", single `message` member). The model does not state the wording, so recorded behavior only for the text: AWS does NOT treat an unassumable role as a request-parameter defect. It accepts the request as well-formed, runs the connector's test connection, and fails on the connector's answer with a 400 whose message is the connector-communication failure. Its FIXED text is "Error while communicating to connector: The test connection request failed due to: com.amazonaws.sandstoneconfigurationservicelambda.coral.model.ConnectorServerException: Failed to validate Connection while attempting \"select distinct(table_schema) from information_schema.tables limit 1\" with connector failure The request for the  Redshift failed with the status code 403: AccessDenied while trying to assume user-provided <roleArn> role by AppFlow service principal. (Service: null; Status Code: 400; Error Code: Client; Request ID: <id>; Proxy: null) (Service: Appflow, Status Code: 400, Request ID: <id>) (SDK Attempt Count: <n>)" — the doubled space in "for the  Redshift" is part of AWS's fixed text. Its VARIABLE parts are ONLY the role ARN, taken verbatim from the request's connectorProfileConfig.connectorProfileProperties.Redshift.dataApiRoleArn, plus the per-run request ids and SDK attempt count (never part of the template). Because that failure is a connector-communication fault and not a parameter fault, the AWS::AppFlow::ConnectorProfile resource handler reports it with HandlerErrorCode `GeneralServiceException`, and the stack rolls back to the previous role.

Emulator: the request is refused by a pre-flight IAM/role check instead of a connector test. The UpdateConnectorProfile handler (services/service-com-amazonaws-appflow-sandstoneconfigurationservicelambda/src/ops/update_connector_profile.rs, the crate::state::unusable_connector_profile_role / UPDATE_CONNECTOR_PROFILE_REQUEST branch) answers 400 ValidationException with the message "Update Connector Profile request failed: [Amazon AppFlow is not authorized to assume the role [<roleArn>]. Update the trust policy of the role so that it can be assumed by the [appflow.amazonaws.com] service principal]", and CloudFormation records that resource failure with HandlerErrorCode `InvalidRequest`. The rollback direction itself is correct — the stack does reach UPDATE_ROLLBACK_COMPLETE and the profile is not replaced — so ONLY the error class and the message text diverge.

Why: a client that classifies CloudFormation resource failures by HandlerErrorCode sees a terminal request-validation fault (`InvalidRequest`) where AWS reports a service-side connector fault (`GeneralServiceException`), so retry/alarm policies keyed on that code take the wrong branch. A client calling AppFlow directly gets ValidationException instead of the connector-communication 400, and the message never names the connection test, the SQL probe, the 403/AccessDenied cause or the AppFlow service principal in AWS's wording, so log- or message-matching on AWS's connector-failure sentence fails even though the update was correctly refused.

Fix: the AppFlow UpdateConnectorProfile handler's role pre-flight branch and the message builder behind crate::state::unusable_connector_profile_role / UPDATE_CONNECTOR_PROFILE_REQUEST in that crate's state module — an unassumable connector role must surface as the connector-test failure (ConnectorServerException-class 400) with AWS's connector-communication message template — together with the CloudFormation AWS::AppFlow::ConnectorProfile resource mapping, which must map that error class to HandlerErrorCode GeneralServiceException rather than InvalidRequest. Not covered by the open issues "AppFlow connector-profile not-found message text wrong on Delete and Update" (20261126T055149Z) or "AppFlow error message text diverges from AWS wording" (20261029T192701Z), which concern 404 not-found and @pattern wording; nor by "AppFlow CreateConnectorProfile skips connector-property validation and persists invalid profile" (20261126T055149Z), which concerns the create path's missing validation rather than the update path's error class.

Traces: appflow__cloudformation.deploy-appflow-connector-profile-redshift-bad-data-api-role-update-rejected-and-rolled-back (the ConnectorProfile UPDATE_FAILED event's ResourceStatusReason and HandlerErrorCode).

## Evidence
Check appflow__cloudformation.deploy-appflow-connector-profile-redshift-bad-data-api-role-update-rejected-and-rolled-back, assertion `got == want` on the (masked message, HandlerErrorCode) parsed out of the ConnectorProfile UPDATE_FAILED stack event.

Expected (AWS): HandlerErrorCode "GeneralServiceException"; message "Error while communicating to connector: The test connection request failed due to: com.amazonaws.sandstoneconfigurationservicelambda.coral.model.ConnectorServerException: Failed to validate Connection while attempting \"select distinct(table_schema) from information_schema.tables limit 1\" with connector failure The request for the  Redshift failed with the status code 403: AccessDenied while trying to assume user-provided <dataApiRoleArn-from-request> role by AppFlow service principal. (Service: null; Status Code: 400; Error Code: Client; Request ID: <id>; Proxy: null) (Service: Appflow, Status Code: 400, Request ID: <id>) (SDK Attempt Count: <n>)". Fixed text: everything except the role ARN (a request value) and the per-run request ids / attempt count (masked by the check).

Actual (emulator): HandlerErrorCode "InvalidRequest"; message "Update Connector Profile request failed: [Amazon AppFlow is not authorized to assume the role [arn:aws:iam::<account>:role/<generated-name>]. Update the trust policy of the role so that it can be assumed by the [appflow.amazonaws.com] service principal]". The generated role name and account in that string are per-run values, not part of any requirement.

The preceding assertion that the stack reaches UPDATE_ROLLBACK_COMPLETE passed, so the refusal and rollback are in the right direction; the error classification and the message text are the divergence.

Model basis: Smithy UpdateConnectorProfile errors = ConflictException(409), ConnectorAuthenticationException(401), InternalServerException(500), ResourceNotFoundException(404), ValidationException(400, "The request has invalid or missing parameters."); com.amazonaws.appflow#ConnectorServerException @httpError 400, doc "An error occurred when retrieving data from the connector endpoint."
