ListAWSDefaultServiceQuotas

## Description
ListAWSDefaultServiceQuotas answers HTTP 200 for all eight of these ServiceCodes, but the rows it serves are not AWS's default-quota catalog. Two faults recur in every cause and are the shared root cause: (a) the emulator's catalog table has no Description text, so `ServiceQuota.Description` is absent from rows where AWS always populates it (or is served in re-worded/re-capitalised form), and (b) the catalog's per-row metadata is bound to the wrong QuotaCode, so a row keyed by one AWS L- code reports a DIFFERENT quota's QuotaName, Value, Unit and Adjustable. This is eight separate ServiceCode catalogs, so it is eight causes to close.

General requirement (applies to every cause): for a ServiceCode registered with Service Quotas, every row of `Quotas` must be the AWS default quota for that `QuotaCode`, with `QuotaName`, `Description`, `Value`, `Unit`, `Adjustable`, `GlobalQuota`, and — where AWS publishes them — `Period` and `UsageMetric` all taken from the SAME AWS quota as the `QuotaCode` that keys the row. Smithy: ListAWSDefaultServiceQuotas output `Quotas` -> ServiceQuotaListDefinition of `ServiceQuota`; `ServiceQuota.Description` is a modelled member (QuotaDescription, @length 0..350, doc "The quota description."), `ServiceQuota.QuotaName`, `.Value` (QuotaValue double, @range 0..10000000000), `.Unit`, `.Adjustable` (@default false), `.Period` (QuotaPeriod) and `.UsageMetric` (MetricInfo) are likewise modelled. The specific expected row values are recorded behavior only — they are the live AWS catalog captured in the fixtures — so each cause below cites the recorded expectation. Status is 200 in both AWS and the emulator; nothing here is an error-path divergence.

Cause 1 of 8 — apigateway (fixture service-quotas-catalog-list-aws-default-service-quotas-apigateway, step task#1).
AWS: the apigateway default catalog carries a Description on every row and binds each row's metadata to its own QuotaCode — e.g. L-F8A34CAF Description 'The maximum size of a logo'; L-B4D69DB7 Description 'The maximum number of custom domain names per portal'; L-1D180A63 Description 'The maximum number of API keys that you can create in this account in the current region'; L-46624B39 QuotaName 'API Payload Size', Unit 'Megabytes', Adjustable false; L-824C9E42 QuotaName 'Client certificates', Value 60.0; L-E5AE38E3 QuotaName 'Maximum integration timeout in milliseconds', Unit 'Milliseconds', Value 29000.0.
Emulator: Description is absent on ~50 rows; L-B4D69DB7's Description is re-capitalised to 'The maximum number of Custom Domain Names per Portal'; L-46624B39 reports QuotaName 'Authorizers per API', Unit 'None', Adjustable true; L-824C9E42 reports QuotaName 'VPC links per account per Region', Value 20.0; L-E5AE38E3 reports QuotaName 'Custom authorizer result TTL', Unit 'Seconds', Value 3600.0 — i.e. neighbouring quotas' rows shifted onto the wrong codes.
Why: a client that reads the API Gateway integration-timeout quota is told 3600 Seconds where the real limit is 29000 Milliseconds, and the client-certificate quota reads 20 instead of 60, so capacity planning and quota-increase automation act on limits AWS does not enforce; a console or report that renders Description shows blanks.
Fix: the service-quotas default-quota catalog data for ServiceCode 'apigateway' and the row projection in the ListAWSDefaultServiceQuotas handler that keys rows by QuotaCode.
Traces: service-quotas-catalog-list-aws-default-service-quotas-apigateway#task#1.

Cause 2 of 8 — appconfig (fixture service-quotas-catalog-list-aws-default-service-quotas-appconfig, step task#1).
AWS: L-08D2C632, L-48F9B951, L-B858C085, L-F59D302B and L-FA210A1F each carry their documented Description (e.g. L-FA210A1F 'A configuration profile contains metadata about a particular set of configuration data used by your application. Emulator: those Descriptions are absent; L-FA210A1F reports a different QuotaName ('Maximum number of application...'), and L-A52E46BE / L-A5FC0339 / L-EEB0151E diverge on Period.PeriodUnit, UsageMetric.MetricName / MetricNamespace / MetricDimensions (Resource, Service, Type) / MetricStatisticRecommendation, Unit and Value.
Why: AppConfig callers read the wrong configuration-profile and rate limits, and the UsageMetric a client would use to build a CloudWatch utilisation alarm points at the wrong metric dimensions, so the alarm never fires.
Fix: the service-quotas default-quota catalog data for ServiceCode 'appconfig', including its Period/UsageMetric sub-structures.
Traces: service-quotas-catalog-list-aws-default-service-quotas-appconfig#task#1.
