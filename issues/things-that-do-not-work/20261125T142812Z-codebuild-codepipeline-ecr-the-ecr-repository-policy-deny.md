# codebuild__codepipeline__ecr: the ECR repository-policy Deny differential reaches no observable step — the CodeBuild builds that push and pull the image produce no verdict inside the harness budget

> _Note: this issue was identified against the code base at commit `34f8b997a46d03b643856bad1989006f24f5aecc`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
SetRepositoryPolicy

## Description
Cause 1 of 1: the whole repository-policy authorization differential on ECR is unreachable, because the CodeBuild builds that carry it never produce an outcome the check can read.
AWS: Smithy (ecr) SetRepositoryPolicy(repositoryName, policyText, force) -> {registryId, repositoryName, policyText}, DeleteRepositoryPolicy -> the removed document, DescribeImages -> {imageDetails}, error ImageNotFoundException; (codebuild) StartBuild -> {build} and BatchGetBuilds(ids) -> {builds, buildsNotFound} with Build.buildStatus in StatusType (SUCCEEDED, FAILED, FAULT, TIMED_OUT, IN_PROGRESS, STOPPED). On real AWS an explicit Deny in a repository's resource policy for a principal overrides that principal's identity-based Allow: a CodeBuild build whose service role has ecr:BatchGetImage/GetDownloadUrlForLayer allowed in IAM but denied by the repository policy fails its `docker pull` of that repository, the build ends buildStatus FAILED, the marker tag it would have pushed is absent so DescribeImages answers ImageNotFoundException with the message "The image with imageId {imageDigest:'null', imageTag:'<tag>'} does not exist within the repository with name '<repositoryName>' in the registry with id '<registryId>'" (fixed text as quoted; the tag, repository name and registry id come from the request and the account), and after DeleteRepositoryPolicy the IDENTICAL build succeeds and the tag appears. Recorded behavior: the check drives this with five builds on one project (two seeds that docker login/build/push, a denied pull, a restored pull and an allowed-repo control), each read back with BatchGetBuilds until buildStatus leaves IN_PROGRESS.
Emulator: the check produces no assertion at all — its only diagnostic is "Check timed out after 60.0s". No build outcome, no repository-policy effect and no DescribeImages verdict is reached, so neither the Deny nor its removal is exercised. Hypothesis (the timeout is the only evidence): the builds' docker login/build/push/pull work against the emulated registry does not complete promptly, which is consistent with two known conditions on this path — the open issue 20261124T134157Z-codebuild-ecr-ecs-elbv2-logs-ecr-repositoryuri-announces-registryid-dkr-ecr-region-localhost.md (the announced repositoryUri is a host the emulator does not serve, so a build's docker client has nothing to reach) and the codebuild finding filed in this same sweep that a build's commands are run inside the API request that reads the build instead of on an independent clock. Neither open issue carries this check's replay key, and the sibling checks of this group that DO reach an assertion are owned by other issues, so this scenario is uncovered.
Why: repository-policy authorization is the only mechanism that lets an account restrict a registry independently of IAM. A client cannot observe that a Deny blocks a pull, that the pull is restored when the Deny is removed, or that a blocked build fails rather than silently succeeding — and against this emulator the scenario simply hangs instead of answering, so the behaviour cannot be tested at all.
Fix: the ECR authorization path for repository policies (SetRepositoryPolicy/DeleteRepositoryPolicy evaluated by the pull operations BatchGetImage and GetDownloadUrlForLayer) together with the CodeBuild build-execution component that performs a build's docker registry calls, so a push/pull build reaches a terminal buildStatus promptly and the policy decision is visible in its outcome.
Traces: codebuild__codepipeline__ecr.ecr-repository-policy-denies-codebuild-role-blocks-pull.
