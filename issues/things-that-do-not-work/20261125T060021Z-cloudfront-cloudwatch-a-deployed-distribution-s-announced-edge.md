# cloudfront__cloudwatch: a Deployed distribution's announced edge address never answers a viewer GET, so neither additional-metrics check (reconciliation nor subscription gating) reaches a verdict

> _Note: this issue was identified against the code base at commit `5dff3459c9fa0114d27ae1b22046b841878cac27`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
CreateMonitoringSubscription

## Description
One net-new root cause, grounded in the two failing checks the suite lists under `### cloudfront__cloudwatch` (0/2, 2 failed). The replay marked neither of them ALREADY FILED nor OWNED, so neither is covered by an existing issue's replay key. Related OPEN issues in this area that do NOT carry these checks' keys and therefore do not cover them: 20261118T131652Z-cloudfront-cloudwatch-reopens-20261115t110550z-cloudfront-cloudwatch-the-obs.md (same reconciliation check, but filed against the earlier symptom where the run exhausted its 600 s budget with no verdict), 20261029T175823Z-cloudfront-10-more-divergences-the-edge-data-plane.md and 20261110T105638Z-cloudfront-4-net-new-causes-origin-group-failover.md. The symptom has also changed shape: the edge address is now reachable as a concept but refuses/never answers, and both checks now fail at their own bounded `_fetch_ok` barrier with the DATAPLANE_UNIMPLEMENTED marker rather than being killed by the run budget.

Cause 1 of 1: a CloudFront distribution that reports Status=Deployed does not serve viewer requests at the address the emulator announces for it, so no edge outcome is ever produced and, consequently, no AWS/CloudFront metric series can be reconciled against one. Failing checks: cloudfront__cloudwatch.obs-cloudfront-1-additional-metrics-match-recorded-edge-outcomes, cloudfront__cloudwatch.obs-cloudfront-1-additional-metrics-withheld-without-monitoring-subscription.
AWS:      Smithy models the control plane only — CreateMonitoringSubscription / GetMonitoringSubscription carry MonitoringSubscription.RealtimeMetricsSubscriptionConfig.RealtimeMetricsSubscriptionStatus with enum values Enabled|Disabled; GetDistribution reports Distribution.Status, and the distribution's DomainName is the host viewers address. The data-plane behavior is recorded behavior only: once a distribution is Deployed, a viewer GET to its published DomainName for a key the origin holds is answered 200 with the origin object's bytes (first request X-Cache: Miss from cloudfront, repeats Hit from cloudfront under a caching-enabled policy), and a GET for a key the origin does not hold is answered with the origin's refusal status (403/404). Those served outcomes are then metered in namespace AWS/CloudFront under the dimension pair DistributionId=<distribution id> + Region='Global': Requests always, and the additional, subscription-gated series CacheHitRate, OriginLatency and the 4xx/403/5xx error rates only while the distribution's monitoring subscription is Enabled — withheld entirely on a distribution with no subscription. The requirement is that relation (served edge outcome -> published datapoint, gated by the subscription); the particular distribution id, host, minute and request counts of one run are not requirements.
Emulator: every viewer GET to the announced edge address fails. Both checks poll for a 200 for 300 s and raise their own data-plane marker: `AssertionError: DATAPLANE_UNIMPLEMENTED: timed out waiting for 200 from https://<announced-edge-address>/_aws/cloudfront/<distribution-id>/warmup.txt after 300.0s (last: None)`. In the sibling check filed separately for cloudfront__cloudwatch__sns__sqs the same barrier reports the underlying transport: `Connection refused` on the HTTPS port of the address the emulator announced. No request is therefore ever served, no edge outcome is recorded, and the subscription-gated comparison (present vs absent series on the subscribed side, their absence on the unsubscribed control) is never evaluated — not a single assertion past the warm-up is reached. This is not a runner fault: the checks use a 15 s per-request HTTP timeout and classify a never-serving edge with DATAPLANE_UNIMPLEMENTED precisely so it reads as a fidelity failure.
Why:      a client that enables a monitoring subscription and builds dashboards or alarms on CacheHitRate / OriginLatency / *ErrorRate sees permanently empty series, and alarms over them sit in INSUFFICIENT_DATA instead of tracking the edge, so cache tuning, paging and autoscaling keyed on them never fire. More basically, the distribution the client created is unusable: content published behind it cannot be fetched at the address CloudFront told the client to use, so the opt-in's effect (and its absence on an unsubscribed distribution) cannot be observed at all.
Fix:      the CloudFront edge data plane — the listener/routing component that must serve viewer requests at the very address GetDistribution publishes as DomainName for a Deployed distribution (it must answer there, not merely announce it) — plus the per-request outcome recording that feeds the AWS/CloudFront metric publication path CreateMonitoringSubscription gates, so Requests is published for any distribution and CacheHitRate/OriginLatency/*ErrorRate only while the subscription is Enabled.
Traces:   cloudfront__cloudwatch.obs-cloudfront-1-additional-metrics-match-recorded-edge-outcomes, cloudfront__cloudwatch.obs-cloudfront-1-additional-metrics-withheld-without-monitoring-subscription.

2. Create an S3 bucket holding one object at the present key and leave the absent key unwritten; create an origin access control (type s3, sigv4/always) and grant the distribution s3:GetObject on the bucket.
3. CreateDistribution over that bucket with the managed cache policy Managed-CachingOptimized (658327ea-f89d-4fab-a63d-7e88639e58f6); poll GetDistribution until Status == 'Deployed' and read the published DomainName.
4. CreateMonitoringSubscription(DistributionId=<id>, MonitoringSubscription={'RealtimeMetricsSubscriptionConfig': {'RealtimeMetricsSubscriptionStatus': 'Enabled'}}) and confirm GetMonitoringSubscription reads back 'Enabled'. 6. Issue the measured burst (present key once plus 3 repeats, absent key twice) inside one 60 s period on each distribution, then GetMetricStatistics in AWS/CloudFront with Dimensions DistributionId=<id>, Region='Global' for Requests (Sum), CacheHitRate (Average) and OriginLatency (ExtendedStatistics p90).
7. Re-replay cloudfront__cloudwatch.obs-cloudfront-1-additional-metrics-match-recorded-edge-outcomes and cloudfront__cloudwatch.obs-cloudfront-1-additional-metrics-withheld-without-monitoring-subscription to confirm the fix.
