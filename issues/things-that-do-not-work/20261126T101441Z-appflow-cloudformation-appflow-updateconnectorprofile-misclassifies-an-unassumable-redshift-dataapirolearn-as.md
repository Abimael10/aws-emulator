# AppFlow UpdateConnectorProfile misclassifies an unassumable Redshift DataApiRoleArn as ValidationException/InvalidRequest instead of the connector-test ConnectorServerException/GeneralServiceException

> _Note: this issue was identified against the code base at commit `e639516452877bddecc80c8c35ecbfcb1f8585bd`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
UpdateConnectorProfile

## Description
One net-new root cause.

Cause 1 of 1: UpdateConnectorProfile rejects a Redshift connector profile whose `DataApiRoleArn` names a role AppFlow cannot assume with the wrong error class and the wrong message, so the CloudFormation resource event carries HandlerErrorCode `InvalidRequest` where AWS carries `GeneralServiceException`. Failing check: appflow__cloudformation.deploy-appflow-connector-profile-redshift-bad-data-api-role-update-rejected-and-rolled-back.

AWS: Smithy (com.amazonaws.appflow#SandstoneConfigurationServiceLambda) models UpdateConnectorProfile as POST /update-connector-profile, success 200, with errors ConflictException(409), ConnectorAuthenticationException(401), InternalServerException(500), ResourceNotFoundException(404), ValidationException(400, doc "The request has invalid or missing parameters."); the service also models ConnectorServerException (httpError 400, doc "An error occurred when retrieving data from the connector endpoint.", single `message` member). The model does not state the wording, so recorded behavior only for the text: AWS does NOT treat an unassumable role as a request-parameter defect. It accepts the request as well-formed, runs the connector's test connection, and fails on the connector's answer — a 400 whose message is the connector-communication failure. Its FIXED text is "Error while communicating to connector: The test connection request failed due to: com.amazonaws.sandstoneconfigurationservicelambda.coral.model.ConnectorServerException: Failed to validate Connection while attempting \"select distinct(table_schema) from information_schema.tables limit 1\" with connector failure The request for the  Redshift failed with the status code 403: AccessDenied while trying to assume user-provided <roleArn> role by AppFlow service principal. (Service: null; Status Code: 400; Error Code: Client; Request ID: <id>; Proxy: null) (Service: Appflow, Status Code: 400, Request ID: <id>) (SDK Attempt Count: <n>)" — note the doubled space in "for the  Redshift" is part of AWS's fixed text. Its VARIABLE parts are ONLY: the role ARN taken verbatim from the request's connectorProfileProperties.Redshift.dataApiRoleArn, and the per-run request ids / attempt count (never part of the template). Because that failure is a connector-communication fault and not a parameter fault, the AWS::AppFlow::ConnectorProfile resource handler reports it with HandlerErrorCode `GeneralServiceException`, and the stack rolls back to the previous role.

Emulator: the request is refused by a pre-flight IAM check instead of a connector test. services/service-com-amazonaws-appflow-sandstoneconfigurationservicelambda/src/ops/update_connector_profile.rs calls `crate::state::unusable_connector_profile_role(... UPDATE_CONNECTOR_PROFILE_REQUEST ...)` and, on any reason, returns `ValidationException` (400) with message "Update Connector Profile request failed: [Amazon AppFlow is not authorized to assume the role [<roleArn>]. Update the trust policy of the role so that it can be assumed by the [appflow.amazonaws.com] service principal]". CloudFormation therefore records the resource failure as HandlerErrorCode `InvalidRequest` with that message. The rollback itself is correct (the stack reaches UPDATE_ROLLBACK_COMPLETE), so ONLY the error class and the message diverge: expected (message-as-above, "GeneralServiceException"), got ("Update Connector Profile request failed: [Amazon AppFlow is not authorized to assume the role [arn:aws:iam::<account>:role/<name>]. Update the trust policy of the role so that it can be assumed by the [appflow.amazonaws.com] service principal]", "InvalidRequest").

Why: a client that classifies CloudFormation resource failures by HandlerErrorCode sees a terminal request-validation fault (`InvalidRequest`) where AWS reports a retryable/service-side fault (`GeneralServiceException`) — retry and alarm policies keyed on that code take the wrong branch. A client reading the AppFlow error directly gets ValidationException where AWS sends the connector-communication 400, and the message does not name the connector test, the SQL probe, the 403/AccessDenied cause or the AppFlow service principal in AWS's wording, so any assertion or log-matching on AWS's connector-failure sentence fails even though the update was correctly refused.

Fix: the AppFlow UpdateConnectorProfile handler's role pre-flight branch (services/service-com-amazonaws-appflow-sandstoneconfigurationservicelambda/src/ops/update_connector_profile.rs, the `unusable_connector_profile_role` branch) together with the message builder behind `crate::state::unusable_connector_profile_role` / `UPDATE_CONNECTOR_PROFILE_REQUEST` in that crate's src/state.rs: an unassumable connector role must surface as the connector-test failure error (ConnectorServerException-class 400) with AWS's connector-communication message template, and the CloudFormation AWS::AppFlow::ConnectorProfile resource mapping must map that error class to HandlerErrorCode GeneralServiceException rather than InvalidRequest. Not covered by the open issues "AppFlow connector-profile not-found message text wrong on Delete and Update" (20261126T055149Z) or "AppFlow error message text diverges from AWS wording" (20261029T192701Z): both concern 404 not-found / @pattern wording, not this connector-test classification. Related open issue "AppFlow CreateConnectorProfile skips connector-property validation and persists invalid profile" (20261126T055149Z) concerns the create path's missing validation, not the update path's error class.

Traces: appflow__cloudformation.deploy-appflow-connector-profile-redshift-bad-data-api-role-update-rejected-and-rolled-back (the ConnectorProfile UPDATE_FAILED event's ResourceStatusReason and HandlerErrorCode).

1. Boot the emulator and replay the behavioral suite check appflow__cloudformation.deploy-appflow-connector-profile-redshift-bad-data-api-role-update-rejected-and-rolled-back.
2. CreateStack with a VPC + 3 subnets, an S3 bucket, an S3-access IAM role, a Data-API IAM role, a RedshiftServerless Namespace + Workgroup, and an AWS::AppFlow::ConnectorProfile (ConnectorType Redshift, ConnectionMode Public, Redshift properties referencing the bucket, the S3 role ARN, the Data-API role ARN, IsRedshiftServerless true). 5.
