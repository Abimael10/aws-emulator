# cloudformation: 3 net-new causes — AWS::CloudFormation::ChangeSet and ::GeneratedTemplate are unregistered resource types, and a Fn::ForEach without AWS::LanguageExtensions is refused with emulator-authored wording

> _Note: this issue was identified against the code base at commit `a0a325cd7a8f100e0b15b3c52772a25e70aa00e8`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
CreateStack

## Description
THREE net-new root causes of service `cloudformation`, grounded in the four failing checks in trace_ids. None of these checks is marked ALREADY FILED or OWNED in the replay report, and no open issue of this service carries them.

=== Cause 1 of 3: AWS::CloudFormation::ChangeSet is not a registered resource type, so CreateStack refuses every template that declares one ===
AWS: recorded behavior only (CloudFormation resource types are registry schemas, not Smithy shapes). A template whose resource is `Type: AWS::CloudFormation::ChangeSet` with Properties StackName / ChangeSetName / TemplateBody is accepted; the holder stack reaches CREATE_COMPLETE and its handler really calls CreateChangeSet against the named target stack, creating one un-executed change set. `Ref` on the resource is that change set's ChangeSetId; ListChangeSets(StackName=<target>) contains exactly that id under the declared ChangeSetName; DescribeChangeSet reports Status=CREATE_COMPLETE, ExecutionStatus=AVAILABLE, StackId=<target stack id> and Changes proposing exactly the resources the declared TemplateBody adds; GetTemplate(StackName=<target>, ChangeSetName=<id>, TemplateStage=Original) returns the declared body verbatim. Deleting the holder stack deletes the change set and leaves the target stack untouched (still CREATE_COMPLETE with only its own resources), after which DescribeChangeSet refuses with error code ChangeSetNotFound and message `ChangeSet [<change set id>] does not exist` (Smithy: DescribeChangeSet error ChangeSetNotFoundException, awsQueryError code ChangeSetNotFound, httpError 404). When the declared StackName names no stack, the holder stack ends ROLLBACK_COMPLETE and the resource's CREATE_FAILED reason is the handler-wrapped CreateChangeSet refusal: `Resource handler returned message: "Stack [<stack name>] does not exist (Service: CloudFormation; Operation: CreateChangeSet; Status Code: 400; Error Code: ValidationError; Request ID: <id>)" (RequestToken: <token>, HandlerErrorCode: InvalidRequest)` — fixed text, with the requested stack name taken from the template property and the request id/token from the call; DescribeChangeSet against that missing stack then refuses ValidationError `Stack [<stack name>] does not exist`.
Emulator: CreateStack refuses the template up front with HTTP 400 ValidationError and message `Template format error: Unrecognized resource types: [AWS::CloudFormation::ChangeSet]`, so neither the positive arm (a real change set) nor the rejection arm (the handler reason) is reachable at all.
Why: a caller that declares change sets from a template — the documented way to stage a review-only update of another stack — gets a template-format rejection instead of a stack, so no change set is ever staged, nothing can be reviewed or executed, and the handler failure wording a client keys on for a missing target stack never appears.
Fix: the CloudFormation resource-type registry and its stack-provisioning path — register AWS::CloudFormation::ChangeSet and have its handler create/delete a change set through the service's own CreateChangeSet/DeleteChangeSet path, surfacing CreateChangeSet refusals as the resource's handler reason.
Traces: cloudformation.cfn-changeset-resource-type-provisions-real-change-set, cloudformation.cfn-changeset-resource-type-against-nonexistent-stack-rejected.

=== Cause 2 of 3: AWS::CloudFormation::GeneratedTemplate is not a registered resource type, so no stack can drive the IaC generator ===
AWS: recorded behavior only. A template declaring `Type: AWS::CloudFormation::GeneratedTemplate` with GeneratedTemplateName and TemplateConfiguration ({DeletionPolicy: DELETE, UpdateReplacePolicy: DELETE}) is accepted; the stack reaches CREATE_COMPLETE and really runs the template generator. `Ref` on the resource is the GeneratedTemplateId and `Fn::GetAtt <logical id>.Status` is its status, and both match the ListGeneratedTemplates summary carrying that GeneratedTemplateName; DescribeGeneratedTemplate(GeneratedTemplateName=<name>) returns that same id and name with Status COMPLETE and echoes the declared TemplateConfiguration. Deleting the stack removes the generated template, after which DescribeGeneratedTemplate refuses with error code GeneratedTemplateNotFound and message `Template with arn <generated template arn> does not exist (Service: CfnTemplateGenerationServiceLambda; Status Code: 400; Error Code: GeneratedTemplateNotFoundException; Request ID: <id>; Proxy: null)` — fixed text with the arn of the deleted template and the per-call request id (Smithy: DescribeGeneratedTemplate error GeneratedTemplateNotFoundException, awsQueryError code GeneratedTemplateNotFound, httpError 404).
Emulator: CreateStack refuses the template with HTTP 400 ValidationError and message `Template format error: Unrecognized resource types: [AWS::CloudFormation::GeneratedTemplate]`; no stack, no generated template, none of the reads above reachable.
Why: the template-generation surface cannot be driven from a stack at all, so any workflow that provisions a generated template as part of an estate fails at CreateStack rather than producing a template to read back. Related OPEN issues describe the generated-template API surface itself and do NOT carry this check or this resource type: 20261029T171940Z-cloudformation-generated-template-reads-omit-modelled-members-and.md, 20261110T090000Z-cloudformation-generated-template-concurrency-limit-wording.md.
Fix: the CloudFormation resource-type registry and its stack-provisioning path — register AWS::CloudFormation::GeneratedTemplate and wire its handler to the service's CreateGeneratedTemplate/DeleteGeneratedTemplate state so Ref/GetAtt Status and the delete both follow it.
Traces: cloudformation.deploy-generated-template-reads-back-status-then-not-found-after-delete.

=== Cause 3 of 3: an Fn::ForEach in Resources with no `Transform: AWS::LanguageExtensions` is refused with the emulator's own 'unsupported function' sentence instead of AWS's malformed-resource-definition wording ===
AWS: recorded behavior only. CreateStack with `Resources: {"Fn::ForEach::<loop name>": [...]}` and no `Transform: AWS::LanguageExtensions` declared is refused before any stack exists with HTTP 400, error code ValidationError and message `Template format error: [/Resources/Fn::ForEach::<loop name>] resource definition is malformed` — the fixed text is `Template format error: [` + `] resource definition is malformed`, and the variable part is the JSON pointer of the offending Resources key taken from the submitted template (here /Resources/Fn::ForEach::Items). The identical loop WITH the transform declared is accepted and expands to one resource per collection item, so the refusal is specific to the missing transform.
Emulator: the call is refused with the same status and code but a different message — `Template Error: Encountered unsupported function: Fn::ForEach::Items Supported functions are: [Fn::GetStackOutput, Fn::AccountIdFromAlias, Fn::GetConstantAZs, Fn::Base64, Fn::GetAtt, Fn::GetAZs, Fn::ImportValue, Fn::Join, Fn::Split, Fn::FindInMap, Fn::Select, Ref, Fn::Equals, Fn::If, Fn::Not, Condition, Fn::And, Fn::Or, Fn::Contains, Fn::EachMemberEquals, Fn::EachMemberIn, Fn::ValueOf, Fn::ValueOfAll, Fn::RefAll, Fn::Sub, Fn::Cidr]` — emulator-authored prose that enumerates the emulator's intrinsic table instead of naming the malformed resource definition and its path.
Why: a client or CI gate that matches CloudFormation's `Template format error: [...] resource definition is malformed` text (or that points a user at the offending template path) sees neither the sentence nor the path, and the leaked list of supported functions is not AWS's answer for this class of template error.
Fix: the CloudFormation template-format validation in the template parser — when a Resources key is an Fn::ForEach loop and the AWS::LanguageExtensions transform is not declared, refuse with AWS's malformed-resource-definition message carrying that key's JSON pointer, rather than the generic unsupported-function path. Related OPEN issue that carries OTHER Fn::ForEach checks but not this one: 20261102T101202Z-cloudformation-9-net-new-root-causes-intrinsics-fn.md.
Traces: cloudformation.foreach-resources-without-language-extensions-transform-rejected.

## Steps to Reproduce
Cause 1 (AWS::CloudFormation::ChangeSet):
1. CreateStack a target stack with one AWS::CloudFormation::WaitConditionHandle; wait for CREATE_COMPLETE.
2. CreateStack a holder stack whose single resource is {"Type": "AWS::CloudFormation::ChangeSet", "Properties": {"StackName": <target name>, "ChangeSetName": <new name>, "TemplateBody": <the target template plus a second WaitConditionHandle>}} and whose Output is {"Ref": <that logical id>}. AWS accepts it and the stack reaches CREATE_COMPLETE; the emulator refuses the CreateStack call with ValidationError 'Template format error: Unrecognized resource types: [AWS::CloudFormation::ChangeSet]'.
3. On AWS: ListChangeSets(StackName=<target>) carries the Ref id, DescribeChangeSet reports CREATE_COMPLETE/AVAILABLE with one Add change, GetTemplate(TemplateStage='Original') returns the declared body; deleting the holder makes DescribeChangeSet refuse ('ChangeSetNotFound', 'ChangeSet [<id>] does not exist') and leaves the target intact.
4. Repeat step 2 with StackName naming a stack that does not exist: the holder ends ROLLBACK_COMPLETE and the resource's CREATE_FAILED reason is the handler-wrapped CreateChangeSet ValidationError with HandlerErrorCode InvalidRequest.
5. Re-replay cloudformation.cfn-changeset-resource-type-provisions-real-change-set and cloudformation.cfn-changeset-resource-type-against-nonexistent-stack-rejected.
