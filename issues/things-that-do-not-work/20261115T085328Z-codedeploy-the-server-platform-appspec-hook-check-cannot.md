## Description

Relation to what is already filed: open issues 20261114T164802Z-codedeploy-the-server-platform-ec2-agent-readiness-gate.md, 20261115T031454Z-codedeploy-the-server-platform-host-readiness-gate-still.md, 20261114T202732Z-codedeploy-the-alarm-gating-check-on-the-server.md, 20261114T130417Z-codedeploy-the-server-platform-ec2-agent-surface-is.md, 20261107T094623Z-codedeploy-no-server-platform-ec2-agent-deployment-check.md and 20261110T134745Z-codedeploy-the-minimumhealthyhosts-concurrency-check-cannot-start-the.md describe the same symptom family for OTHER checks, and none of them carries this check's id or replay key (their Issue-Trace-Ids lists do not contain codedeploy.ec2-agent-deployment-runs-appspec-hook-on-instance). It is filed here so a fixer has a re-replayable key for the one happy-path check that proves an AppSpec files-section install plus an AfterInstall hook actually runs on the host; a fix for the sibling issues is expected to close this one too, but nothing currently gates on it.

=== Cause 1 of 1: the Server-platform host-readiness gate never passes — an SSM Run Command on a running, Online managed node never reports the codedeploy-agent unit active, so codedeploy:CreateDeployment for computePlatform 'Server' is never issued and the AppSpec install/hook behaviour is never exercised ===
Failing check ids for this cause: codedeploy.ec2-agent-deployment-runs-appspec-hook-on-instance.

AWS: the check launches one AL2023 t3.micro whose user data installs the CodeDeploy agent, waits for ssm:DescribeInstanceInformation to report PingStatus 'Online', and then proves the host usable by running a shell command through Run Command — ssm:SendCommand(InstanceIds=[<id>], DocumentName='AWS-RunShellScript', Parameters={commands:['systemctl is-active codedeploy-agent']}) followed by ssm:GetCommandInvocation(CommandId, InstanceId). Smithy (ssm): GetCommandInvocation output member Status targets CommandInvocationStatus, an enum with values Pending, InProgress, Delayed, Success, Cancelled, TimedOut, Failed, Cancelling; Pending/InProgress/Delayed are the transient subset, and on a reachable node the invocation settles within seconds on Success (else Failed/TimedOut) with StandardOutputContent (@length 0..24000) carrying the command's stdout — 'active' for a running codedeploy-agent unit — and ResponseCode set. Only once the unit reads 'active' does the check call codedeploy:CreateDeployment with an S3 zip revision (revisionType S3, bundleType zip) against an IN_PLACE / WITHOUT_TRAFFIC_CONTROL group selected by ec2TagFilters, then read the host back through the same channel. Smithy (codedeploy, com.amazonaws.codedeploy#CodeDeploy_20141006) states what should then be observable: DeploymentStatus = Created|Queued|InProgress|Baking|Succeeded|Failed|Stopped|Ready; TargetStatus = Pending|InProgress|Succeeded|Failed|Skipped|Unknown|Ready; LifecycleEvent.status via LifecycleEventStatus = Pending|InProgress|Succeeded|Failed|Skipped|Unknown (the check requires Install and AfterInstall == 'Succeeded'); Diagnostics.errorCode via LifecycleErrorCode = Success|ScriptMissing|ScriptNotExecutable|ScriptTimedOut|ScriptFailed|UnknownError. Recorded behavior only for the on-host effects: the revision's files section copies payload.txt to /opt/sim2real and the AfterInstall hook (runas root) writes the run's token to /opt/sim2real/sentinel.
Emulator: the instance launches and is reported Online by ssm:DescribeInstanceInformation, SendCommand is accepted and returns a CommandId, but the readiness poll never observes 'systemctl is-active codedeploy-agent' returning 'active' — the invocation never yields that stdout — so _wait_agent_active loops until the runner's budget is exhausted and the check ends with 'TimeoutError: the CodeDeploy agent on <instance-id> active: the run budget ended first; not graded'. No codedeploy:CreateDeployment with computePlatform 'Server' is reached, so no deployment status, instance target, lifecycle event or on-host file is produced to compare. Hypothesis: the emulated Run Command execution plane records a sent invocation against a running node but never completes it to a terminal CommandInvocationStatus with output, so every in-guest readiness probe stalls; the Server-platform deployment driver behind it is consequently never reached.
Why: a client cannot use this emulator for any EC2/on-premises CodeDeploy workflow. The documented happy path — an AppSpec files section installing a revision's files on the host and an AfterInstall hook running as root, with the instance target reporting Install and AfterInstall 'Succeeded' — is unobservable. Worse than a refusal: the blocking symptom is a status that never advances rather than a modeled error, so a client's own wait loop hangs instead of failing fast.
Fix: two components, in order. First the SSM Run Command execution plane for an emulated managed node — the state behind SendCommand/GetCommandInvocation/ListCommandInvocations must advance an invocation sent to a running instance to a terminal CommandInvocationStatus and populate StandardOutputContent/StandardErrorContent/ResponseCode for AWS-RunShellScript. Then the CodeDeploy Server-platform deployment driver — the instance-target lifecycle execution path behind CreateDeployment/GetDeployment/GetDeploymentTarget/ListDeploymentTargets — which must unpack an S3 zip revision onto the selected host, run its AppSpec hooks, and record per-event LifecycleEvent.status values.
Traces: codedeploy.ec2-agent-deployment-runs-appspec-hook-on-instance — cut off in the host-readiness setup before any CreateDeployment.

## Evidence
Expected (AWS): after the launched host reports PingStatus 'Online', ssm:SendCommand(DocumentName='AWS-RunShellScript', Parameters={commands:['systemctl is-active codedeploy-agent']}) + ssm:GetCommandInvocation(CommandId, InstanceId) settles within seconds on a terminal CommandInvocationStatus (Success for a reachable node, else Failed/TimedOut) with StandardOutputContent == 'active'. A Server-platform codedeploy:CreateDeployment with an S3 zip revision then advances deploymentInfo.status to 'Succeeded'; ListDeploymentTargets/GetDeploymentTarget report the instance target with status 'Succeeded' and lifecycleEvents containing Install == 'Succeeded' and AfterInstall == 'Succeeded'; on the host, /opt/sim2real/payload.txt holds the revision payload and the AfterInstall hook's sentinel file holds the token the run generated.

Actual (emulator): the readiness probe never returns 'active'. The check errors verbatim:
  File "check_codedeploy_ec2_agent_deployment_runs_appspec_hook_on_instance.py", line 75, in run
    active = _wait_agent_active(ctx, ssm, instance_id)
  File "check_codedeploy_ec2_agent_deployment_runs_appspec_hook_on_instance.py", line 603, in _wait_agent_active
    raise TimeoutError(f"the CodeDeploy agent on {instance_id!r} active: the run budget ended first; not graded")
  TimeoutError: the CodeDeploy agent on 'i-00000000000000001' active: the run budget ended first; not graded
No CreateDeployment for computePlatform 'Server' is issued in this replay, so no deployment status, target status, lifecycle event or installed file exists to compare.

Per-run values that are NOT part of the requirement: the instance id ('i-00000000000000001'), the generated application/deployment-group/bucket names, the revision ETag, the deployment id, the command id, the generated sentinel token, and the runner's time budget. The requirement is only that a Run Command sent to a running managed node reaches a terminal CommandInvocationStatus with its stdout, and that a Server-platform deployment then installs the revision and runs its AppSpec hooks with Install/AfterInstall reported 'Succeeded'.

## Steps to Reproduce
1. Create a VPC with a public subnet, a security group, and an instance profile granting AmazonSSMManagedInstanceCore plus read on the revision bucket; read the AL2023 AMI id from the public SSM parameter /aws/service/ami-amazon-linux-latest/al2023-ami-kernel-default-x86_64.
2. s3:PutObject a zip revision containing appspec.yml (version 0.0, os linux, files: payload.txt -> /opt/sim2real, hooks: AfterInstall -> after_install.sh runas root), payload.txt, and after_install.sh writing a token to /opt/sim2real/sentinel; s3:HeadObject for its ETag.
3. ec2:RunInstances one t3.micro with that profile and subnet, tagged with the key the deployment group will filter on, and user data installing the CodeDeploy agent and enabling the codedeploy-agent unit.
4. Poll ssm:DescribeInstanceInformation(Filters=[{Key:'InstanceIds',Values:[<id>]}]) until PingStatus == 'Online' (this step succeeds today).
5. ssm:SendCommand(InstanceIds=[<id>], DocumentName='AWS-RunShellScript', Parameters={commands:['systemctl is-active codedeploy-agent']}), then poll ssm:GetCommandInvocation(CommandId=<returned id>, InstanceId=<id>). Observe that 'active' is never returned, so the readiness gate never passes.
6. Because of step 5, codedeploy:CreateApplication(computePlatform='Server') + CreateDeploymentGroup(ec2TagFilters=[...], deploymentStyle={deploymentType:'IN_PLACE',deploymentOption:'WITHOUT_TRAFFIC_CONTROL'}, deploymentConfigName='CodeDeployDefault.AllAtOnce') + CreateDeployment with the S3 zip revision is never issued; the AppSpec files install, the AfterInstall hook execution, and the instance target's Install/AfterInstall lifecycle events cannot be observed.
