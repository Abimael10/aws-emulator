# cloudformation__redshift: an AWS::Redshift::EventSubscription with a SourceType outside the resource's enum rolls the stack back but emits no VALIDATION_ERROR OperationEvent, so DescribeEvents never reports the property-validation failure or its path

> _Note: this issue was identified against the code base at commit `616e510b6c9fc5a742ae081415d2f4cf49efcb62`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
DescribeEvents

## Description
One net-new root cause, grounded in a failing behavioral check the suite marked neither "ALREADY FILED" nor "OWNED by".

=== Cause 1 of 1: the property-validation failure that rolled the stack back is not reported as a VALIDATION_ERROR OperationEvent ===
Failing check: cloudformation__redshift__sns.cfn-redshift-eventsubscription-invalid-source-type-rejected
AWS: when a template declares an AWS::Redshift::EventSubscription whose SourceType is outside the resource schema's enum, CloudFormation fails the resource in early PROPERTY_VALIDATION and the create ends ROLLBACK_COMPLETE, AND it records that failure as an operation event readable through DescribeEvents: an OperationEvent with EventType=VALIDATION_ERROR (Smithy: EventType enum includes VALIDATION_ERROR; OperationEvent carries ValidationName, ValidationStatus, ValidationFailureMode, ValidationStatusReason, ValidationPath; ValidationStatus enum = FAILED|SKIPPED; DescribeEvents output member OperationEvents, paginated by NextToken), whose fields for this class of failure are LogicalResourceId = the offending resource's logical id, ValidationName = `PROPERTY_VALIDATION`, ValidationStatus = `FAILED`, ValidationFailureMode = `FAIL`, ValidationPath = the JSON pointer of the offending property (`/Resources/<LogicalId>/Properties/<PropertyName>`), and ValidationStatusReason = `<given value> is not a valid enum value. Supported values: [<the schema's enum, comma-separated>]`. Fixed text of the reason: ` is not a valid enum value. Supported values: [` and `]`; variable parts: the rejected value copied from the template and the resource schema's own enum list — for AWS::Redshift::EventSubscription.SourceType that list is `cluster, cluster-parameter-group, cluster-security-group, cluster-snapshot, scheduled-action`. The rolled-back subscription must also not exist in Redshift (DescribeEventSubscriptions by that SubscriptionName refused SubscriptionNotFound / `Event Subscription <name> not found`), and the same template with SourceType `cluster` must deploy CREATE_COMPLETE and read back with SourceType `cluster` and EventCategoriesList ['monitoring'].
Emulator: the stack status is right — the create ends ROLLBACK_COMPLETE, so the invalid enum value IS rejected — but DescribeEvents(StackName=<stack id>) returns NO event with EventType=VALIDATION_ERROR at all (the check collected an empty list across every page), so the ValidationName/ValidationStatus/ValidationFailureMode/ValidationStatusReason/ValidationPath fields are never populated for the failure that caused the rollback.
Why: the VALIDATION_ERROR operation event is the machine-readable explanation of WHY a deploy rolled back. A CI pipeline, a deploy wrapper or a console-like client that reads DescribeEvents to tell an operator which property of which resource was rejected, and what the allowed values are, gets a bare ROLLBACK_COMPLETE with nothing to attribute it to; it cannot distinguish an early property-validation refusal from a provisioning failure, and the JSON pointer it would use to point a user at the offending template line never exists.
Fix: CloudFormation's template/property-validation stage and the operation-event recorder behind DescribeEvents — when a resource's properties fail schema validation, emit an OperationEvent of EventType VALIDATION_ERROR for that logical resource carrying ValidationName PROPERTY_VALIDATION, ValidationStatus FAILED, ValidationFailureMode FAIL, the `/Resources/<LogicalId>/Properties/<Property>` ValidationPath and the enum-rejection reason sentence built from the rejected value and the resource schema's enum, and serve it from DescribeEvents(StackName=...) (paginated).
