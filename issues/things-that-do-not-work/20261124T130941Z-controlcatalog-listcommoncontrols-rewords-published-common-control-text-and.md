# controlcatalog: ListCommonControls rewords published common-control text and ListDomains omits published domains (4 causes)

> _Note: this issue was identified against the code base at commit `3cf14233d7b3c1398fbfecd8519fd2fa7d531f41`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
ListCommonControls

## Description
The common-control and domain halves of the ControlCatalog read surface answer HTTP 200 from an emulator-authored catalog rather than from AWS's published one. Two faults recur: the @required Name/Description strings of published rows are replaced by shorter re-written prose (often describing a different concept under the same ARN), and the domain listing serves a different ARN set from the published one — published domain ARNs are absent while ARNs of a 25-hex-character form the catalog never publishes appear in their place. FOUR net-new causes, all on service `controlcatalog`.

These clusters are reported un-owned by the replay. Related OPEN issues that do NOT cover them (different ARNs/steps, and none carries these replay keys): 20261123T051108Z-controlcatalog-serves-a-synthesized-control-catalog-getcontrol-404s.md (GetControl 404s plus ListCommonControls task#16/task#37), 20261116T095506Z-controlcatalog-common-control-and-domain-catalog-text-is.md, 20261030T021409Z-controlcatalog-listcommoncontrols-returns-an-empty-commoncontrols-list-for-every--r2.md.

Emulator: answers 200 with, for 2o50zyyv219ir9r7brjq0y37f, "Establish procedures for rolling a failed change back, keep backups of what a change alters, and restore the affected systems and data from them." — the periodic-testing and recovery-procedure requirements are dropped. Why: a client resolving a common-control ARN to its published name and description — framework mapping, coverage reporting, console rendering — displays and attests to a different control than the ARN identifies, and the requirements the published text states are silently absent from its compliance narrative.
Fix: the common-control rows in the control-catalog state that ListCommonControls' response projection reads; the published Name/Description must be stored verbatim keyed by the published ARN.

Hypothesis: domain rows are minted locally with generated identifiers instead of being seeded from the published catalog, which is why the published ARNs are missing and unpublished ones appear. Fix: the domain rows in the control-catalog state read by ListDomains' response projection — the published domain ARNs, names and descriptions must be seeded verbatim and no locally generated domain identifier emitted.
