# dynamodb, ebs, ecr, eks, elasticache, elasticfilesystem and elasticloadbalancing default quota rows misbound

> _Note: this issue was identified against the code base at commit `701b7d43696bfd8d52286723c43a23a76a522357`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
ListAWSDefaultServiceQuotas

## Description
SHARED FAULT (7 causes, one per ServiceCode). ListAWSDefaultServiceQuotas returns HTTP 200 with a well-formed ListAWSDefaultServiceQuotasResponse for each of these ServiceCode values, so there is no status or error divergence in any cause — the defect is entirely in the Quotas list the emulator's built-in default-quota catalog serves. For each of the seven service codes below the catalog (a) binds a row's QuotaName/Description/Value/Unit/UsageMetric/Period to the WRONG QuotaCode, i.e. a quota's metadata is published under another quota's code, (b) re-words or truncates the published Description/QuotaName, (c) mis-flags Adjustable, and/or (d) omits quota rows AWS returns for that code. The per-row contract is ServiceQuota (Smithy: ServiceQuota members QuotaCode @pattern ^[a-zA-Z][a-zA-Z0-9-]{1,128}$, QuotaName, Description @length max 350, Value QuotaValue @range 0..10000000000, Unit, Adjustable @default false, GlobalQuota @default false, UsageMetric->MetricInfo{MetricNamespace,MetricName,MetricDimensions,MetricStatisticRecommendation}, Period->QuotaPeriod{PeriodValue,PeriodUnit}); the model carries no value table, so the required content of each row is recorded behavior only, taken from the recorded AWS response for the same ServiceCode. The general requirement: for a given ServiceCode, each QuotaCode AWS publishes must appear exactly once and carry AWS's own QuotaName, Description, Value, Unit, Adjustable, GlobalQuota, Period and UsageMetric for THAT code — the QuotaCode is the stable identifier clients key on, so the pairing, not any one recorded number, is the contract. Fixture values quoted below are examples of the misbinding, not the requirement.

Cause 1 of 7: ServiceCode `dynamodb`. AWS (recorded behavior only): 25 fields across 13 QuotaCodes, e.g. L-F7858A77 is 'Global Secondary Indexes per table', Value 20, described as the maximum number of global secondary indexes per table; L-F3CA5463 QuotaName is 'Provisioned capacity decreases per day'; L-34F8CCC8 and L-923BEB7A carry AWS's provisioned-write-capacity wording. Emulator: L-F7858A77 is served as 'Concurrent export jobs' with Value 300 and the export-job description (another quota's row under this code); L-F3CA5463 is re-worded to 'Maximum number of decreases per day'; L-34F8CCC8's Description is paraphrased; L-923BEB7A carries the on-demand read-request-units row. Why: a client that reads the GSI-per-table or capacity-decrease default from the catalog gets a different quota's name and limit under the code it asked about, so limit-aware logic and quota-increase requests target the wrong quota. Fix: the service-quotas default-quota catalog data for ServiceCode dynamodb (the static table the ListAWSDefaultServiceQuotas handler reads), re-pairing each row to its own QuotaCode and restoring AWS's QuotaName/Description/Value. Traces: service-quotas-catalog-list-aws-default-service-quotas-dynamodb#task#1.

Cause 2 of 7: ServiceCode `ebs`. AWS (recorded behavior only): ~100 fields across ~45 QuotaCodes, and rows L-C125AE42 and L-DB2FBAA1 exist; e.g. L-E137849C is 'Time-based snapshot copy throughput per destination Region' Value 2000; L-98A0B26D is 'IOPS modifications for Provisioned IOPS SSD (io1) volumes' Value 500000; L-9A0E0F82 is 'Storage modifications for Provisioned IOPS SSD (io2) volumes, in TiB'; L-09BD8365 is the provisioned-storage-for-io2 row. Why: EBS capacity and request-rate defaults are swapped, so a client reading a storage/IOPS limit gets a per-second API rate (and two codes it expects are missing, which reads as 'quota does not exist'). Fix: the service-quotas default-quota catalog data for ServiceCode ebs — restore the two dropped rows and re-pair the API-rate rows to their own QuotaCodes.
