# Glue CreateScript generates script text AWS does not: skeleton preamble, transformation_ctx and @inputs frames

> _Note: this issue was identified against the code base at commit `704c48b6f7bf8dd638f70ff69c421beba4994c4a`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
CreateScript

## Description
Two net-new wire-replay root causes in Glue's CreateScript code generator. Both answer HTTP 200 with the right output member, but the GENERATED SCRIPT TEXT is not the script AWS writes for the same graph: one cause is the Python script, the other the Scala code, and they are two separate generators/skeleton constants, so a fixer must close BOTH before submitting. Each has its own fixture#step below.

Cause 1 of 2: the PythonScript CreateScript generates for a graph differs from AWS's in three places at once (one cluster, 5 steps). AWS: Smithy (services/service-com-amazonaws-glue-awsglue/smithy-model/com-amazonaws-glue-awsglue.json) models CreateScript with input DagNodes (CodeGenNode: required Id matching ^[A-Za-z_][A-Za-z0-9_]*$, required NodeType, required Args of CodeGenNodeArg{Name,Value,Param}), DagEdges (CodeGenEdge: required Source, required Target, optional TargetParameter) and Language, and output members PythonScript/ScalaCode, both plain strings — the TEXT itself is not modeled, so this is recorded behavior only. The recording shows AWS's generated Python as: (a) a job skeleton in which the codegen comment line '## @params: [JOB_NAME]' stands between the awsglue imports and the "args = getResolvedOptions(sys.argv, ['JOB_NAME'])" line; (b) every node's '## @args: [...]' annotation and its generated call carrying a transformation context the GRAPH DOES NOT CARRY — 'transformation_ctx = "<the node's Id>"', double-quoted, where the node's own properties keep the quoting the request sent them with (Hypothesis: AWS synthesizes a transformation_ctx per node from the node Id when the node's Args name none, which is why its quoting differs from the request-supplied properties); (c) a frame an edge names with NO TargetParameter rendered as the NAMED parameter 'frame' both in the annotation ('## @inputs: [frame = <source Id>]') and in the call ('glueContext.write_dynamic_frame.from_catalog(frame = <source Id>, ...)'). Emulator: the same request answers 200 with a PythonScript that omits the '## @params: [JOB_NAME]' line entirely, emits only the properties the request's Args carried (no transformation_ctx anywhere), and passes a parameterless edge's frame BARE — '## @inputs: [<source Id>]' and 'from_catalog(<source Id>, ...)' positionally. Why: a client asking Glue to generate a script writes that text into a job (the same corpus does exactly that in glue-job-lifecycle-with-script) and then diffs or re-reads it; a script without a transformation_ctx per node loses Glue's job-bookmark context, the bare positional frame is not the call Glue's own codegen emits, and the missing '## @params' line shifts every node's line number by one relative to AWS, so a client that reads the script back (GetDataflowGraph) or compares generated code against AWS's never agrees with the service. Fix: CreateScript's script generator and the skeleton it shares with GetPlan — the Python preamble constant and script_frame (services/service-com-amazonaws-glue-awsglue/src/ops/get_plan.rs:721-797, PYTHON_PREAMBLE has no '## @params: [JOB_NAME]' line), and the annotation/argument builders annotated_args, annotated_inputs and python_frames in services/service-com-amazonaws-glue-awsglue/src/ops/create_script.rs:337-355 and 455-467, which neither synthesize a transformation_ctx for a node whose Args omit it nor default a parameterless edge to the 'frame' parameter. Traces: glue-create-script-etl-dag#task#1; same cluster: glue-create-script-from-dag#task#1, glue-create-script-from-dag#task#2, glue-create-script-multi-language#task#1, glue-job-lifecycle-with-script#task#2.

Cause 2 of 2: the ScalaCode CreateScript generates opens with the wrong import set (one cluster, 2 steps). AWS: recorded behavior only (ScalaCode is an unconstrained string in the model). The recording shows AWS's Scala preamble importing, in order, com.amazonaws.services.glue.GlueContext, com.amazonaws.services.glue.errors.CallSite, com.amazonaws.services.glue.util.GlueArgParser, com.amazonaws.services.glue.util.Job, com.amazonaws.services.glue.util.JsonOptions, org.apache.spark.SparkContext and scala.collection.JavaConverters._, and then the GlueApp object/main skeleton; the same recording's node text carries the synthesized context of cause 1 in Scala spelling ('// @args: [... transformation_ctx = "<Id>"]', 'transformationContext = "<Id>"' inside getCatalogSource/getCatalogSink, and '// @inputs: [frame = <source Id>]'). Emulator: the generated Scala preamble imports com.amazonaws.services.glue.ChoiceOption and does NOT import com.amazonaws.services.glue.errors.CallSite (services/service-com-amazonaws-glue-awsglue/src/ops/get_plan.rs:742-758, SCALA_PREAMBLE), and because the Scala path shares the annotation/argument builders of cause 1 it carries the same missing transformation context and bare @inputs (the replay detail is truncated past the import block, so the import divergence is the part the output states outright). Why: generated Scala is compiled as-is by the client; an import the service emits is part of the artifact a caller checks into a build, and a caller comparing the emulator's generated code with AWS's sees a different file for the same graph. Fix: the Scala skeleton constant SCALA_PREAMBLE in services/service-com-amazonaws-glue-awsglue/src/ops/get_plan.rs:742-758 must carry AWS's import set, and the shared builders named in cause 1 fix the Scala node text with the Python one. Traces: glue-create-script-etl-dag#task#2; same cluster: glue-create-script-multi-language#task#2.

Related open issues, named for the fixer — neither carries these fixture#step replay keys, so neither covers these steps (the replay reports both clusters as unowned): 20261117T133709Z-glue-read-paths-omit-or-misreport-members-aws.md owns glue-get-plan-script-generation#task#3 (GetPlan's PythonScript) and glue-get-dataflow-graph#task#1 (DagNodes LineNumber), both of which are downstream of the SAME shared skeleton, so repairing the preamble is expected to move them too; CreateScript's own steps are filed here.
