# cloudfront__pricing-plan-manager__wafv2: 2 net-new root causes in DisassociateResourcesFromSubscription — a resource the subscription does not cover is refused instead of being a no-op, and the plan-composition refusal uses the wrong message

> _Note: this issue was identified against the code base at commit `c676fa8352d872372c6182d9b8e82740bdddb0ee`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
DisassociateResourcesFromSubscription

## Description
Two independent root causes in pricing-plan-manager's DisassociateResourcesFromSubscription, both decided by crate::state::subscription_resources::plan_resource_removal and its refusal mapping. Neither is covered by the open issues on this surface (20261111T004423Z-cloudfront-pricing-plan-manager-wafv2-4-net-new.md, 20261114T092337Z-cloudfront-pricing-plan-manager-wafv2-the-createsubscription-eligibility.md, 20261115T024858Z-cloudfront-pricing-plan-manager-wafv2-cancelsubscription-with-the.md, 20261109T121305Z-pricing-plan-manager-2-net-new-root-causes.md): those describe CreateSubscription/CancelSubscription/UpdateDistribution gates, none of them this operation's removal rule.

Cause 1 of 2: DisassociateResourcesFromSubscription naming a resource the subscription does not cover is refused with ValidationException instead of being answered as an inert no-op.
AWS: Smithy (services/service-com-amazonaws-pricingplanmanager-awspricingplanmanager/smithy-model/com-amazonaws-pricingplanmanager-awspricingplanmanager.json): DisassociateResourcesFromSubscription takes arn (@required SubscriptionArn), ifMatch (@required, the ETag from a previous read), resourceArns (@required ResourceArns, @length 1..10 — "The ARNs of the resources to remove from the subscription. For subscriptions in the CloudFront plan family, you cannot remove the required CloudFront distribution or WAF web ACL."), and returns @required subscription + @required eTag; its modeled errors are AccessDeniedException 403, ConflictException 409, InternalServerException 500, ResourceNotFoundException 404, ThrottlingException 429, ValidationException 400. The model says NOTHING about a resource the subscription does not cover, so this is recorded behavior only: the recording shows the call SUCCEEDS with HTTP 200 and is a complete no-op — the response's subscription.resourceArns is exactly the stored set (the CloudFront distribution and the WAF web ACL), a following GetSubscription reports the same set, status stays "ACTIVE" (it does NOT move to SYNC_IN_PROGRESS, because nothing is being applied), and the eTag read back is IDENTICAL to the one the caller passed as ifMatch (no revision/updatedAt bump, since no write happened). Removing a name the subscription never held leaves the record byte-for-byte unchanged.
Emulator: the same call is refused HTTP 400, Error.Code "ValidationException", Error.Message "Cannot remove <resource-arn> from subscription <subscription-arn>: the resource is not associated with this subscription." (fixed text "Cannot remove " / " from subscription " / ": the resource is not associated with this subscription.", with the two ARNs taken from the request), resourceId = the named resource. The refusal comes from state/subscription_resources.rs plan_resource_removal, which rejects with ResourceChangeRefusal::NotAssociated for any requested ARN not in record.resource_arns, mapped to ValidationException in ResourceChangeRefusal::into_modelled; the handler ops/disassociate_resources_from_subscription.rs turns that into the 400.
Why: a client's cleanup/reconciliation path is normally written to be idempotent — it disassociates a resource it believes may still be attached and relies on AWS answering 200 with the current set. Against the emulator that same call raises ValidationException, so a convergence loop or teardown aborts on a resource that is ALREADY in the desired state, and a client cannot distinguish "nothing to do" from a real input error. Note that merely admitting the call is not enough: the success path must not record a write either — the handler currently calls record.begin_sync(now) on every accepted removal, which would move status to SYNC_IN_PROGRESS and advance the eTag, and AWS leaves both untouched for a no-op.
Fix: the removal rule in services/service-com-amazonaws-pricingplanmanager-awspricingplanmanager/src/state/subscription_resources.rs (plan_resource_removal's NotAssociated arm and the ResourceChangeRefusal::NotAssociated variant) plus the success path of the handler services/service-com-amazonaws-pricingplanmanager-awspricingplanmanager/src/ops/disassociate_resources_from_subscription.rs: ARNs the subscription does not cover must be ignored rather than refused, and a request that removes nothing at all must return the stored subscription unchanged with the same eTag, status and updatedAt (no touch/begin_sync).
Traces: cloudfront__pricing-plan-manager__wafv2.disassociate-unassociated-resource-leaves-subscription-unchanged.

Cause 2 of 2: when a removal would strip a resource the plan requires, the ValidationException message states the CloudFront plan-family composition rule and lists the offending ARNs instead of AWS's plan-tier-incompatibility sentence.
AWS: Smithy: the operation documents the rule itself ("For subscriptions in the CloudFront plan family, the associated resources must always include exactly one Amazon CloudFront distribution and exactly one WAF web ACL. You cannot remove these required resources.") and models ValidationException (HTTP 400, "The request failed a business rule validation"). The model does not state the message text, so the wording is recorded behavior only: removing the subscribed WAF web ACL from an ACTIVE CloudFront/FREE subscription is refused HTTP 400, Error.Code "ValidationException", Error.Message "Resources are incompatible with plan tier 'FREE': modify resources or select a different tier." Fixed text: "Resources are incompatible with plan tier '" and "': modify resources or select a different tier."; the only variable part is the plan tier, read from the stored subscription's planTier ("FREE" in the recording — a value from state, not part of the template). The refusal is inert: a following GetSubscription still lists both the distribution and the web ACL.
Emulator: the same call is refused with the right code and status but the message "For subscriptions in the CloudFront plan family, the associated resources must always include exactly one Amazon CloudFront distribution and exactly one WAF web ACL. You cannot remove these required resources: <web-acl-arn>." — the model's documentation sentence plus the requested ARNs, produced by required_resources_message in services/service-com-amazonaws-pricingplanmanager-awspricingplanmanager/src/state/subscription_resources.rs and used by the ResourceChangeRefusal::Required arm of into_modelled.
Why: the error message is part of the contract a client matches on and logs. A client (or a test suite) that keys on AWS's plan-tier sentence sees an unrecognised message, and the emulator additionally attributes the refusal to a plan-FAMILY composition rule rather than to the tier's resource compatibility, so operator-facing diagnostics point at the wrong remedy (change the resource set vs. select a different tier).
Fix: the refusal message for a removal the plan does not admit — required_resources_message / ResourceChangeRefusal::Required in services/service-com-amazonaws-pricingplanmanager-awspricingplanmanager/src/state/subscription_resources.rs, as rendered by ops/disassociate_resources_from_subscription.rs — must produce AWS's sentence with the subscription's own planTier interpolated, keeping ValidationException/400 and leaving the stored resource set untouched.
Traces: cloudfront__pricing-plan-manager__wafv2.subscription-resource-association-reaches-active.
