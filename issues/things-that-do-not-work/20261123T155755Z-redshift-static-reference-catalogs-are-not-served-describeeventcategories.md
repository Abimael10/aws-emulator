# Redshift static reference catalogs are not served: DescribeEventCategories returns an empty list and DescribeReservedNodeOfferings synthesizes offerings

> _Note: this issue was identified against the code base at commit `0826656a275733cd2bc4d28ee672375812eb9b87`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
DescribeEventCategories

## Description
Two net-new causes, both in the same place: the read-only, account-independent reference catalogs Redshift serves from service-side static data are either absent or synthesized at random in the emulator, so catalog reads answer 200 with content that does not describe Redshift.

Cause 1 of 2: DescribeEventCategories answers 200 with an empty EventCategoriesMapList.
AWS: Smithy: DescribeEventCategories (input DescribeEventCategoriesMessage.SourceType, optional; output EventCategoriesMessage.EventCategoriesMapList : EventCategoriesMapList, no modeled errors). The model declares the list but not its contents, so for the catalog itself this is recorded behavior only: a DescribeEventCategories with no SourceType filter returns one EventCategoriesMap per event source type (the recording carries six, led by SourceType 'cluster'), and each map carries Events.EventInfoMap entries, each with EventId (e.g. 'REDSHIFT-EVENT-2000', 'REDSHIFT-EVENT-3015', 'REDSHIFT-EVENT-4502'), a Severity ('INFO' or 'ERROR'), an EventCategories.EventCategory ('management', 'monitoring', 'pending', 'security'), and an EventDescription that is Redshift's fixed template text with angle-bracket placeholders left unsubstituted, e.g. 'Cluster <cluster name> created at <time in UTC>.' The fixed text and the placeholder tokens are the requirement; no value in these entries comes from the request or from account state, because the catalog is static. When SourceType is supplied, only that source type's map is returned.
Emulator: every expected element is absent — the replay reports $.DescribeEventCategoriesResponse.DescribeEventCategoriesResult.EventCategoriesMapList.EventCategoriesMap[0] through [5] as 'missing', i.e. status 200 with no EventCategoriesMap members at all.
Why: a client that enumerates event categories to build the Event Categories / Severities it may pass to CreateEventSubscription or DescribeEvents gets an empty universe, so it either offers the user nothing to subscribe to or concludes that no category such as 'management' exists and refuses a subscription request that AWS would accept. Console-style and infrastructure tooling that validates a requested category against this catalog before calling CreateEventSubscription fails closed.
Fix: the DescribeEventCategories handler and the static reference data it reads — the catalog must be a checked-in table of source types and their event-info entries (EventId, Severity, EventCategory, template EventDescription), with the SourceType input filtering it; it is not derivable from cluster state.
Traces: redshift-catalog-describe-event-categories#task#1.

Cause 2 of 2: DescribeReservedNodeOfferings answers 200 with randomly generated offerings instead of Redshift's offerings catalog.
AWS: Smithy: DescribeReservedNodeOfferings (input ReservedNodeOfferingId / MaxRecords / Marker; output ReservedNodeOfferings : ReservedNodeOfferingList plus Marker; paginated inputToken=Marker outputToken=Marker items=ReservedNodeOfferings pageSize=MaxRecords; errors ReservedNodeOfferingNotFound 404, DependentServiceUnavailableFault 400, UnsupportedOperation 400). The offering contents are recorded behavior only: AWS returns a fixed per-region catalog spanning several node types and both term lengths, in which each offering's fields are mutually consistent — a 3-year term is Duration '94608000' and a 1-year term is '31536000'; OfferingType 'All Upfront' carries a non-zero FixedPrice with a RecurringCharges.RecurringCharge of RecurringChargeAmount '0.0' at RecurringChargeFrequency 'Hourly'; 'No Upfront' carries FixedPrice '0.0' with a non-zero hourly RecurringChargeAmount; 'Partial Upfront' carries both non-zero; CurrencyCode is 'USD', UsagePrice '0.0' and ReservedNodeOfferingType 'Regular'. The recording's catalog includes node types the emulator never offers (e.g. 'rg.large', 'rg.xlarge') alongside 'dc2.large'. The individual price numbers and offering ids of any one recording are that region's catalog values, not a template to copy literally; what is required is that a stable catalog covering the region's node types and both durations is served, that a ReservedNodeOfferingId returned here is the same id on a later call, and that it resolves in DescribeReservedNodeOfferings(ReservedNodeOfferingId=...) and PurchaseReservedNodeOffering rather than 404 ReservedNodeOfferingNotFound.
Emulator: every expected offering is reported 'missing' and replaced by a differently-shaped generated one. At index 0 the recording expects NodeType 'rg.large', Duration '94608000', OfferingType 'All Upfront', FixedPrice '3743.6' with hourly RecurringChargeAmount '0.0'; the emulator returned NodeType 'dc2.large', Duration '31536000', OfferingType 'No Upfront', FixedPrice '0.0' with RecurringChargeAmount '0.175', under a freshly generated ReservedNodeOfferingId ('0d99b00e-0f97-9735-3b0d-57239e32baa9' on that run). All 60 returned elements ([0]..[59]) diverge the same way: a single node type, a single duration, and per-run random ids.
Why: a client cannot shop for a reservation. Filtering for a 3-year term or for a node type other than dc2.large yields nothing, so capacity-planning and cost tooling reports that no offering exists; and because the ids are generated per run rather than catalog-stable, an id captured from one DescribeReservedNodeOfferings cannot be fed to PurchaseReservedNodeOffering or re-queried by ReservedNodeOfferingId, which is the whole purchase workflow.
Fix: the DescribeReservedNodeOfferings handler and its backing reference data — serve a fixed, checked-in offerings catalog (stable ReservedNodeOfferingIds, one entry per node type x duration x offering type with internally consistent FixedPrice/RecurringCharges/UsagePrice/CurrencyCode), keyed so ReservedNodeOfferingId lookups and PurchaseReservedNodeOffering resolve against it, with Marker/MaxRecords paginating that catalog instead of generating rows.
Traces: redshift-catalog-describe-reserved-node-offerings#task#1.

Neither cause is covered by an open issue. The nearest open redshift issues are 20261122T081123Z-redshift-reports-generated-values-instead-of-the-request.md (generated Endpoint.Port / SnapshotCopyGrant KmsKeyId in place of request-supplied values) and 20261114T091053Z-redshift-not-found-refusals-carry-emulator-authored-messages.md (not-found message wording); both are about per-resource responses, not about the absent static catalogs here, and neither carries these replay keys.
