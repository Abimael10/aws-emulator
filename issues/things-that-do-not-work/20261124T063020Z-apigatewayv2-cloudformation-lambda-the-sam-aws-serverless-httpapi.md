# apigatewayv2__cloudformation__lambda: the SAM AWS::Serverless::HttpApi deploy-and-serve scenario reaches no verdict — the run produces no status, error or answer inside the budget (1 cause)

> _Note: this issue was identified against the code base at commit `c1cdd983ca2491984ece40896171481518806128`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
CreateStack

## Description
One net-new root cause on the CloudFormation/SAM path that provisions an HTTP API from AWS::Serverless::HttpApi. It must be closed before submitting.

Cause 1 of 1: a SAM template whose Transform is AWS::Serverless-2016-10-31 and which declares an AWS::Serverless::HttpApi plus an AWS::Serverless::Function with an HttpApi event (and Globals.Function / Globals.HttpApi) produces no terminal answer at all: the replay is killed at the harness budget with no status, no error code and no message. The first blocking wait is the stack's terminal status (the check polls DescribeStacks until a status that does not end in _IN_PROGRESS, with its own 600 s deadline), so the stack does not settle; nothing downstream — the function's configuration, the stack Outputs, or the endpoint — is observable. Failing check: apigatewayv2__cloudformation__lambda.sam-httpapi-event-serves-payload-v2-route.
AWS: recorded behavior only for the data plane; the control plane is modelled. Smithy (services/service-com-amazonaws-apigatewayv2-apigatewayv2/smithy-model/com-amazonaws-apigatewayv2-apigatewayv2.json): CreateApi member CorsConfiguration : Cors — AllowOrigins/AllowMethods/AllowHeaders/ExposeHeaders/AllowCredentials/MaxAge @range -1..86400, 'Supported only for HTTP APIs', doc link https://docs.aws.amazon.com/apigateway/latest/developerguide/http-api-cors.html; the SAM resource contract is documented at https://docs.aws.amazon.com/serverless-application-model/latest/developerguide/sam-property-function-httpapi.html. On AWS, CreateStack with CAPABILITY_IAM + CAPABILITY_AUTO_EXPAND expands the transform and reaches the terminal status CREATE_COMPLETE; GetFunctionConfiguration then reports the MemorySize inherited from Globals.Function; the stack's Outputs carry Api.ApiEndpoint via Fn::GetAtt; the HttpApi event's Path/Method is served through the implicit $default stage, answering HTTP 200 with a 2.0 proxy payload whose version is '2.0', whose routeKey is the declared '<METHOD> <path>' and whose rawPath is the request path; a request carrying an Origin in Globals.HttpApi's CorsConfiguration.AllowOrigins is answered with access-control-allow-origin equal to that origin; a request from an origin not in AllowOrigins is still answered 200 but with no access-control-allow-origin; and an undeclared path is answered HTTP 404 with body {"message":"Not Found"} ('Not Found' is the fixed text, no variable parts). The statuses, the payload member names, the header name and the 404 body are the requirement; the function/stack names, the origin string and the MemorySize number come from the template and the request.
Emulator: 'Error: Check timed out after 60.0s'. No stack status, no resource failure reason, no HTTP status and no error code is produced on this path, so the emulator neither completes the SAM HttpApi deployment nor refuses it with a CREATE_FAILED resource event carrying a ResourceStatusReason. A client gets no answer rather than a response or a modelled refusal.
Why: AWS::Serverless::HttpApi with an HttpApi function event is the standard way an application declares an HTTP API, and a stack that never reaches a terminal state hangs every deployer (SAM CLI, CloudFormation waiters, CI) until its own timeout instead of failing fast with a reason, and leaves resources in an indeterminate state that cannot be rolled back or deleted. Even the refusal path is unusable: a template error surfaces as a hang, not as a CREATE_FAILED event a client can read.
Fix: the SAM transform expansion of AWS::Serverless::HttpApi (and of an AWS::Serverless::Function Events entry of Type HttpApi, including Globals.HttpApi/Globals.Function inheritance) in the CloudFormation provisioner, together with the stack's status machine, which must always drive the stack to a terminal status — CREATE_COMPLETE, or CREATE_FAILED/ROLLBACK_COMPLETE with a ResourceStatusReason on the failing logical id — rather than remaining _IN_PROGRESS; and then the execute-api HTTP data plane for the implicit $default stage the transform creates.
Traces: apigatewayv2__cloudformation__lambda.sam-httpapi-event-serves-payload-v2-route.
