# cloudformation__ssm: DeleteChangeSet refuses a change set in a terminal ExecutionStatus ("Cannot delete ChangeSet in execution status EXECUTE_COMPLETE"), so every second `cdk deploy` of a stack exits 1 before it plans anything

> _Note: this issue was identified against the code base at commit `d480a9c819aca039333e6ccd75fa51254e2ac722`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
DeleteChangeSet

## Description
Cause 1 of 1: DeleteChangeSet refuses a change set whose execution has already finished, instead of deleting it (failing checks: cloudformation__ssm.cdk-deploy-outputs-file-matches-describe-stacks-outputs-for-every-deployed-stack, cloudformation__ssm.cdk-deploy-parameters-are-reused-until-no-previous-parameters).
AWS: Smithy (cloudformation): DeleteChangeSet input {ChangeSetName (required), StackName}; output is empty; the ONE modeled error is InvalidChangeSetStatusException (client, httpError 400, awsQueryError code InvalidChangeSetStatus), documented "The specified change set can't be used to update the stack. For example, the change set status might be CREATE_IN_PROGRESS, or the stack status might be UPDATE_IN_PROGRESS." That is a refusal of a change set still being computed or still being applied. A change set in a TERMINAL execution status — EXECUTE_COMPLETE or EXECUTE_FAILED — is deletable: AWS answers HTTP 200 with an empty DeleteChangeSetResult and the plan is discarded. The CDK CLI depends on exactly that: before creating its change set it deletes any pre-existing one of the same name, which on every deploy after the first is one left in EXECUTE_COMPLETE (or EXECUTE_FAILED) by the previous deploy.
Emulator: HTTP 400 InvalidChangeSetStatusException with the message "Cannot delete ChangeSet in execution status EXECUTE_COMPLETE" (and "... EXECUTE_FAILED" for a change set whose execution failed). The handler refuses whenever the change set's plan is not "discardable", which it defines as every ExecutionStatus past the two a plan waits in — so it refuses the terminal statuses AWS deletes, not just the in-progress ones the model's error names. Both the status/code and the message are the emulator's own: AWS emits no such sentence for a terminal change set because it does not refuse the call.
Why: the refusal is on the path of ordinary stack maintenance, so it does not degrade a feature — it stops it. Any client that re-deploys a stack through a named change set (the CDK CLI, `aws cloudformation deploy`, CI pipelines that reuse a change-set name, and any "clean up the old plan" step) fails at the delete and never gets as far as creating or executing a plan: `cdk deploy` exits 1 with "Cannot delete ChangeSet in execution status EXECUTE_COMPLETE" after synthesis, the stack is left exactly as the previous deploy left it, and neither outputs nor parameters are ever updated. A client cannot work around it either: the plan can never be discarded, so DescribeChangeSet keeps resolving a change set that should be gone.
Fix: the DeleteChangeSet handler's precondition on the change set's execution status — only a change set whose CREATION has not concluded, or whose execution is in progress, may be refused InvalidChangeSetStatusException; a change set in a terminal execution status must be deleted (together with its nested hierarchy) and answered 200. Open issue 20261120T150300Z-cloudformation-deletechangeset-refuses-an-executed-change-set-so.md reports the same root cause, and 20261120T150929Z-cloudformation-s3-deletechangeset-refuses-a-change-set-in.md, 20261120T150929Z-cloudformation-iam-lambda-s3-deletechangeset-refuses-the-change.md and 20261120T162942Z-cloudformation-lambda-deletechangeset-refuses-an-executed-change-set.md report it under other service headings; none of them carries these two checks' replay keys, so they do not cover them.
Traces: cloudformation__ssm.cdk-deploy-outputs-file-matches-describe-stacks-outputs-for-every-deployed-stack, cloudformation__ssm.cdk-deploy-parameters-are-reused-until-no-previous-parameters. Code: services/service-com-amazonaws-cloudformation-cloudformation/src/ops/delete_change_set.rs:185-196 (the `!change_set.plan_is_discardable()` guard and the InvalidChangeSetStatusException it raises) and the message builder `crate::state::cannot_delete_change_set`.

cloudformation__ssm.cdk-deploy-outputs-file-matches-describe-stacks-outputs-for-every-deployed-stack: `AssertionError: 'cdk deploy <stack-a> --outputs-file <path> --require-approval never --toolkit-stack-name <toolkit>' exited 1, expected 0; output tail: '\n✨  Synthesis time: 2.17s\n\nCannot delete ChangeSet in execution status EXECUTE_COMPLETE\n'` — the second deploy of stack A, after the first `deploy --all` succeeded.

cloudformation__ssm.cdk-deploy-parameters-are-reused-until-no-previous-parameters: `AssertionError: deploy 2 [] exited 1; output tail '\n✨  Synthesis time: 1.83s\n\nCannot delete ChangeSet in execution status EXECUTE_COMPLETE\n'` — the deploy that must reuse the previous parameter value never runs, so DescribeStacks still reports the first deploy's Parameters.

Expected in both: DeleteChangeSet answers HTTP 200 with an empty body for the change set the previous deploy executed, `cdk deploy` exits 0, and DescribeStacks reflects the new deploy. Actual: HTTP 400 InvalidChangeSetStatusException, message "Cannot delete ChangeSet in execution status EXECUTE_COMPLETE" — fixed text "Cannot delete ChangeSet in execution status " plus the change set's ExecutionStatus; AWS emits no message here at all because it does not refuse.

## Steps to Reproduce
1. Clone the repo and boot the emulator built from it.
2. cloudformation CreateChangeSet(StackName=<new stack>, ChangeSetName='cdk-deploy-change-set', ChangeSetType='CREATE', TemplateBody=<any template>), then ExecuteChangeSet on it and wait for CREATE_COMPLETE. DescribeChangeSet now reports ExecutionStatus EXECUTE_COMPLETE.
3. DeleteChangeSet(StackName=<stack>, ChangeSetName='cdk-deploy-change-set') — observe HTTP 400 InvalidChangeSetStatusException "Cannot delete ChangeSet in execution status EXECUTE_COMPLETE" instead of 200.
4. End to end: with `cdk` and `node` available, `cdk deploy <stack> --require-approval never` twice against the emulator — the second run exits 1 right after synthesis with the same sentence and the stack is never updated.
