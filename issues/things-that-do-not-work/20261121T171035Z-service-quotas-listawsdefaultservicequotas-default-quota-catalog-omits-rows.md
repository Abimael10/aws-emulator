ListAWSDefaultServiceQuotas

## Description
TEN net-new causes, one per `ServiceCode`, all of the SAME defect: the emulator's default-quota catalog behind `ListAWSDefaultServiceQuotas` is not the catalog the service publishes for that `ServiceCode`. Every reply is HTTP 200 and well-formed, so the divergence is entirely in `$.Quotas`: rows the service publishes are absent, `Description` is omitted from rows that are present, `Adjustable` is published as `true` where the service publishes `false`, `QuotaName` is a shortened paraphrase rather than the published name, and `UsageMetric` is dropped.

THE RULE (shared by all ten causes). For a given `ServiceCode`, `$.Quotas` must contain ONE row per `QuotaCode` the service publishes for that code — no row missing and none invented — and each row must carry that quota's own `QuotaName`, `Value`, `Unit`, `Adjustable`, `GlobalQuota`, `Period`, `UsageMetric`, `QuotaContext` and `Description` as the service words them, never a paraphrase and never a truncation. Smithy fixes only the row SHAPE (`ServiceQuota`: `QuotaCode` @length 1..128 @pattern ^[a-zA-Z][a-zA-Z0-9-]{1,128}$, `Value` @range 0..10000000000, `Description` @length 0..350 "The quota description.", `Adjustable` boolean default false "Indicates whether the quota value can be increased.", `QuotaName` "Specifies the quota name.", `UsageMetric` -> MetricInfo "Information about the measurement.", `Period` -> QuotaPeriod; `ListAWSDefaultServiceQuotas` input `ServiceCode` required, output `Quotas` -> ServiceQuotaListDefinition, paginated items=Quotas). The per-code CONTENT is not in the model, so it is RECORDED BEHAVIOR ONLY and the recorded `ListAWSDefaultServiceQuotas` response for each `ServiceCode` is the reference. None of these rows can be authored by guessing: a plausible invented sentence, a shortened name or a flipped `Adjustable` IS the defect.
