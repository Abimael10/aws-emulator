# kinesis-video-archived-media: the DataEndpoint announced for APIName=LIST_FRAGMENTS is an authority the emulator does not serve, so ListFragments addressed to the discovered endpoint cannot connect at all

> _Note: this issue was identified against the code base at commit `6ad539f79015bc27d2d0777d4c5c145ae7d45c50`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Description
One net-new root cause, grounded in the single failing kinesis-video-archived-media check of this run that is neither ALREADY FILED nor OWNED. The other two failures (get-clip-missing-codec-private-data-rejected, list-fragments-and-get-clip-serve-ingested-video) are marked OWNED by 20261109T114037Z-kinesis-video-archived-media-getclip-returns-the-raw-ingested-matroska-ebml-bytes.md and were skipped.

NOTE on related open issues, named so neither is read as covering this check: 20261113T124707Z-kinesisvideo-a-control-plane-call-to-a-discovered.md is about the SHAPE of the refusal (an empty-string message member) a discovered DataEndpoint returns for a control-plane route that it does reach; it presupposes a connectable address and says nothing about an address that refuses TCP. 20261116T145451Z-kinesis-video-signaling-geticeserverconfig-announces-turn-uris-at.md is the same class of defect (an announced authority the emulator is not reached on) in a different service and for a different operation (GetIceServerConfig / TURN Uris), so it does not carry this check's replay key. Neither covers ListFragments reached through kinesisvideo GetDataEndpoint(APIName=LIST_FRAGMENTS).

=== Cause 1 of 1: GetDataEndpoint(APIName=LIST_FRAGMENTS) publishes an authority nothing is listening on, so an archived-media client built from the discovered endpoint — the only way AWS documents reaching this data plane — never reaches the service ===
AWS: Smithy (com.amazonaws.kinesisvideo#GetDataEndpoint, POST /getDataEndpoint -> 200, APIName required enum including LIST_FRAGMENTS, output member DataEndpoint) models endpoint discovery as the mandatory first step of every Kinesis Video Streams read: the caller asks the control plane for the data-plane address for one API, constructs a client at that address, and calls the archived-media operation there. com.amazonaws.kinesisvideoarchivedmedia#ListFragments is POST /listFragments -> 200 with output Fragments (a FragmentList) and NextToken, and its only modelled refusals are ClientLimitExceededException 400, InvalidArgumentException 400, NotAuthorizedException 401 and ResourceNotFoundException 404. The contract the model expresses is that the string returned in DataEndpoint is an address at which POST /listFragments is served and answers with one of those statuses. Against AWS it always is: there is no AWS response in which ListFragments at the discovered DataEndpoint fails to establish a connection. Recorded behavior only for the transport fact itself (the model does not describe hosts): the recording shows an archived-media client constructed verbatim from the DataEndpoint string completing the request/response exchange.
Emulator: GetDataEndpoint(APIName=LIST_FRAGMENTS) returns a DataEndpoint string whose scheme://host:port passes the check's `'://' in endpoint` sanity test but which nothing is bound to. The first ListFragments issued at that address never gets an HTTP response at all — botocore raises `botocore.exceptions.EndpointConnectionError: Could not connect to the endpoint URL: "http://127.0.0.1:<port>/listFragments"` from httpsession.send. (The specific host:port in the replay output is a per-run value, not part of the requirement; the requirement is that whatever authority the emulator announces in DataEndpoint is one it actually serves /listFragments on.) Note this is specifically the raw-DataEndpoint path: the two sibling checks that pass through the harness's endpoint rewrite reach the service and fail later, on content, which is what isolates the defect to the announced authority rather than to the ListFragments handler.
Why: endpoint discovery is not optional in Kinesis Video Streams — every SDK example, every consumer and the service's own documentation construct the archived-media client from GetDataEndpoint's output. A client that follows that contract gets a connection error instead of a response, so the whole archived-media read plane is unreachable for it: ListFragments, and by the same announcement every other LIST_FRAGMENTS-addressed read, cannot be exercised, retried or error-handled, because no HTTP status or error code is ever produced to branch on. A connection failure is also indistinguishable, at the client, from the emulator being down, so a caller cannot tell a configuration problem from a service defect. Downstream, the post-DeleteStream half of this check (ListFragments by StreamName and by StreamARN must both be refused ResourceNotFoundException with the message `The requested stream is not found or not active.`) and the name-vs-ARN addressing equivalence it asserts are entirely unverifiable, since the call never leaves the client.
Fix: the endpoint-announcement seam of the kinesisvideo control plane that builds GetDataEndpoint's DataEndpoint value, and the routing that must bind /listFragments at whatever authority it announces. The announced scheme/host/port must be the authority the emulator is actually reached on for that API (the same authority the front door accepts), so that a client constructed from the raw DataEndpoint string reaches POST /listFragments and gets a modelled answer — 200 with Fragments, or one of the four modelled errors. Nothing about this depends on a particular host or port value.
