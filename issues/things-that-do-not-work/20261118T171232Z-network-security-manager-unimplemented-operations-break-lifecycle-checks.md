# network-security-manager unimplemented operations break lifecycle checks: 2 causes — DeleteRule answers 501 instead of 409 ConflictException on a template-referenced rule, CreateScope answers 501 instead of 201

> _Note: this issue was identified against the code base at commit `21144120b923f578d0c940193e5b4a3734c2fd4d`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
DeleteRule

## Description
Two distinct root causes observed replaying the simparity-behavioral-aws-v1 behavioral suite against the emulator built from this checkout. Both are in the Network Security Manager service (com.amazonaws.networksecuritymanager#PiccoloCustomerAPIService, restJson1). Neither failing check was marked ALREADY FILED or OWNED by the replay report, so both are reported here; the related open issues are named in each cause.

=== Cause 1 of 2: DeleteRule on a rule a Template still references answers 501 NotImplemented instead of refusing with 409 ConflictException (and instead of 204 once the reference is gone) ===
AWS: Smithy model DeleteRule — DELETE /rules/{ruleIdentifier} (ruleIdentifier @httpLabel, @required, length 1..1010), output Unit, success @http code 204, @idempotent. Its modeled errors are AccessDeniedException (403), ConflictException (@error client, @httpError 409), InternalServerException (500), ThrottlingException (429) and ValidationException (400); 501 is not a modeled outcome. ConflictException is documented as "The request conflicts with the current state of the resource... it is in a state that does not allow the requested operation" and carries a @required `message` plus optional `resourceId`/`resourceType`. Recorded behavior for a rule that is still listed in a Template's associatedRuleList: HTTP 409, error code ConflictException, message "The resource is currently in use and cannot be modified" — that message is entirely fixed text for this dependency-protection class (no request- or state-derived parts); the optional resourceId/resourceType, when present, carry the in-use rule's id and type from emulator state. The refusal must not mutate state: a following GetRule still returns the same ruleId. After the referencing Template is deleted, the identical DeleteRule call must succeed with 204, and GetRule on the deleted rule must then answer 404 ResourceNotFoundException with message "Rule not found: <ruleId>" (fixed text "Rule not found: " plus the ruleId from the request/state).
Emulator: DeleteRule is an unimplemented scaffold. Every call answers HTTP 501 with error code `NotImplemented` and message of the form "operation DELETE /rules/{ruleIdentifier} is not implemented in this emulator", so the dependency check never runs: the check asserts `code == "ConflictException"` and gets 'NotImplemented'. The positive control (delete succeeds once the template is gone) and the post-delete ResourceNotFoundException are therefore unreachable too.
Why: a client cannot delete a rule at all, and a client that relies on AWS protecting an in-use rule gets a protocol-level 501 that no SDK models as an NSM error — it is not retriable, not a ConflictException, and not catchable through the service's modeled exception set. Dependency-protection logic in callers (delete template first, then rule) can never be exercised, and cleanup paths leak rules.
Related open issue: `20261118T113746Z-network-security-manager-deleterule-is-an-unimplemented-scaffold.md` owns the policy-reference variant of this refusal (check network-security-manager.delete-rule-blocked-while-associated-with-policy). It does NOT carry this check's replay key, and the template-reference dependency edge (Template.associatedRuleList -> Rule) is a separate reference path from the policy one, so this cause records it; closing it requires the template edge to refuse as well as the policy edge.
Fix: implement the DeleteRule handler (services/service-com-amazonaws-networksecuritymanager-piccolocustomerapiservice/src/ops/delete_rule.rs), its state-level reference check (refuse while any Template's associatedRuleList — and any Policy — still references the rule, without mutating state), the 409 ConflictException serializer with the fixed in-use message, and the 204 empty success response.
Traces: network-security-manager.delete-rule-blocked-while-associated-with-template.

=== Cause 2 of 2: CreateScope answers 501 NotImplemented, so no scope can be created and the ListScopes/ListTemplates read-back is unreachable ===
AWS: Smithy model CreateScope — POST /scopes, success @http code 201, @idempotent. Input requires scopeName (ScopeName, length 1..128, pattern ^[a-zA-Z0-9][a-zA-Z0-9 _.:/=+\-@]*$) and scopeConfiguration (ScopeConfiguration), with optional clientToken (@idempotencyToken), scopeDescription, isPublished (default true) and tags. Output CreateScopeOutput requires scopeId (pattern ^[a-z0-9]{1,64}$), scopeArn, scopeName, status (EntityStatus) and version (EntityVersion, pattern ^[1-9][0-9]*$), plus scopeConfiguration, updateToken (36-char UUID form), isSnapshot, hasPublishedVersion and updatedAt (@timestampFormat date-time). Modeled errors are AccessDeniedException (403), ConflictException (409), InternalServerException (500), ServiceQuotaExceededException (402), ServiceUnavailableException (503), TagPolicyViolationException (400), ThrottlingException (429), ValidationException (400); 501 is not among them. A valid CreateScope returns 201 echoing the submitted scopeName and scopeConfiguration, status ACTIVE when isPublished defaults to true, version "1" for a first create, and freshly generated scopeId/scopeArn/updateToken/updatedAt. The created scope's scopeId must then appear in ListScopes (GET /scopes, paginated on nextToken/maxResults, required output member `scopes`) with exactly the submitted scopeName and the returned scopeArn — likewise a created template's templateId in ListTemplates with its templateName, templateArn and firewallType.
Emulator: the call is refused with HTTP 501, error code `NotImplemented`, message "operation POST /scopes is not implemented in this emulator" (botocore: "An error occurred (NotImplemented) when calling the CreateScope operation"). No output members are produced. Because CreateScope is the entry point of the scope lifecycle, the by-id read-back assertions over ListScopes (and the ListTemplates half of the same check, which the emulator is never asked) cannot run.
Why: a caller cannot express the accounts-and-resources selection a policy deployment needs; it receives a 501 that is outside the service's modeled exception set rather than a created scope or a modeled 4xx, and every later scope operation (GetScope/ListScopes/UpdateScope/DeleteScope) has nothing to act on.
Related open issue: `20261109T164319Z-network-security-manager-create-entity-operations-diverge-3.md` describes the same 501 as its Cause 3, keyed to the wire fixture network-security-manager-scope-and-template-crud#task#6. It does not carry this behavioral check's replay key, so this cause records it; a fixer closing it should re-replay the check listed below as well.
Fix: implement the CreateScope handler and its state (scope entity store: scopeId/scopeArn generation, version and updateToken issuance, DRAFT vs ACTIVE from isPublished, updatedAt) and its 201 serializer, and make the created scope visible to ListScopes (and the created template to ListTemplates) with its exact name/ARN.
Traces: network-security-manager.create-template-and-scope-appear-by-id-in-their-lists.
