# cloudformation__sns__sqs: DeleteChangeSet refuses a change set in execution status EXECUTE_COMPLETE, so the second `cdk deploy` of a sibling-NestedStack app exits 1 before it updates anything

> _Note: this issue was identified against the code base at commit `d480a9c819aca039333e6ccd75fa51254e2ac722`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
DeleteChangeSet

## Description
Cause 1 of 1: `DeleteChangeSet` is refused with `InvalidChangeSetStatus` for every change set whose execution has begun or concluded, including the terminal `EXECUTE_COMPLETE`. AWS discards such a plan and answers 200, and the CDK CLI depends on that: before it creates its change set for a second deploy it deletes the identically-named change set the previous deploy executed. Failing check ids for this cause: cloudformation__sns__sqs.cdk-sibling-nested-stacks-deliver-topic-to-queue-across-a-producer-only-update.

AWS: `DeleteChangeSet` "Deletes the specified change set. Deleting change sets ensures that no one executes the wrong change set. If the call successfully completes, CloudFormation successfully deleted the change set." (Smithy: CloudFormation#DeleteChangeSet documentation; input `ChangeSetName` required, optional `StackName`; output `DeleteChangeSetOutput` is empty, SUCCESS_STATUS 200). The ONE modelled error is `InvalidChangeSetStatusException` (errorKind client, httpError 400, awsQueryError code `InvalidChangeSetStatus`), documented as "The specified change set can't be used to update the stack. For example, the change set status might be CREATE_IN_PROGRESS, or the stack status might be UPDATE_IN_PROGRESS." — i.e. a change set whose CREATION has not concluded, or one whose execution is still being applied. Neither the model nor the docs name a concluded execution as a refusal, and the model declares no not-found error, so discarding a change set that is merely a record of a finished execution is a success. Recorded behavior confirms it: the recorded run of this check performs two `cdk deploy` invocations of the same app and both exit 0, which is only possible if the CLI's pre-create `DeleteChangeSet` of the first deploy's executed change set succeeded.

Emulator: `DeleteChangeSet` answers HTTP 400 `InvalidChangeSetStatus` with message `Cannot delete ChangeSet in execution status EXECUTE_COMPLETE`. The fixed text is `Cannot delete ChangeSet in execution status ` and the only variable part is the change set's `ExecutionStatus` read from emulator state (here `EXECUTE_COMPLETE`); no name, ARN or stack is interpolated. The refusal is produced for every `ExecutionStatus` outside `UNAVAILABLE`/`AVAILABLE`, so `EXECUTE_IN_PROGRESS`, `EXECUTE_COMPLETE`, `EXECUTE_FAILED` and `OBSOLETE` are all refused, and the record is left in place. The replayed `cdk deploy` surfaces this as `the producer-only `cdk deploy` exited 1; output tail '... Published sim2real-cdk-sib-<id> Template ...\nCannot delete ChangeSet in execution status EXECUTE_COMPLETE\n'` — the CLI aborts after publishing the nested templates and before issuing any `CreateChangeSet`/`ExecuteChangeSet`, so the parent and both nested stacks never reach `UPDATE_COMPLETE`, the producer topic's `DisplayName` is never updated, and the post-update topic→queue delivery is never exercised.

Why: a client that re-deploys a stack is blocked outright. Any workflow that reuses a change-set name — the CDK CLI's `cdk deploy` on an already-deployed stack, `aws cloudformation deploy`, or any tool that cleans up an executed change set before planning the next one — gets a 400 instead of a 200, treats the stack as un-updatable, and exits non-zero. On AWS the same sequence succeeds, so the emulator turns a routine update into a hard failure, and it also leaks executed change sets permanently: nothing can ever discard them, so `DescribeChangeSet`/`ListChangeSets` keep resolving plans a caller has deliberately deleted.

Fix: the `DeleteChangeSet` handler's status gate and the predicate it reads — the discardability decision must refuse only a change set whose creation has not concluded (`CREATE_PENDING`/`CREATE_IN_PROGRESS`) or whose execution is still in flight (`EXECUTE_IN_PROGRESS`), and must delete (and answer an empty 200) for a concluded or superseded execution (`EXECUTE_COMPLETE`, `EXECUTE_FAILED`, `OBSOLETE`), dropping the record and its nested hierarchy as it already does for a discardable plan.

## Evidence
Expected (AWS): the producer-only second `cdk deploy` exits 0. The CLI's pre-create `DeleteChangeSet` of the change set the first deploy executed (ExecutionStatus `EXECUTE_COMPLETE`) returns HTTP 200 with an empty `DeleteChangeSetOutput`; the deploy then creates and executes a new change set, parent/producer/consumer all report `StackStatus` `UPDATE_COMPLETE`, the same nested stack ids and the same topic and queue physical ids are retained, `GetTopicAttributes` reports `DisplayName` `second`, and a publish to the topic still reaches the subscribed queue.

Actual (emulator): `DeleteChangeSet` answers HTTP 400, error code `InvalidChangeSetStatus`, message `Cannot delete ChangeSet in execution status EXECUTE_COMPLETE` (fixed text `Cannot delete ChangeSet in execution status ` + the change set's `ExecutionStatus` from emulator state). The CLI aborts:

  AssertionError: the producer-only `cdk deploy` exited 1; output tail '... success: Published Producer Nested Stack Template (...)\n... success: Published sim2real-cdk-sib-<id> Template (...)\nCannot delete ChangeSet in execution status EXECUTE_COMPLETE\n'

No `CreateChangeSet`/`ExecuteChangeSet` is issued for the second deploy, so no stack reaches `UPDATE_COMPLETE`, the topic `DisplayName` stays at its first-deploy value, and the post-update delivery assertion is never reached. The same gate refuses `EXECUTE_FAILED` and `OBSOLETE` change sets too, so no executed change set can ever be discarded.

## Steps to Reproduce
1. Create a change set for a stack (`CreateChangeSet`), wait for `ChangeSetStatus` `CREATE_COMPLETE`, then `ExecuteChangeSet` and wait for the stack operation to conclude; `DescribeChangeSet` now reports `ExecutionStatus` `EXECUTE_COMPLETE`.
2. Call `DeleteChangeSet` with that change set's ARN (or its name plus `StackName`).
3. AWS answers HTTP 200 with an empty body and the change set is gone. The emulator answers HTTP 400 `InvalidChangeSetStatus` with message `Cannot delete ChangeSet in execution status EXECUTE_COMPLETE` and keeps the record.
4. End to end: replay cloudformation__sns__sqs.cdk-sibling-nested-stacks-deliver-topic-to-queue-across-a-producer-only-update — deploy the sibling-NestedStack CDK app once (`display_name=first`), then deploy it again with only the producer changed (`display_name=second`). The second `cdk deploy` exits 1 with `Cannot delete ChangeSet in execution status EXECUTE_COMPLETE` in its output tail instead of exiting 0 and leaving parent, producer and consumer in `UPDATE_COMPLETE`.
