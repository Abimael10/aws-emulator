# elasticbeanstalk__logs: a Ready environment's published CNAME is an unserved '.elasticbeanstalk.localhost' host, so the StreamLogs-to-CloudWatch-Logs flow can never be observed

> _Note: this issue was identified against the code base at commit `9f7bf23473ff024f6e39d27cef35bcce93712a4b`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Description
ONE root cause in the elasticbeanstalk emulator, grounded in the single failing behavioral check of this suite that the replay marked neither ALREADY FILED nor OWNED. ONE cause must be closed before submitting.

Adjacent OPEN issues describe neighbouring ground but do NOT carry this check (the replay marked this failure neither ALREADY FILED nor OWNED, so no recorded replay key matches it): 20261109T144630Z-elasticbeanstalk-elastic-beanstalk-publishes-environment-cname-endpointurl-and-log.md (its Cause 1 is the same class of defect but is grounded in a published host of the form '<env>.<region>.elasticbeanstalk.com'; in THIS replay the published host has changed to '<env>.<cname-suffix>.<region>.elasticbeanstalk.localhost', so the grounding here is new and still unowned), 20261124T063442Z-elasticbeanstalk-elastic-beanstalk-environment-cname-is-published-as-host.md (describes the CNAME published as a bare 'host:port/path' rather than a DNS name — a different published form from the one observed here), 20261107T192913Z-elasticbeanstalk-elastic-beanstalk-environments-have-no-data-plane-endpointurl.md (its causes read 'EndpointURL is never published' and 'nothing answers at the CNAME'; here a CNAME IS published and the failure has moved to WHICH host it names), 20261123T012852Z-elasticbeanstalk-elastic-beanstalk-swapenvironmentcnames-moves-no-traffic-the-served.md (CNAME swapping, not the initial publication). None of them is grounded in the elasticbeanstalk__logs check below, and the whole CloudWatch-Logs half of this scenario (log-group derivation, RetentionInDays, the platform-specific streamed log set, event delivery and stream attribution) is unreached ground that no open issue covers.

Cause 1 of 1: DescribeEnvironments publishes a Ready environment's CNAME on a '.elasticbeanstalk.localhost' host that the emulator does not listen on, so the environment's data plane is unreachable and every downstream CloudWatch Logs assertion of the StreamLogs scenario is unreachable with it.
AWS: Smithy (com.amazonaws.elasticbeanstalk#AWSElasticBeanstalkService): DescribeEnvironments -> EnvironmentDescriptionsMessage/EnvironmentDescription, member CNAME targets DNSCname @length 1..255, documented '<p>The URL to the CNAME for this environment.</p>'; sibling member EndpointURL documented 'For load-balanced, autoscaling environments, the URL to the LoadBalancer. For single-instance environments, the IP address of the instance.'; EnvironmentDescription.Status enum value 'Ready' is documented 'Environment is available to have an action performed on it'. The model does not constrain the host itself, so beyond that: recorded behavior only — once an environment reports Status='Ready', the address published in CNAME is the address a client dials with a plain HTTP GET and gets the deployed application bundle's own response back from; the published address and the reachable address are the same address. The AWS documentation for log streaming (https://docs.aws.amazon.com/elasticbeanstalk/latest/dg/AWSHowTo.cloudwatchlogs.html) then states the rule this check's later steps assert: with aws:elasticbeanstalk:cloudwatch:logs StreamLogs=true the instance log is streamed to the group named '/aws/elasticbeanstalk/<environment-name>' followed by the on-instance path (so '/aws/elasticbeanstalk/<env>/var/log/web.stdout.log' for a Python platform's application stdout), RetentionInDays configures that group's retentionInDays, and the set of streamed files is decided by the platform (a Ruby-only path such as '/var/log/puma/puma.log' must get no group under a Python environment).
Emulator: the environment does reach Status='Ready' and DescribeEnvironments does return a non-empty CNAME, but the host it names is a synthetic '.elasticbeanstalk.localhost' name the emulator serves nothing on. The first dial of that address is refused by the harness's own routing before any request leaves: simparity.published.PublishedUrlRejected: "endpoint_url was given http://<env-name>.<cname-suffix>.<region>.elasticbeanstalk.localhost/ (published by the emulator or built by the check): its host is not one of the emulator's own hosts; a customer of the emulator needs http(s)://127.0.0.1:<port>/<resource path>, or http(s)://<own host>:<port>/<path> on a per-resource listener". The environment name, the generated CNAME suffix, the region and the 127.0.0.1:<port> in that message are per-run values; the requirement is that the announced host is one the emulator answers on. Because the dial never succeeds, nothing downstream of it is exercised either, and all of it is additionally unverified: whether StreamLogs=true creates '/aws/elasticbeanstalk/<env>/var/log/web.stdout.log', whether RetentionInDays reaches that group's retentionInDays, whether a Ruby-only path is correctly left without a group, whether the application's own stdout line is delivered as an event with a timestamp inside the window that caused it, and whether the group's log streams are attributable to the instance ids DescribeEnvironmentResources reports.
Why: a client reads CNAME from the API and dials it. Against the emulator it is sent to a host that resolves to nothing the emulator serves, so the application it just deployed is unreachable and it cannot distinguish 'my deployment is broken' from 'the service announced an address it does not serve'. Everything that depends on the running application is then unobservable, including the entire Elastic Beanstalk -> CloudWatch Logs integration: a client cannot confirm that enabling StreamLogs produced the documented log group, that its retention was applied, or that a line its application printed to stdout was delivered.
Fix: the environment endpoint publication — the CNAME (and EndpointURL) the environment state records and the EnvironmentDescription serializer emits must be an address on one of the emulator's own listeners (its own host/port, or a per-resource listener), and that listener must serve the deployed application version; the log-stream delivery that keys off the same running instance follows from it. Belongs in the CreateEnvironment / UpdateEnvironment / DescribeEnvironments handlers and the service's environment state module (services/service-com-amazonaws-elasticbeanstalk-awselasticbeanstalkservice/src/ops/ plus the environment/CNAME state module), together with the aws:elasticbeanstalk:cloudwatch:logs option handling that derives the log group and its retention in CloudWatch Logs.

## Evidence
Cause 1: the check creates an application, publishes a Processed application version from a stdlib source bundle, and calls CreateEnvironment with CNAMEPrefix=<env>, an Amazon Linux 2023 Python solution stack and option settings aws:elasticbeanstalk:cloudwatch:logs StreamLogs=true / DeleteOnTerminate=true / RetentionInDays=1. The environment settles Status='Ready'. Expected: the CNAME DescribeEnvironments publishes for that Ready environment is dialable and 'http://<CNAME>/' answers HTTP 200 with the bundle's nonce body. Actual: the dial is refused at the published address, in context.py:616 -> _published_target (context.py:632) with simparity.published.PublishedUrlRejected: "endpoint_url was given http://sim2real-eb-log-env-add17e8fadc2.eba-815d188d.us-west-2.elasticbeanstalk.localhost/ (published by the emulator or built by the check): its host is not one of the emulator's own hosts; a customer of the emulator needs http(s)://127.0.0.1:40655/<resource path>, or http(s)://<own host>:<port>/<path> on a per-resource listener". The environment name 'sim2real-eb-log-env-add17e8fadc2', the CNAME suffix 'eba-815d188d', the region and the port 40655 are this run's generated values filling the template; the requirement is that the published host is an address the emulator listens on.

Consequently unverified in the same check (no assertion on them was ever reached, because the data-plane dial precedes them): describe_log_groups(logGroupNamePrefix='/aws/elasticbeanstalk/<env>') holding '/aws/elasticbeanstalk/<env>/var/log/web.stdout.log'; that group's retentionInDays == 1; describe_log_groups(logGroupNamePrefix='/aws/elasticbeanstalk/<env>/var/log/puma/puma.log') returning [] for a Python platform; filter_log_events(logGroupName='/aws/elasticbeanstalk/<env>/var/log/web.stdout.log', filterPattern='"<nonce>"') returning an event whose message contains the exact line 'SIM2REAL-LOG-LINE <nonce>' the application wrote to stdout, with a timestamp inside the request window (±60 s skew); and describe_log_streams on that group returning at least one stream whose name contains one of the instance ids DescribeEnvironmentResources reports.
