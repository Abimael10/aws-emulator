# bedrock foundation-model and inference-profile catalogs diverge from AWS (2 causes)

> _Note: this issue was identified against the code base at commit `1b6c4d4558e893b437b9e0fd87cc8835e7f57e31`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
ListFoundationModels

## Description
The emulator answers both bedrock read-only catalog list operations with HTTP 200 and the right envelope shape, but the catalog CONTENT it serves diverges from what AWS returns. Two distinct causes, both in the bedrock service's static model/profile catalog and its serializer. THIS ISSUE HAS 2 CAUSES; both must be closed before submitting.

Cause 1 of 2: ListFoundationModels model summaries carry stale, incomplete and partly wrong per-model metadata (fixture bedrock-catalog-list-foundation-models, step task#1).
AWS: GET /foundation-models -> 200 with `modelSummaries`, a list of FoundationModelSummary (Smithy: ListFoundationModels, http GET /foundation-models, code 200, output member modelSummaries -> FoundationModelSummaryList; FoundationModelSummary models modelArn, modelId, modelName, providerName, inputModalities, outputModalities, responseStreamingSupported, customizationsSupported, inferenceTypesSupported, modelLifecycle).
