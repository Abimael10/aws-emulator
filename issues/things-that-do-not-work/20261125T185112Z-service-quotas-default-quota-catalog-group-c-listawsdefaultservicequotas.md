Smithy (services/service-com-amazonaws-servicequotas-servicequotasv20190624/smithy-model/com-amazonaws-servicequotas-servicequotasv20190624.json): ListAWSDefaultServiceQuotas input ServiceCode required (@length 1..63, @pattern ^[a-zA-Z][a-zA-Z0-9-]{1,63}$), MaxResults (@range 1..100), NextToken (@length 0..2048); output Quotas: ServiceQuotaListDefinition + NextToken; paginated {inputToken NextToken, outputToken NextToken, items Quotas, pageSize MaxResults}; errors AccessDeniedException 403, IllegalArgumentException 400, InvalidPaginationTokenException 400, NoSuchResourceException 404, TooManyRequestsException 429, ServiceException 500. Shape ServiceQuota members: ServiceCode, ServiceName, QuotaArn, QuotaCode (@length 1..128), QuotaName, Value (double @range 0..1e10), Unit, Adjustable (@default false), GlobalQuota (@default false), UsageMetric, Period, QuotaContext, Description (@length 0..350, @pattern ^.{0,350}$). The model does not enumerate the catalog rows themselves, so the row set and each row's field values are "recorded behavior only": each recording shows AWS answering HTTP 200 with the COMPLETE published default-quota set for the requested ServiceCode, every row carrying Description.

Emulator, in general: HTTP 200 (status matches) but the Quotas list is either empty for the ServiceCode or missing rows, and rows that are returned omit ServiceQuota.Description. Per the op's own doc (services/service-com-amazonaws-servicequotas-servicequotasv20190624/src/ops/list_aws_default_service_quotas.rs lines 10-22) a known ServiceCode whose defaults are not seeded answers 200 with an EMPTY list, so this is a catalog-seed gap, not a serializer or routing fault.

Why, in general: ListAWSDefaultServiceQuotas is the discovery API for AWS-published limits. A client that walks it sees a service with no limits at all (or limits with no description), so quota-inventory tooling, limit dashboards and "am I near my quota" checks silently report nothing, and GetAWSDefaultServiceQuota for the same pair cannot be reached either.

Fix, in general: the seeded default-quota map in crate::state of the service-quotas crate (plus ServiceQuota.Description population for the rows it already seeds), consumed by ops/list_aws_default_service_quotas.rs.
