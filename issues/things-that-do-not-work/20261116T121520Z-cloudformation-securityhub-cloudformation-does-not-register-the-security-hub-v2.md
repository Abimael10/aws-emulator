# CloudFormation does not register the Security Hub v2 resource types: CreateStack refuses AWS::SecurityHub::HubV2, AggregatorV2 and AutomationRuleV2 as unrecognized

> _Note: this issue was identified against the code base at commit `13e968f2d712b86cbfec63dd795b2bc21b7f9b4c`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
CreateStack

## Description
One net-new root cause, grounded in two failing behavioral checks that no open issue carries the replay key for.

Cause 1 of 1: the CloudFormation resource-type registry does not know the Security Hub v2 resource types, so every stack that declares one is refused at CreateStack instead of being provisioned (positive path) or accepted-then-rolled-back on property validation (negative path).
Failing checks: cloudformation__securityhub.deploy-securityhub-hubv2-aggregatorv2-rulev2-round-trip, cloudformation__securityhub.deploy-securityhub-automationrulev2-invalid-ruleorder-rejected
  AWS:      CloudFormation registers AWS::SecurityHub::HubV2, AWS::SecurityHub::AggregatorV2 and AWS::SecurityHub::AutomationRuleV2, and provisions them through Security Hub's v2 control plane. Smithy (securityhub): CreateAutomationRuleV2 input requires RuleName, Description, Criteria, Actions (@length 1..1) and RuleOrder (target RuleOrderValueV2, @range min 1.0 max 1000.0), returns RuleArn/RuleId and models ValidationException (httpError 400); CreateAggregatorV2 requires RegionLinkingMode and returns AggregatorV2Arn/AggregationRegion/LinkedRegions; the rules read back through GetAutomationRuleV2 / ListAutomationRulesV2 and the hub through DescribeSecurityHubV2 (ResourceNotFoundException when v2 is off). Because the types are registered, AWS does NOT refuse the template: for a well-formed template the stack reaches CREATE_COMPLETE and Ref/outputs resolve to the created rule's ARN; for a RuleOrder outside the modelled range the stack is still ACCEPTED, fails early property validation and reaches ROLLBACK_COMPLETE with a VALIDATION_ERROR operation event whose decisive row is (<LogicalResourceId>, "PROPERTY_VALIDATION", "FAILED", "FAIL", "#/RuleOrder: <submitted value> is not greater or equal to <modelled minimum>", "/Resources/<LogicalResourceId>/Properties/RuleOrder"). In that message "#/RuleOrder: " and " is not greater or equal to " are fixed text; the member name, the submitted value, the minimum (1.0, from the model) and the template path come from the request and the model, never from one run.
  Emulator: CreateStack is refused outright with HTTP 400 and error code ValidationError, message "Template format error: Unrecognized resource types: [AWS::SecurityHub::HubV2, AWS::SecurityHub::AutomationRuleV2]" for the rule template and "Template format error: Unrecognized resource types: [AWS::SecurityHub::HubV2, AWS::SecurityHub::AggregatorV2, AWS::SecurityHub::AutomationRuleV2]" for the hub/aggregator/rule round trip. The fixed text is "Template format error: Unrecognized resource types: [" ... "]"; the names inside the brackets are the types the submitted template declares. No stack is created, no stack event is emitted and Security Hub never sees the resources, so neither the happy path nor the property-validation refusal can be observed.
  Why:      a client relying on AWS's behavior deploys Security Hub v2 (hub, cross-region aggregator and automation rules) as CloudFormation resources; against this emulator every such stack is rejected at submit time, so the resources cannot be created at all, and a client testing its own guardrails sees a synchronous ValidationError at CreateStack instead of an accepted stack that rolls back with a per-property PROPERTY_VALIDATION reason it can read from the stack's events.
  Fix:      the CloudFormation service's resource-type registry and the resource handlers for the three AWS::SecurityHub::*V2 types (provision/read/delete against the securityhub service's state), plus the pre-provision property validation that must report an out-of-range RuleOrder as a PROPERTY_VALIDATION failure on an accepted stack rather than as a template-format refusal.
  Traces:   cloudformation__securityhub.deploy-securityhub-hubv2-aggregatorv2-rulev2-round-trip, cloudformation__securityhub.deploy-securityhub-automationrulev2-invalid-ruleorder-rejected. Open issue 20261116T061927Z-cloudformation-securityhub-cloudformation-accepts-an-off-enum-aws-securityhub-hub.md covers a different Security Hub CloudFormation defect (an off-enum AWS::SecurityHub::Hub ControlFindingGenerator being accepted) and does not carry these checks' replay keys, so this cause is filed here.

## Evidence
Expected (round trip): CreateStack accepts a template declaring AWS::SecurityHub::HubV2 + AWS::SecurityHub::AggregatorV2 + AWS::SecurityHub::AutomationRuleV2, the stack reaches CREATE_COMPLETE, and the rule reads back through securityhub GetAutomationRuleV2 with the RuleName/RuleOrder/Description/Actions the template declared.
Actual (replay): botocore.exceptions.ClientError: An error occurred (ValidationError) when calling the CreateStack operation: Template format error: Unrecognized resource types: [AWS::SecurityHub::HubV2, AWS::SecurityHub::AggregatorV2, AWS::SecurityHub::AutomationRuleV2]

Expected (negative): the same template with RuleOrder=0 is accepted, the stack ends ROLLBACK_COMPLETE, and its VALIDATION_ERROR operation events contain exactly one FAIL row ("Rule", "PROPERTY_VALIDATION", "FAILED", "FAIL", "#/RuleOrder: 0 is not greater or equal to 1.0", "/Resources/Rule/Properties/RuleOrder"); Security Hub never holds the rejected rule while the RuleOrder=5 control stack deploys and its rule is listed.
Actual (replay): botocore.exceptions.ClientError: An error occurred (ValidationError) when calling the CreateStack operation: Template format error: Unrecognized resource types: [AWS::SecurityHub::HubV2, AWS::SecurityHub::AutomationRuleV2] — the call is refused before any stack exists, so there is no stack status and no PROPERTY_VALIDATION event.

## Steps to Reproduce
1. Call cloudformation CreateStack with a template whose Resources declare {"Hub": {"Type": "AWS::SecurityHub::HubV2", "Properties": {}}, "Rule": {"Type": "AWS::SecurityHub::AutomationRuleV2", "DependsOn": "Hub", "Properties": {RuleName, Description, RuleOrder: 5, Criteria.OcsfFindingCriteria, Actions: [{"Type": "FINDING_FIELDS_UPDATE", ...}]}}} and an Output {"Ref": "Rule"}. Expected: 200 with a StackId, the stack reaching CREATE_COMPLETE and securityhub GetAutomationRuleV2(Identifier=<output ARN>) returning the declared values. Observed: 400 ValidationError "Template format error: Unrecognized resource types: [AWS::SecurityHub::HubV2, AWS::SecurityHub::AutomationRuleV2]".
2. Repeat with RuleOrder: 0. Expected: the stack is accepted and ends ROLLBACK_COMPLETE with a VALIDATION_ERROR event row PROPERTY_VALIDATION/FAILED/FAIL "#/RuleOrder: 0 is not greater or equal to 1.0" at /Resources/Rule/Properties/RuleOrder. Observed: the same synchronous CreateStack ValidationError refusal.
3. Add an AWS::SecurityHub::AggregatorV2 resource to the template: the refusal's bracketed list grows to include it, confirming none of the three types is registered.
