# wafv2 DescribeAllManagedProducts serves a divergent managed-product catalog

> _Note: this issue was identified against the code base at commit `25bdbacbe9a9d6bbd8127a5ccb0043b8e680cf5e`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
DescribeAllManagedProducts

## Description
Cause 1 of 1: DescribeAllManagedProducts answers 200 with a ManagedProducts list whose entries are not the managed-product catalog AWS publishes: every modeled descriptor in the recorded catalog is absent from the emulator's list, the emulator's own entries omit two modeled members outright, and the members it does emit carry values of the wrong form.

AWS: Smithy: DescribeAllManagedProducts(Scope required) -> DescribeAllManagedProductsResponse.ManagedProducts : ManagedProductDescriptors (list of ManagedProductDescriptor). ManagedProductDescriptor models VendorName, ManagedRuleSetName, ProductId, ProductLink, ProductTitle (@length min 1, pattern \S, "The display name for the managed rule group"), ProductDescription (@length min 1, pattern \S, "A short description of the managed rule group"), SnsTopicArn (ResourceArn, "the ARN of the SNS topic that's used to provide notification of changes to the managed rule group"), IsVersioningSupported and IsAdvancedManagedRuleSet. The operation is a read of a fixed, service-owned catalog of AWS Managed Rules and AWS Marketplace managed rule groups, so for a given Scope AWS returns the same descriptor set on every call, and each descriptor is fully populated: a ProductTitle and a ProductDescription for every product, the vendor's own ProductId, the vendor's Marketplace ProductLink exactly as AWS publishes it (the recording shows the http://aws.amazon.com/marketplace/pp/<asin> form), and an SnsTopicArn owned by the publishing vendor's account (the recording shows arn:aws:sns:us-east-1:343255486711:CyberSecurityCloud-ManagedRule for the Cyber Security Cloud products) rather than the caller's account. Membership and per-product identity are the requirement; list order is not, and the generated/account-specific parts of a single recording are not. Recorded behavior only for the exact catalog size: the recording asserts 46 descriptors ($.ManagedProducts[0] through $.ManagedProducts[45]).

Emulator: the replayed response is 200 but carries a different catalog. All 46 recorded descriptors are reported missing ($.ManagedProducts[0]..$.ManagedProducts[45]: missing), i.e. the emulator's list does not contain them at any index. The descriptors it does return are stripped and reshaped: e.g. at index 0 it serves {VendorName: 'Cyber Security Cloud Inc.', ManagedRuleSetName: 'CyberSecurityCloud-HighSecurityOWASPSet-', ProductId: 'daa750b9-0dd9-4927-b921-57e5a4fc3370', ProductLink: 'https://aws.amazon.com/marketplace/pp/B081TD6XL1', SnsTopicArn: 'arn:aws:sns:us-east-1:000000000000:CyberSecurityCloud-ManagedRule', IsVersioningSupported: true, IsAdvancedManagedRuleSet: false} with NO ProductTitle and NO ProductDescription member at all, where AWS's descriptor for that ManagedRuleSetName carries ProductTitle 'Cyber Security Cloud Managed Rules for AWS WAF -HighSecurity OWASP Set-', ProductDescription 'The Cyber Security Cloud OWASP ruleset is designed to mitigate and minimize vulnerabilities, including all those on OWASP Top 10 Web Application Threats list.', ProductId 'fa8c6ca7-12c3-4e3f-8524-782177f2f2bd' and SnsTopicArn in the vendor account. Three independent defects show in the same list: (a) ProductTitle/ProductDescription are never emitted for any entry; (b) ProductId values are emulator-minted UUIDs unrelated to the vendor's published product ids, so no entry joins to the recorded catalog; (c) ProductLink is rewritten to the https:// scheme and SnsTopicArn is rewritten into the local account 000000000000 instead of the publishing vendor's account ($.ManagedProducts[0].ProductLink and $.ManagedProducts[1].ProductLink are called out separately in the cluster key). The same list is served for Scope=REGIONAL and Scope=CLOUDFRONT.

Why: DescribeAllManagedProducts is how a client discovers which managed rule groups it may reference. A console or tool that lists products renders blank titles and descriptions because the two modeled display members are absent; code that pins a product by its published ProductId, follows its ProductLink, or subscribes to its vendor SnsTopicArn to learn of rule-group version changes finds nothing, because none of those values is the one AWS serves. A caller that then passes a discovered VendorName/ManagedRuleSetName pair to ManagedRuleGroupStatement reasons over a catalog that does not describe the deployment it will hit in AWS.

Fix: the DescribeAllManagedProducts handler and the static managed-product catalog it reads. The catalog data must carry the full AWS descriptor set for each product (including ProductTitle and ProductDescription) with the vendor's published ProductId, ProductLink and vendor-account SnsTopicArn, and the serializer must emit every populated member rather than dropping the two description members; the SnsTopicArn and ProductLink values must not be rewritten through the local-account/URL normalization applied to caller-owned resources, since these are service-owned catalog constants.

Traces: wafv2-catalog-describe-all-managed-products#task#1 (representative) and wafv2-catalog-describe-all-managed-products-cloudfront#task#1, the same cluster under Scope=CLOUDFRONT. No open issue covers this operation; the nearest wafv2 catalog-adjacent issue, 20261029T221828Z-apigateway-wafv2-2-net-new-root-causes-describemanagedrulegroup.md, is about DescribeManagedRuleGroup's AvailableLabels and does not cover the DescribeAllManagedProducts catalog.
