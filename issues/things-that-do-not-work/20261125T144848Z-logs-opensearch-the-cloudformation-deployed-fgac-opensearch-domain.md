# logs__opensearch: the CloudFormation-deployed FGAC OpenSearch domain whose four log types publish to their own groups never becomes observable, so the document-request-status audit lifecycle reaches no verdict

> _Note: this issue was identified against the code base at commit `e5aaacd45122de0ad72e17122715047bd1f281f6`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
DescribeDomain

## Description
One net-new root cause with one grounded check (Cause 1 of 1).

Cause 1 of 1: a CloudFormation stack that provisions four CloudWatch Logs log groups, an account-scoped AWS::Logs::ResourcePolicy granting es.amazonaws.com logs:PutLogEvents/logs:CreateLogStream on those four group ARNs, and one fine-grained-access-control AWS::OpenSearchService::Domain (OpenSearch_2.11, t3.small.search x1, gp3 10 GiB EBS, encryption at rest, node-to-node encryption, EnforceHTTPS, AdvancedSecurityOptions with an IAM MasterUserARN, and LogPublishingOptions enabling AUDIT_LOGS, ES_APPLICATION_LOGS, INDEX_SLOW_LOGS and SEARCH_SLOW_LOGS, each to its own group) never becomes an observable estate. The check makes no observable progress and is cut off at the harness cap (60.0 s) while still in its first phase, so none of the five phases (deploy, setup, solve, cleanup, destroy) reaches an assertion. Failing check: logs__opensearch.e2e-osdocstat-document-request-status-logs-lifecycle.

AWS: Smithy (opensearch) CreateDomain POST /2021-01-01/opensearch/domain takes DomainName (pattern ^[a-z][a-z0-9\-]+$, length 3-28), EngineVersion, ClusterConfig, EBSOptions, EncryptionAtRestOptions, NodeToNodeEncryptionOptions, DomainEndpointOptions, AdvancedSecurityOptions and a LogPublishingOptions map keyed by LogType (AUDIT_LOGS, ES_APPLICATION_LOGS, INDEX_SLOW_LOGS, SEARCH_SLOW_LOGS), and answers DomainStatus (errors BaseException 400, DisabledOperationException 409, InternalException 500, InvalidTypeException 409, LimitExceededException 409, ResourceAlreadyExistsException 409, ValidationException 400). DescribeDomain GET /2021-01-01/opensearch/domain/{DomainName} returns a required DomainStatus whose members include Created, Processing ('True if OpenSearch Service is processing configuration changes. False if the configuration is active'), Endpoint ('Domain-specific endpoint used to submit index, search, and data upload requests'), DomainProcessingStatus and LogPublishingOptions. On AWS the stack reaches CREATE_COMPLETE and publishes its Outputs (the domain name, the Fn::GetAtt DomainEndpoint and Arn, and the four group names); the domain then settles (Created=true, Processing=false) and serves its SigV4 ('es') REST data plane, so GET / answers 200, GET/PATCH /_opendistro/_security/api/audit reads and patches the FGAC audit configuration (a second patch finds it already enabled and changes nothing), PUT of an index succeeds once and is then refused 400 with error.type resource_already_exists_exception, a seeded document PUT answers 201, a GET of it answers 200 with found=true and a GET of an unseeded id answers 404; DescribeDomain then echoes all four LogTypes Enabled=true against the stack's own group ARNs, and the audit group receives exactly one REST record (audit_category AUTHENTICATED, audit_rest_request_method GET) and one transport record (audit_transport_request_type GetRequest, audit_category GRANTED_PRIVILEGES) per document GET, identical between the 200 and the 404 apart from volatile fields and carrying no status-, response- or code-bearing field, while the application, slow-search and slow-index groups record neither GET. Finally DELETE of the index is acknowledged, a GET of the deleted document answers 404 index_not_found_exception, DeleteStack reaches DELETE_COMPLETE, DescribeStackResources on the gone stack is refused with ValidationError and the message 'Stack with id <stack name> does not exist' (fixed text 'Stack with id ' + the StackName from the request + ' does not exist'), and a second DeleteStack on the already-deleted stack is a documented no-op that leaves it gone.
Emulator: the check terminates with 'Error: Check timed out after 60.0s' and reaches none of those assertions. Its own budgets are generous (deploy and destroy 2400 s, data plane 300 s, delivery 900 s), so the first predicate that is never satisfied is in the deploy phase: the DescribeStacks poll for the stack reaching a terminal state (CREATE_COMPLETE/CREATE_FAILED/ROLLBACK_COMPLETE/ROLLBACK_FAILED/GONE), or — if the stack does settle — the follow-on poll for the domain endpoint answering GET / with 200. Hypothesis: the AWS::OpenSearchService::Domain resource never reaches a terminal CloudFormation state (or the domain it creates stays Processing / publishes an endpoint the emulator does not serve), so the whole estate is never observable; the replay output states only the timeout, so the exact blocking poll is not attributable from this run. Net effect: the FGAC audit surface — audit-config read/patch, the REST and transport audit records for a found and a not-found document GET, their indistinguishability by outcome, and the absence of those records from the other three groups — is entirely unverifiable, and so is the stack's delete path and DeleteStack idempotency.
Why: a client that deploys an audited OpenSearch domain by template gets a stack that never reports a terminal status and a domain it can never index, query or audit. Because nothing is ever refused, there is no status, error code or message to act on — only a hang: CloudFormation waiters, the CLI, and CDK block indefinitely, and a security team relying on audit records to prove that a document GET was authenticated and authorised (and that the outcome does not leak into the audit record) gets no records at all.
Fix: the AWS::OpenSearchService::Domain resource handler in the CloudFormation engine (it must drive the resource to a terminal state and publish Ref/Fn::GetAtt DomainEndpoint and Arn outputs), the OpenSearch domain lifecycle behind CreateDomain/DescribeDomain (Created=true, Processing=false, DomainProcessingStatus active, and an Endpoint the emulator actually serves), the domain's FGAC REST data plane including /_opendistro/_security/api/audit, and the AUDIT_LOGS delivery path that must write REST and transport audit records into the named CloudWatch Logs group.
