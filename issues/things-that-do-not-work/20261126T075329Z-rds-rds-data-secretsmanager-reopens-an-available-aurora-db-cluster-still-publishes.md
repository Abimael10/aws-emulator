# REOPENS: an available Aurora DB cluster still publishes DBCluster.Endpoint on an unserved '.rds.localhost' host, so every cross-surface Data-API/native-SQL check is ungradeable

> _Note: this issue was identified against the code base at commit `79a507fc73607a18f097ced0776fe19bc62bb90e`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
DescribeDBClusters

## Description
REOPENS 20261121T083106Z-rds-rds-data-secretsmanager-every-cross-surface-data.md: its fix left the call refused. That issue is now marked fixed and the open issue 20261122T073021Z-rds-rds-data-secretsmanager-4-net-new-causes.md records that native sessions had begun connecting ("reached only now that a native session can connect"), yet on this branch all 22 checks of the group again abort on the published endpoint before any cross-surface assertion. The open issues 20261122T073021Z-rds-rds-data-secretsmanager-{2,3,4}-net-new-causes.md describe SQL/transaction semantics behind this wall and cover none of this cause; the neighbouring published-endpoint issues named by the reopened file (20261121T053640Z-logs-rds-..., 20261121T064921Z-rds-s3-..., 20261118T181500Z-rds-..., 20261120T153000Z-pi-rds-...) carry none of these 22 replay keys.

Cause 1 of 1: the connection endpoint an Aurora DB cluster publishes (CreateDBCluster / DescribeDBClusters -> DBCluster.Endpoint, paired with DBCluster.Port) is a cluster-domain DNS name under the suffix '.rds.localhost', a host the emulator neither resolves nor serves, while DBCluster.Port is the real ephemeral port of the listener the emulator opened for that cluster's engine. The announced authority is half real: the port answers, the host does not exist.

AWS: Smithy (rds, com-amazonaws-rds-amazonrdsv19): DBCluster.Endpoint — "The connection endpoint for the primary instance of the DB cluster"; DBCluster.Port is the port that endpoint accepts connections on. On AWS the value is a resolvable DNS name of the form <DBClusterIdentifier>.cluster-<cluster hash>.<region>.rds.amazonaws.com — the '.cluster-' infix and the regional 'rds.amazonaws.com' suffix are the fixed parts, the identifier comes from the request and the hash/region from the service's state — and once DBCluster.Status is 'available' a client that dials Endpoint:Port gets an engine session. For an emulator the structural requirement these checks depend on is only that the announced Endpoint:Port is an address the responding service actually answers on.

Emulator: the create and the describe both succeed (HTTP 200, no error code — the earlier assertions on HttpEndpointEnabled=True, BacktrackWindow and MasterUserSecret.SecretStatus='active' all pass), and the cluster reports Endpoint '<identifier>.cluster-<hash>.<region>.rds.localhost' with Port set to the emulator's own listener port. The published-address guard then refuses the pair with the whole sentence as fixed text: "endpoint_host was given <host>:<port> (published by the emulator or built by the check): its host is not one of the emulator's own hosts; a customer of the emulator needs an own host[:port]: the endpoint host, a documented own host or, for a loopback endpoint, a loopback address". In that message only <host>:<port> is a value — it is the authority the emulator published; the identifier, hash, region and port seen in any one run (e.g. 'sim2real-behav-clus-7e0003c195d5.cluster-5agetm06p19u.us-west-2.rds.localhost:37833') are per-run values and are NOT part of the requirement. There is no status or error-code divergence: the control-plane read is fine, the value it publishes is unusable.

Why: a client doing exactly the documented thing — read Endpoint and Port from an available cluster and connect with a MySQL/PostgreSQL driver — cannot reach the database at all. Everything downstream of that connection is unreachable: no native session, hence no comparison of what the Data API wrote against what a native session reads, no transaction-visibility or row-lock semantics, no typed-value agreement, no post-failover / post-backtrack / post-snapshot-restore verification, and no check that native SQL still works while the HTTP endpoint is disabled. The emulator's RDS data plane is unaddressable from its own API answer.

Fix: the RDS DB-cluster endpoint publication path — the component that computes DBCluster.Endpoint / ReaderEndpoint / Port from the cluster record and the listener actually opened for it (the create/modify DB-cluster handler's engine-endpoint planning and the DbClusterRecord -> DBCluster projection in the rds crate's state, which falls back to the minted DNS-form host). It must announce an authority the emulator answers on — an own host or a loopback address for that cluster's listener — or make the cluster-domain name resolvable and served. The port side is already correct, so only the host component of the published pair needs to change.

Traces: all 22 failing checks listed in trace_ids, each aborting at ctx.endpoint_host(cluster["Endpoint"], int(cluster["Port"])) with simparity.published.PublishedUrlRejected (context.py line 665, in endpoint_host). Components cited above: services/service-com-amazonaws-rds-amazonrdsv19/src/ops/create_db_cluster.rs (engine-endpoint/served-endpoint assignment) and services/service-com-amazonaws-rds-amazonrdsv19/src/state.rs (DBCluster projection).

## Steps to Reproduce
1. Boot the emulator; point rds, rds-data, secretsmanager and ec2 clients at it.
2. CreateDBCluster with Engine aurora-mysql (or aurora-postgresql), ManageMasterUserPassword=True, DatabaseName set, EnableHttpEndpoint=True, ServerlessV2ScalingConfiguration, a subnet group and security group; then CreateDBInstance with DBInstanceClass db.serverless in that cluster.
3. Poll until DescribeDBInstances reports 'available' and DescribeDBClusters reports Status 'available' with MasterUserSecret.SecretStatus 'active'.
4. Read DBCluster.Endpoint and DBCluster.Port from that describe response: Endpoint is '<identifier>.cluster-<hash>.<region>.rds.localhost' and Port is the emulator's own listener port.
5. Resolve and dial that host:port from a client of the emulator (pymysql / psycopg): the '.rds.localhost' authority is not a host the emulator serves or resolves, while the port is its real listener port.
6. Replay any of the 22 checks in trace_ids; each aborts at ctx.endpoint_host(cluster['Endpoint'], int(cluster['Port'])) with simparity.published.PublishedUrlRejected before reaching its cross-surface assertion.
