# ListAWSDefaultServiceQuotas default catalog misbinds QuotaCodes and drops Description for apigateway appconfig application-autoscaling athena glue

> _Note: this issue was identified against the code base at commit `fc05151cc5015eb457b31a79871539af51fb9fdd`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
ListAWSDefaultServiceQuotas

## Description
ListAWSDefaultServiceQuotas returns 200 with a `Quotas` list whose rows do not correspond to the AWS default-quota catalog for five service codes. The shared fault is the seeded default-quota table behind the operation: a `QuotaCode` is bound to another quota's `QuotaName`/`Value`/`Description`/`Unit`/`UsageMetric` (the rows appear shifted relative to their codes), `Description` is omitted entirely on rows where AWS publishes one, and some AWS rows are absent from the catalog. Statuses match (200 -> 200); every divergence is in the response body. THIS ISSUE BUNDLES 5 CAUSES — all five must be closed before submitting.

Model basis for all causes — Smithy: ListAWSDefaultServiceQuotas(ServiceCode required, @length 1..63, @pattern ^[a-zA-Z][a-zA-Z0-9-]{1,63}$) -> ListAWSDefaultServiceQuotasResponse{Quotas: ServiceQuotaListDefinition, NextToken}; ServiceQuota members ServiceCode, ServiceName, QuotaArn, QuotaCode (@length 1..128), QuotaName, Value (QuotaValue, @range 0..1e10), Unit, Adjustable (@default false), GlobalQuota, UsageMetric (MetricInfo), Period (QuotaPeriod), Description (@length 0..350). The model fixes the shape but not the catalog contents, so the per-code quota identity, name, value, unit, period, usage metric and description are recorded behavior only, taken from the recorded AWS responses for each ServiceCode. The invariant AWS guarantees and the emulator breaks: for a given ServiceCode, each QuotaCode identifies exactly one quota, and every member of that row describes that same quota.

Cause 1 of 5: apigateway rows carry another quota's name/value/unit and omit Description.
  AWS: recorded behavior only — for ServiceCode `apigateway` the recorded response binds L-8B81B02C to QuotaName 'Maximum resource policy size in bytes' with Value 8192 and a Description ('The maximum resource policy size in bytes you can have in this account in the current region.'), L-F8BD84D3 to 'Portals per account' Value 15, L-668C9B28 to 'Subnets per VPC link(V2)' Value 10, L-FD0EB744 to 'WebSocket message payload size' Unit 'Kilobytes' Value 128; and it populates Description on L-8F8AAAFE, L-AA0FF27B, L-5244589D, L-8A5B8E43 and the rest of the apigateway rows.
  Emulator: returns 200 but binds L-8B81B02C to 'Throttle rate' Value 10000, L-F8BD84D3 to 'Integrations per API' Value 300, L-668C9B28 to 'Custom domain names per account per Region' Value 120, L-FD0EB744 to 'Tags per API' Unit 'None' Value 50, and returns Description absent (None) on those and ~40 further apigateway codes; Adjustable and Unit also differ on the shifted rows.
  Why: a client that looks a quota up by QuotaCode (the documented way to identify a quota) gets a different quota's name and limit, so quota-driven preflight checks and limit dashboards compare usage against the wrong ceiling and silently mis-size. A client rendering the catalog gets rows with no Description at all.
  Fix: the ListAWSDefaultServiceQuotas default-quota catalog/state seed for ServiceCode `apigateway` (the code->row mapping and the Description column), not the serializer: the shape is correct, the row contents are not.
  Traces: service-quotas-catalog-list-aws-default-service-quotas-apigateway#task#1.

Cause 2 of 5: appconfig rows omit Description and understate one Value.
  AWS: recorded behavior only — for ServiceCode `appconfig` the recorded response populates Description on L-08D2C632, L-48F9B951, L-B858C085, L-F59D302B, L-A5FC0339, L-A52E46BE and L-EEB0151E, and binds L-A5FC0339 to Value 2048.
  Emulator: returns 200 with Description absent (None) on all seven of those codes, and L-A5FC0339 Value 1024 instead of 2048.
  Why: the quota description is how a console or operator learns what a code means and what the increase policy is; dropping it leaves rows unexplainable. The understated value makes a client believe it has half the deployment-size budget AWS actually grants.
  Fix: the ListAWSDefaultServiceQuotas default-quota catalog/state seed for ServiceCode `appconfig`.
  Traces: service-quotas-catalog-list-aws-default-service-quotas-appconfig#task#1.

Cause 3 of 5: application-autoscaling namespace rows are bound to the wrong namespace and two values are understated.
  AWS: recorded behavior only — for ServiceCode `application-autoscaling` the recorded response binds L-800F6F7B to 'Scalable targets for RDS', L-1A11EB4B to 'Scalable targets for Amazon MSK' (Kafka namespace), L-60E4E5E2 to 'Scalable targets for Amazon ElastiCache', and gives L-782A3EE2 Value 3000 and L-A1D42901 Value 5000.
  Emulator: returns 200 with L-800F6F7B as 'Scalable targets for Neptune' (and the Neptune wording in Description), L-1A11EB4B as 'Scalable targets for Aurora' (Aurora wording in Description), L-60E4E5E2 as 'Scalable targets for ElastiCache' (name text differs from AWS's), and Value 500 for both L-782A3EE2 and L-A1D42901.
  Why: scaling-capacity planning keyed on these codes reads the wrong namespace's quota, and the two understated limits are 6x and 10x below AWS, so a client throttles itself or reports a false capacity breach.
  Fix: the ListAWSDefaultServiceQuotas default-quota catalog/state seed for ServiceCode `application-autoscaling` — the per-namespace code->row binding and the two quota values.
  Traces: service-quotas-catalog-list-aws-default-service-quotas-application-autoscaling#task#1.

Cause 4 of 5: athena rows swap resource quotas for API rate quotas, drop Description/UsageMetric and omit a row.
  AWS: recorded behavior only — for ServiceCode `athena` the recorded response binds L-FD9D80C2 to 'Maximum number of workgroups per account', Value 1000, with UsageMetric {MetricNamespace 'AWS/Usage', MetricName 'ResourceCount', MetricDimensions{Service 'Athena', Resource 'WorkGroup', Type 'Resource', Class 'None'}, MetricStatisticRecommendation 'Maximum'}; binds L-82E47245 to 'Replenishment rate of ListNamedQueries API calls'; populates Description on L-07F4444F and the other athena rows; and includes a row for L-B13EED8E.

  Why: a resource-count quota is reported as a rate-burst multiplier with value 2, so a client provisioning workgroups believes it may create two of them instead of a thousand; the absent UsageMetric also breaks CloudWatch usage-vs-quota wiring, and the missing row makes a real quota invisible.
  Fix: the ListAWSDefaultServiceQuotas default-quota catalog/state seed for ServiceCode `athena`, including the UsageMetric/Period columns and the absent row.
  Traces: service-quotas-catalog-list-aws-default-service-quotas-athena#task#1.

  AWS: recorded behavior only — for ServiceCode `glue` the recorded response binds L-A457CBAB to 'Maximum number of queued job runs' Value 1000 (Description 'Orchestration: maximum number of queued job runs'), L-F545C262 to 'Number of connection types' Value 1000, L-C3952F6C to the concurrent data-quality-ruleset-evaluation-runs quota; words L-F1AAB534's Description 'The maximum number of integrations per AWS Region for this account.' and L-87F5991C's 'The maximum number of data quality rulesets per account.'; and includes rows for L-83192DBF ('Max security configurations per account', Value 250, Adjustable true), L-2E9FB93F, L-337244C9 and L-5E4153CA.

  Why: resource-count quotas are served as per-second request rates, so a client reads 10 where AWS grants 1000 and throttles or alarms spuriously; absent rows hide real quotas from a catalog walk.
