## Description
ONE shared fault with 2 numbered causes, one per read path of an AWS-managed (service-owned) catalogue entry. Reading the CloudTrail-delivered schema of the service-owned `aws.events` registry answers HTTP 200 with the right status, headers and every other output member, but the `Content` document is not the document the catalogue publishes for that entry. `ExportSchema` renders its draft-04 document FROM the document `DescribeSchema` serves, so both causes come from the one seeded source document — but they are two separate replay units with two separate replay keys, and BOTH must be re-replayed before this issue is closed. SHARED SHAPE: the emulator does not STORE a published catalogue document. It RENDERS one, for every CloudTrail-delivered kind and every event source, from a single hand-written components template (`CLOUD_TRAIL_COMPONENTS`) whose own doc comment describes it as the record as the CloudTrail User Guide documents it, plus a per-kind payload member grafted on. A rendering of a document is not the document: any member the template declares differently from the published text — absent, extra, differently typed, or at another position in the document's name order at any depth — changes the whole `Content` string, which is what both read paths are compared on.

Cause 1 of 2: DescribeSchema serves an OpenApi3 document that is not the published one.
AWS: Smithy (services/service-com-amazonaws-schemas-schemas/smithy-model/com-amazonaws-schemas-schemas.json): `DescribeSchema` GET /v1/registries/name/{RegistryName}/schemas/name/{SchemaName}, httpLabel `RegistryName` + `SchemaName` (both required), httpQuery `schemaVersion`, success 200; output `Content: __string`, `Description`, `LastModified` (__timestampIso8601, @timestampFormat date-time), `SchemaArn`, `SchemaName`, `SchemaVersion`, `Tags` (jsonName `tags`), `Type`, `VersionCreatedDate`; errors BadRequestException 400, UnauthorizedException 401, ForbiddenException 403, NotFoundException 404, InternalServerErrorException 500, ServiceUnavailableException 503. The model constrains `Content` only as a string and says NOTHING about the document's text, so WHAT the document says is recorded behavior only. The recording for a CloudTrail-delivered entry of the `aws.events` registry is an OpenAPI 3.0.0 document of the form {"openapi":"3.0.0","info":{"title":"<detail-type> published by <source>","version":"1.0.0"},"paths":{},"components":{"schemas":{"<EventName>":{"type":"object","properties":{...}}}}} — exactly one component (the event's own record), every nested structure (a `resources` item, `tlsDetails`, `userIdentity` and the structures inside it) declared INLINE, the free-form members `addendum`/`additionalEventData`/`requestParameters`/`responseElements` as {"type":"object","nullable":true}, and `eventTime` as {"pattern":"yyyy-MM-dd'T'HH:mm:ss'Z'","type":"string","format":"date-time"}. Member order at every depth is part of the requirement, because `Content` is text a client caches, diffs, hashes and generates bindings from.
Emulator: answers 200 and the replay reports `$.Content: value_mismatch` for the WHOLE string — the served document differs from the recorded one. The served text is rendered, not stored: `event_schema_document` wraps `CLOUD_TRAIL_COMPONENTS` in the envelope and the catalogue is built once per process. The prefix of the recorded document the replay detail still exposes (the openapi/info/paths/components envelope and the record members `addendum` .. `userIdentity.properties.onBehalfOf.{identityStoreArn,userId}`) agrees member-for-member and order-for-order with the template, so the residual difference is at or after `components.schemas.<EventName>.properties.userIdentity.properties.principalId` and runs to the end of the record (`sessionContext` and its subtree, `type`, `userName`, `vpcEndpointAccountId`, `vpcEndpointId`) — and/or in the per-kind payload graft. Hypothesis: that tail region is where the reconstructed member set, spelling, typing or name-order position still parts from the published text; the replay compares the whole string and localises no further, and this replay's detail withholds the recorded bytes past the clip point.
Why: `Content` is the entire point of a schema read. A client generates event bindings from it, feeds it to a JSON-schema validator to accept or reject delivered EventBridge events, caches it, or hashes it to detect catalogue drift. A document that declares the CloudTrail record differently from AWS's makes generated bindings miss or mistype members of real delivered events, makes a validator reach a different verdict than AWS's document would, and makes any digest or cached copy of the schema text differ from the published one — all while the call looks successful.
Fix: the AWS-managed catalogue DATA in the schemas service's state module, not the DescribeSchema handler and not the serializer (the envelope, status, headers and all other members are already right). The served document must be the catalogue's published document for the entry rather than a record reconstructed from prose and fanned out across a whole family of kinds and every event source. The diff must be run end to end against the recorded string, not corrected one subtree at a time — five previous fixes each corrected one visible subtree and left this step diverging.
